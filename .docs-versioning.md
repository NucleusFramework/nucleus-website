# Document versioning

How major/minor doc lines are archived and exposed in the version switcher
(`2.0` · `2.1` · `2.2` · `2.3 (latest)` · …).

## Mental model

| What | Where | URL |
|------|--------|-----|
| **Latest** (actively edited) | `content/docs/` | `/docs` |
| **Archived line** | `content/versioned/<X.Y>/` | `/docs/<X.Y>` |
| Switcher + sources | `lib/source.ts` → `DOC_VERSIONS` | — |
| MDX collections | `source.config.ts` → `defineDocs(...)` | — |
| App routes | `app/[lang]/docs/<X.Y>/` | thin wrappers |

- **Latest** is always index `0` in `DOC_VERSIONS`, labeled `"<X.Y> (latest)"`.
- Archives are frozen: do not edit them for new features. Only fix typos / broken links
  if you must.
- Sitemap and the sidebar switcher both read `DOC_VERSIONS` — no extra wiring.

Fumadocs regenerates `.source/` on `postinstall` / `npm run dev`. That directory is
gitignored; never commit it.

## When to snapshot

Snapshot **before** you rewrite `content/docs/` for a new Nucleus minor/major
(e.g. 2.2 docs while latest still describes 2.1).

Do **not** snapshot patch releases (2.1.9 → 2.1.10): keep editing latest and the
changelog; the line stays `2.1` until the next minor.

Ideal order for a new line (e.g. shipping **2.3** docs):

1. Finish any last 2.2 doc fixes on `main`.
2. **Snapshot 2.2** while `content/docs/` is still the 2.2 tree.
3. Bump **`lib/nucleus-version.ts`** (`NUCLEUS_VERSION` / line) — this drives the landing
   nav badge, footer, architecture stack, code samples, docs switcher label
   (`NUCLEUS_LATEST_DOCS_LABEL`), and `SITE.description`.
4. Confirm `lib/versions.json` → `core` matches after `npm run fetch-versions` (or predev).
5. Update docs in `content/docs/` for 2.3 (changelog with deep-links, new pages, install table).
6. Grep the repo for the previous line string (`2.2`) on the landing and latest docs; fix stragglers.
7. Commit archive + wiring + new content together or as a small stack.

**Never hardcode a product version on the landing or in live docs** except via
`lib/nucleus-version.ts` or the MDX `<version>` placeholder.

If you already wrote the new line into `content/docs/`, you **cannot** use
`npm run snapshot-docs` for the old line (it copies *current* latest). Recover from
git instead (see [Late archive from git](#late-archive-from-git)).

## Happy path (current latest → new archive)

Example: latest is 2.2; you are about to start 2.3 docs. Archive **2.2** first.

### 1. Snapshot content + routes

```bash
npm run snapshot-docs 2.2
```

This:

1. Copies `content/docs/` → `content/versioned/2.2/`
2. Scaffolds `app/[lang]/docs/2.2/layout.tsx` and `[[...slug]]/page.tsx`

If the destination already exists the script exits; delete it only if you
intentionally re-snapshot.

### 2. Register the MDX collection

In `source.config.ts`, next to the other archives:

```ts
export const docs_2_2 = defineDocs({
  dir: 'content/versioned/2.2',
});
```

Identifier rule: `docs_` + version with dots → underscores (`2.1` → `docs_2_1`).

### 3. Register the version in the switcher

In `lib/source.ts`, keep **newest first**, `latest` at index 0:

```ts
export const DOC_VERSIONS: DocVersion[] = [
  version({
    id: 'latest',
    label: '2.3 (latest)', // ← bump the line number
    baseUrl: '/docs',
    collection: Source.docs,
    latest: true,
  }),
  version({
    id: '2.2',
    label: '2.2',
    baseUrl: '/docs/2.2',
    collection: Source.docs_2_2,
  }),
  version({
    id: '2.1',
    label: '2.1',
    baseUrl: '/docs/2.1',
    collection: Source.docs_2_1,
  }),
  version({
    id: '2.0',
    label: '2.0',
    baseUrl: '/docs/2.0',
    collection: Source.docs_2_0,
  }),
];
```

After adding the export, run `npx fumadocs-mdx` (or `npm run dev`) so `Source.docs_2_2`
exists under `.source/`.

### 4. Write the new line in latest

Edit only `content/docs/` (and its `*.fr.mdx` twins):

- Changelog: add the new `vX.Y.0` section at the top (EN + FR).
  **Deep-link every documented feature to its page/section** — see
  [`.docs-style-guide.md` §9b](.docs-style-guide.md) (no sidebar "New" badges).
- Feature pages, DSL reference, roadmap, etc.
- Follow [`.docs-ia.md`](.docs-ia.md) structure and [`.docs-style-guide.md`](.docs-style-guide.md).

`lib/versions.json` is filled by `scripts/fetch-versions.mjs` on `predev`/`prebuild`
(gitignored). Snippets use the `<version>` placeholder; the badge uses `<Version module="core" />`.

### 5. Sanity check

```bash
npm run dev
```

- Switcher shows `2.3 (latest)`, `2.2`, `2.1`, `2.0`.
- `/en/docs/` is the new line; `/en/docs/2.2/` matches the freeze.
- Switching versions keeps the same page when the slug exists; otherwise falls back to the
  version home.
- French: `/fr/docs/...` and `/fr/docs/2.2/...`.

### 6. Commit

Include at least:

- `content/versioned/<X.Y>/` (full tree)
- `app/[lang]/docs/<X.Y>/`
- `source.config.ts`
- `lib/source.ts`
- any new/changed files under `content/docs/`

Do **not** commit `.source/`, `lib/versions.json`, `node_modules/`, `.next/`.

## Late archive from git

You already landed new-line docs in `content/docs/` and forgot to snapshot the previous
line. Recover the old tree from the last commit *before* that rewrite:

```bash
# Example: last commit that still had pure 2.2 docs
PREV=4604d41   # replace with the real SHA

rm -rf content/versioned/2.2
mkdir -p content/versioned/2.2
git archive "$PREV" content/docs | tar -x -C content/versioned/2.2 --strip-components=2

# Scaffold routes (or re-run a one-off copy of an existing version folder)
npm run snapshot-docs 2.2
# If snapshot-docs fails because content/versioned/2.2 exists, only create the
# app/[lang]/docs/2.2/ files (see scripts/snapshot-docs.mjs) and wire config.
```

Then wire `source.config.ts` + `lib/source.ts` as in the happy path.

Optional: if a final patch of the old line shipped after that SHA (e.g. changelog
entry for `2.2.1`), add it manually on the **archive** only.

## Checklist (copy/paste)

```
[ ] content/docs is still the line you want to freeze
[ ] npm run snapshot-docs <X.Y>
[ ] source.config.ts → export const docs_X_Y = defineDocs({ dir: 'content/versioned/X.Y' })
[ ] lib/source.ts → DOC_VERSIONS: latest label bumped; archive entry after latest
[ ] npx fumadocs-mdx   # or npm run dev
[ ] Write new content under content/docs/ (EN + FR)
[ ] Changelog + roadmap updated for the new line
[ ] Switcher smoke: latest + each archive URL (en + fr)
[ ] Commit archive + wiring + new docs (no .source / versions.json)
```
