The `nucleus.application { }` block in `build.gradle.kts` tells the plugin how to run and package
your app. A Kotlin/Native app uses `nucleus.nativeApplication { }` instead, see
[the Gradle DSL reference](/docs/reference/gradle-dsl#native-application).

## Write the minimal configuration

```kotlin title="build.gradle.kts"
import dev.nucleusframework.desktop.application.dsl.TargetFormat

nucleus.application {
    mainClass = "com.example.MainKt" // fun main in com/example/Main.kt

    nativeDistributions {
        packageName = "MyApp"
        packageVersion = "1.0.0"
        description = "Notes that sync across devices"
        vendor = "Example Corp"
        homepage = "https://myapp.example.com" // required for DEB and RPM
        targetFormats(TargetFormat.Dmg, TargetFormat.Msi, TargetFormat.Deb)

        macOS {
            bundleID = "com.example.myapp"
            iconFile.set(project.file("icons/app.icns"))
        }
        windows { iconFile.set(project.file("icons/app.ico")) }
        linux { iconFile.set(project.file("icons/app.png")) }
    }
}
```

`packageName` and `packageVersion` end up in installer names and OS metadata.

## Select packaging formats

`targetFormats(...)` accepts any of the 18 `TargetFormat` values. Each build machine produces the
formats of its own OS.

| OS | Formats |
|---|---|
| macOS | `Dmg`, `Pkg` |
| Windows | `Msi`, `Exe`, `Nsis`, `NsisWeb`, `Portable`, `AppX` |
| Linux | `Deb`, `Rpm`, `AppImage`, `Pacman`, `Snap`, `Flatpak` |
| Any | `Zip`, `Tar`, `SevenZ`, `RawAppImage` |
