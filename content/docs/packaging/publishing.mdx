import { Tab, Tabs } from 'fumadocs-ui/components/tabs';

`publish { }` inside `nativeDistributions { }` tells Nucleus where your installers and their
[auto-update](/docs/packaging/auto-update) metadata live. Enable one backend.

## Configure a publishing backend

<Tabs items={['GitHub Releases', 'S3', 'Generic HTTPS']}>
<Tab value="GitHub Releases">

```kotlin title="build.gradle.kts"
publish {
    github {
        enabled = true
        owner = "myorg"
        repo = "myapp"
        token = System.getenv("GITHUB_TOKEN") // needs contents: write
        channel = ReleaseChannel.Latest
        releaseType = ReleaseType.Release // or Draft, Prerelease
    }
}
```

</Tab>
<Tab value="S3">

```kotlin title="build.gradle.kts"
publish {
    s3 {
        enabled = true
        bucket = "my-updates-bucket"
        region = "us-east-1"
        path = "releases/myapp"
        acl = "public-read"
    }
}
```

Provide `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_REGION` in the environment.

</Tab>
<Tab value="Generic HTTPS">

```kotlin title="build.gradle.kts"
publish {
    generic {
        enabled = true
        url = "https://updates.example.com/releases/"
        channel = ReleaseChannel.Latest
        useMultipleRangeRequest = true // default
    }
}
```

You upload the files to any static host. It must serve HTTP `Range` requests over `https`.

</Tab>
</Tabs>

`channel` selects the YAML the updater reads: `Latest` (`latest-*.yml`, tag `v1.0.0`), `Beta`
(`beta-*.yml`, `v1.0.0-beta.1`), or `Alpha` (`alpha-*.yml`, `v1.0.0-alpha.1`).

## Set the publish mode

```kotlin title="build.gradle.kts"
publish {
    publishMode = PublishMode.Auto
}
```

| Mode | Behavior |
|------|----------|
| `PublishMode.Never` (default) | No upload. The plugin still writes `latest-*.yml` for every updatable format. |
| `PublishMode.Auto` | Upload when the build runs from a git tag. |
| `PublishMode.Always` | Upload on every build. |

The `compose.electronBuilder.publishMode` Gradle property overrides the DSL value for one run. The
reference [CI/CD workflow](/docs/packaging/ci-cd#publish-the-release) keeps `Never` and uploads in
a separate job.

## Submit to a desktop store

Store builds skip `publish { }`. Upload the store format through the vendor:

- **Mac App Store**: the App Store PKG, with Transporter or `xcrun altool`. See
  [Package for the Mac App Store](/docs/packaging/macos#package-for-the-mac-app-store).
- **Microsoft Store**: the `.msixbundle`, in [Partner Center](https://partner.microsoft.com/).
  `identityName`, `publisher` (`CN=<GUID>`), and `publisherDisplayName` must match the reservation.
  See [Build an AppX or MSIX package](/docs/packaging/windows#build-an-appx-or-msix-package).
- **Snap Store**: `snapcraft upload` from CI. `classic` confinement needs Snap Store approval.
- **Flathub**: a manifest pull request on the [Flathub repository](https://github.com/flathub/flathub).
