The Nucleus Gradle plugin builds desktop installers from one `nativeDistributions { }` block. The
packaging DSL comes with the plugin, so you add no dependency.

## Declare the formats

```kotlin title="build.gradle.kts"
nucleus.application {
    mainClass = "com.example.MainKt"
    nativeDistributions {
        packageName = "MyApp"
        packageVersion = "1.0.0"
        targetFormats(TargetFormat.Dmg, TargetFormat.Nsis, TargetFormat.Deb, TargetFormat.AppImage)
    }
}
```

```shell
./gradlew packageDistributionForCurrentOS
```

The task builds every format the host supports and skips the rest, so one script runs on all three
OSes. Output lands in `build/compose/binaries/main/<format>/`. Each format also has its own task
(`packageDmg`, `packageNsis`), and `packageReleaseDistributionForCurrentOS` runs ProGuard first.

## Supported formats

| OS | Direct distribution | Store | Archives |
|----|---------------------|-------|----------|
| macOS | DMG, PKG (Developer ID) | PKG (Mac App Store) | ZIP, TAR, 7z |
| Windows | Exe, NSIS, NSIS Web, MSI, Portable | AppX (Microsoft Store) | ZIP, TAR, 7z |
| Linux | DEB, RPM, AppImage, Pacman | Snap, Flatpak | ZIP, TAR, 7z |

`TargetFormat.RawAppImage` builds the bare app image with no installer. Store formats use a
[sandboxed layout](/docs/packaging/sandboxing).

## Provision Node.js

The plugin downloads Node.js on first use and caches it in `~/.gradle/nucleus/nodejs`. You install
nothing, and CI no longer needs `actions/setup-node`.

```kotlin title="build.gradle.kts"
nativeDistributions {
    nodejs {
        version = "22"        // default: a major line, "lts", or a pinned release such as "22.11.0"
        autoDownload = true   // false: use node and npm from PATH
    }
}
```

The `compose.electronBuilder.nodePath` Gradle property and the `NUCLEUS_NODE_HOME` environment
variable take precedence over the download. A floating version stays on the release it first
downloaded: delete its cache directory to update.

## Native libraries next to the app

The plugin places the JNI libraries of Nucleus modules next to the app, so the packaged app
extracts nothing at startup. For fat JARs and IDE runs, see
[Native library loader](/docs/performance/native-library-loader).

<Callout type="warn" title="Changed in 3.0">
Packaged apps no longer carry Nucleus JNI libraries inside their JARs. Code that read them as
classpath resources must load them through `NativeLibraryLoader`. See
[Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

## Trim the runtime image

<Callout type="warn" title="Changed in 3.0">
`stripJreFonts` defaults to `true`: the runtime image drops the JRE fonts, since Compose draws text
with its own. An app that draws text with AWT or Swing must set `stripJreFonts = false`. See
[Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

With `includeAllModules = true`, the plugin leaves out `jdk.jlink`, which JDKs built without
`jmods/` (such as Temurin 24+) refuse to link.

<Accordion title="Under the hood">

- jpackage builds the app image. electron-builder 26.16.1 wraps it in every format except
  `RawAppImage`.
- Node.js resolution order: `nodePath`, `NUCLEUS_NODE_HOME`, the `nodejs { }` download (checked
  against `SHASUMS256.txt`), then `node` on `PATH`.
- Packaged apps get `-Dnucleus.native.libraryPath=$APPDIR`. GraalVM images keep the libraries next
  to the executable.
