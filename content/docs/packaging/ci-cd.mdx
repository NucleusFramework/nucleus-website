In this tutorial, you'll set up a GitHub Actions pipeline that builds, signs, and publishes your
installers. The [`NucleusFramework/Nucleus`](https://github.com/NucleusFramework/Nucleus)
repository ships the composite actions: reference them as
`NucleusFramework/Nucleus/.github/actions/<name>@<ref>`, with `<ref>` pinned to a release tag in
production. Installers do not cross-compile, so you need one runner per OS and architecture.

## Build on every platform

```yaml title=".github/workflows/release.yaml"
name: Release
on:
  push:
    tags: ['v*']

permissions:
  contents: write

jobs:
  build:
    strategy:
      fail-fast: false
      matrix:
        include:
          - { os: ubuntu-22.04,     arch: amd64 }
          - { os: ubuntu-22.04-arm, arch: arm64 }
          - { os: windows-latest,   arch: amd64 }
          - { os: windows-11-arm,   arch: arm64 }
          - { os: macos-latest,     arch: arm64 }
          - { os: macos-15-intel,   arch: amd64 }
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: NucleusFramework/Nucleus/.github/actions/setup-nucleus@main
        with:
          java-version: '25'
          flatpak: 'true'
          snap: 'true'
      - run: ./gradlew packageReleaseDistributionForCurrentOS --stacktrace --no-daemon
      - uses: actions/upload-artifact@v4
        with:
          name: release-assets-${{ runner.os }}-${{ matrix.arch }}
          path: build/compose/binaries/**/*
```

Later jobs find the artifacts by their `release-assets-<os>-<arch>` names, so keep that scheme.
`setup-nucleus` installs a JDK, the Linux packaging tools, and Gradle:

| Input | Default | Purpose |
|-------|---------|---------|
| `java-version` | `25` | JDK that runs Gradle and that jpackage bundles. |
| `packaging-tools` | `true` | Install the Linux packaging tools. |
| `flatpak` / `snap` | `false` | Install Flatpak (Freedesktop 24.08) or Snapcraft. |
| `graalvm` | `false` | Prepare a native-image build: Xcode 26 on macOS, MSVC on Windows. |
| `graalvm-version` | `25i4` | Keep it equal to `graalvm { toolchain { version } }`. |
| `node-version` | `22` | Keep it equal to `nodejs { version }`. |

<Callout type="warn" title="Changed in 3.0">
`setup-nucleus` no longer runs `actions/setup-node`, and the `setup-node` input is gone. Remove
`actions/setup-node` from your jobs and cache `~/.gradle/nucleus/nodejs` instead. See
[Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

## Sign macOS builds

```yaml
- uses: NucleusFramework/Nucleus/.github/actions/setup-macos-signing@main
  id: signing
  with:
    certificate-base64: ${{ secrets.MAC_CERTIFICATES_P12 }}
    certificate-password: ${{ secrets.MAC_CERTIFICATES_PASSWORD }}
```

| Secret | Purpose |
|--------|---------|
| `MAC_CERTIFICATES_P12`, `MAC_CERTIFICATES_PASSWORD` | Base64 `.p12` bundle and its password. |
| `MAC_DEVELOPER_ID_APPLICATION` | Developer ID Application identity (DMG, ZIP). |
| `MAC_APP_STORE_APPLICATION`, `MAC_APP_STORE_INSTALLER` | 3rd Party Mac Developer identities (App Store PKG). |
| `MAC_PROVISIONING_PROFILE`, `MAC_RUNTIME_PROVISIONING_PROFILE` | Base64 profiles for the app and the JVM runtime. |
| `MAC_NOTARIZATION_APPLE_ID`, `MAC_NOTARIZATION_PASSWORD`, `MAC_NOTARIZATION_TEAM_ID` | `notarytool` credentials. |

Without the `MAC_*` secrets, the pipeline signs ad hoc. See
[Code signing](/docs/packaging/code-signing#manage-signing-secrets-in-ci).

## Merge the universal macOS binary

`build-macos-universal` merges the arm64 and x64 builds and repackages a signed universal ZIP, DMG,
and PKG. Check out the Nucleus repository first, at the ref that matches your plugin version:

```yaml
- uses: actions/checkout@v4
  with:
    repository: NucleusFramework/Nucleus
    ref: main
    path: nucleus
    sparse-checkout: plugin-build/plugin/src/main/resources/nucleus/electron-builder
- uses: NucleusFramework/Nucleus/.github/actions/build-macos-universal@main
  with:
    arm64-path: artifacts/release-assets-macOS-arm64
    x64-path: artifacts/release-assets-macOS-amd64
    output-path: artifacts/release-assets-macOS-universal
    signing-identity: ${{ secrets.MAC_DEVELOPER_ID_APPLICATION }}
    app-store-identity: ${{ secrets.MAC_APP_STORE_APPLICATION }}
    installer-identity: ${{ secrets.MAC_APP_STORE_INSTALLER }}
    keychain-path: ${{ steps.signing.outputs.keychain-path }}
    electron-builder-toolchain-dir: nucleus/plugin-build/plugin/src/main/resources/nucleus/electron-builder
```

Notarize with `xcrun notarytool submit --wait`. Staple the DMG and leave the ZIP unstapled, so the
[updater](/docs/packaging/auto-update)'s block map stays valid. On private repositories, macOS
minutes count ten times against your quota; a self-hosted macOS runner avoids that cost.

## Bundle Windows for the Microsoft Store

```yaml
- uses: NucleusFramework/Nucleus/.github/actions/build-windows-appxbundle@main
  with:
    amd64-path: artifacts/release-assets-Windows-amd64
    arm64-path: artifacts/release-assets-Windows-arm64
    output-path: artifacts/release-assets-Windows-bundle
```

## Publish the release

`generate-update-yml` writes `<channel>-mac.yml`, `<channel>.yml`, and `<channel>-linux.yml`.
`publish-release` creates the GitHub Release and uploads everything:

```yaml
- uses: NucleusFramework/Nucleus/.github/actions/generate-update-yml@main
  with:
    artifacts-path: artifacts
    version: ${{ env.VERSION }}
    channel: ${{ env.CHANNEL }} # latest, beta, or alpha
- uses: NucleusFramework/Nucleus/.github/actions/publish-release@main
  with:
    artifacts-path: artifacts
    tag: ${{ env.TAG }}
    release-type: ${{ env.RELEASE_TYPE }} # release, draft, or prerelease
```

The reference [`release-desktop.yaml`](https://github.com/NucleusFramework/Nucleus/blob/main/.github/workflows/release-desktop.yaml)
wires all these jobs together. It derives the version and channel from the tag with
`release-tag-info`, and `validate-release-ref` rejects an `-alpha`, `-beta`, or `-rc` tag that does
not point to a commit on a `nucleus-*` release branch.

<Accordions>
<Accordion title="Under the hood">

- `setup-nucleus` installs Microsoft Build of OpenJDK on Windows and Temurin elsewhere. On Linux it
  installs `rpm`, `fakeroot`, `libarchive-tools`, `patchelf`, the GTK, GLib, D-Bus and X11
  headers, and starts a virtual display with `xvfb`.
- The Nucleus plugin downloads Node.js and the GraalVM JDK itself; `setup-nucleus` only caches
  `~/.gradle/nucleus/nodejs` and `~/.gradle/nucleus/graalvm`.
- `build-macos-universal` runs `lipo` on every Mach-O file, re-signs inside-out, and runs
  electron-builder outside Gradle, installed with `npm ci` from `electron-builder-toolchain-dir`.

</Accordion>
</Accordions>
