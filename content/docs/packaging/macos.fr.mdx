Cette page couvre le bloc `macOS { }` : builds DMG et PKG, extensions d'application et binaires
universels. Il vous faut un hôte macOS avec les Xcode Command Line Tools et un compte Apple
Developer.

## Configurer le bloc macOS

```kotlin title="build.gradle.kts"
nativeDistributions {
    targetFormats(TargetFormat.Dmg, TargetFormat.Zip, TargetFormat.Pkg)
    macOS {
        bundleID = "com.example.myapp"
        appCategory = "public.app-category.utilities"
        minimumSystemVersion = "12.0"
        iconFile.set(project.file("icons/app.icns"))
        layeredIconDir.set(project.file("icons/MyApp.icon")) // macOS 26, exige Xcode CLT 26+

        signing {
            sign.set(true)
            identity.set("Developer ID Application: My Company (TEAMID)")
        }
        notarization {
            appleID.set("dev@example.com")
            password.set(System.getenv("MAC_NOTARIZATION_PASSWORD"))
            teamID.set("TEAMID")
        }
    }
}
```

Le plugin choisit, à partir de cette seule identité, le certificat dont chaque format a besoin.
Pour les autres modes de notarisation, voir
[Signature du code](/docs/packaging/code-signing#choisir-un-mode-de-notarisation).

| Format | Certificats |
|--------|-------------|
| DMG, ZIP | Developer ID Application |
| PKG Developer ID | Developer ID Application, Developer ID Installer |
| PKG Mac App Store | 3rd Party Mac Developer Application et Installer, provisioning profiles |

## Empaqueter un DMG

`./gradlew packageDmg` construit le DMG. Avec des identifiants dans `notarization { }`,
`notarizeDmg` le notarise et l'agrafe, et `packageDistributionForCurrentOS` lance cette tâche pour
vous.

```kotlin title="build.gradle.kts"
macOS {
    dmg {
        window { x = 400; y = 100; width = 540; height = 380 }
        background.set(project.file("packaging/dmg-bg.png"))
        content(x = 130, y = 220, type = DmgContentType.File, name = "MyApp.app")
        content(x = 410, y = 220, type = DmgContentType.Link, path = "/Applications")
    }
}
```

`nativeDistributions.compressionLevel = CompressionLevel.Ultra` exige un `minimumSystemVersion` de
10.15 ou plus et aucun `dmg.format` imposé. Livrez un `Zip` à côté du DMG si vous utilisez la
[mise à jour automatique](/docs/packaging/auto-update).

## Choisir un canal PKG

`macOS { pkg { appStore } }` choisit le canal. La valeur par défaut, `true`, vise le Mac App Store.

| | `appStore = true` (défaut) | `appStore = false` |
|---|---|---|
| Distribution | Mac App Store (Transporter) | Téléchargement direct, MDM |
| Pipeline | [Sandboxé](/docs/packaging/sandboxing) | Le même que le DMG |
| Notarisé | Non, Apple examine l'envoi | Oui, par `notarizePkg` |
| Scripts d'installation | Font échouer le build | `preInstall`, `postInstall` |
| Mise à jour automatique | Gérée par le store | Possible |

<Callout type="warn" title="Modifié en 3.0">
`macOS.appStore` et `TargetFormat.isStoreFormat` ne compilent plus. Réglez `macOS { pkg { appStore = … } }`
explicitement. L'ancienne propriété `appStore` était ignorée : vérifiez le canal de chaque build.
Voir [Migrer depuis la 2.x](/docs/migrate/from-2.x).
</Callout>

### Empaqueter pour le Mac App Store

```kotlin title="build.gradle.kts"
macOS {
    entitlementsFile.set(project.file("packaging/sandbox-entitlements.plist"))
    runtimeEntitlementsFile.set(project.file("packaging/sandbox-runtime-entitlements.plist"))
    provisioningProfile.set(project.file("packaging/MyApp.provisionprofile"))
    runtimeProvisioningProfile.set(project.file("packaging/MyApp_Runtime.provisionprofile"))
}
```

Lancez `./gradlew packagePkg`. À l'exécution, `ExecutableRuntime.isSandboxed()` indique si l'App
Sandbox s'applique. Voir [Sandboxing](/docs/packaging/sandboxing#détecter-le-sandbox-à-lexécution).

### Empaqueter un PKG Developer ID

```kotlin title="build.gradle.kts"
macOS {
    pkg {
        appStore = false
        preInstall.set(file("packaging/macos/preinstall"))
        postInstall.set(file("packaging/macos/postinstall"))
    }
}
```

Lancez `./gradlew packagePkg notarizePkg`. L'Installer exécute les deux scripts en root, une fois
par installation. Chacun doit avoir un shebang et reçoit `$1` chemin du paquet, `$2` cible
d'installation, `$3` volume cible, `$4` disque de démarrage.

## Intégrer des extensions d'application

Nucleus copie et signe des bundles `.appex` préconstruits, par exemple une Network Extension, dans
`Contents/PlugIns/`. Vous construisez le `.appex` avec Xcode ou Kotlin/Native.

```kotlin title="build.gradle.kts"
macOS {
    entitlementsFile.set(file("packaging/app.entitlements"))
    appExtensions {
        extension("NetworkFilter") {
            appex(file("build/appex/NetworkFilter.appex"))
            entitlements(file("packaging/extension/NetworkExtension.entitlements"))
            provisioningProfile(file("packaging/NetworkFilter.provisionprofile")) // optionnel
        }
    }
}
```

- Pointez `entitlementsFile` vers un plist avec seulement `com.apple.security.cs.allow-jit`. Un
  hôte qui garde les entitlements par défaut `allow-unsigned-executable-memory` et
  `disable-library-validation` à côté d'une network extension ne se lancerait pas, d'après des
  signalements.
- `run` ne peut pas charger d'extension. Utilisez `runDistributable`.
- Une network extension exige un profil délivré par Apple qui accorde
  `com.apple.developer.networking.networkextension`.
- Nucleus n'active pas l'extension. Appelez `NEFilterManager` ou `NETunnelProviderManager`.

## Activer Liquid Glass sur le SDK 26

macOS 26 n'active Liquid Glass que pour les applications construites avec le SDK 26.0. Le plugin
marque le lanceur avec n'importe quel JDK, y compris dans `run`. Réglez
`macOS { macOsSdkVersion = null }` pour désactiver ce comportement. Les images natives GraalVM
exigent plutôt Xcode 26 sélectionné sur l'hôte de build.

## Construire un binaire universel

Construisez `arm64` et `x86_64` sur deux runners, puis fusionnez-les avec l'action
`build-macos-universal`. Voir [CI/CD](/docs/packaging/ci-cd#fusionner-le-binaire-macos-universel).

## Personnaliser Info.plist et les launch agents

```kotlin title="build.gradle.kts"
macOS {
    infoPlist {
        extraKeysRawXml = """<key>NSMicrophoneUsageDescription</key><string>Voice notes.</string>"""
    }
    launchAgents {
        agent("com.example.myapp.indexer") { bundleProgram("Contents/MacOS/indexer") }
    }
}
```

Enregistrez les launch agents à l'exécution avec la [Gestion des services](/docs/lifecycle/background/service-management).

## Référence

`bundleName` renomme le `.app` dans chaque artefact. `installationPath` s'applique au PKG et au lien
`/Applications` du DMG. Le bloc `macOS { }` complet se trouve dans la
[référence du DSL Gradle](/docs/reference/gradle-dsl).
