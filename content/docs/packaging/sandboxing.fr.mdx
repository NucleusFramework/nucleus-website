Trois formats tournent en sandbox : le PKG Mac App Store ([App Sandbox](https://developer.apple.com/documentation/security/app-sandbox)),
`AppX` (MSIX, full trust) et `Flatpak` ([sandbox Flatpak](https://docs.flatpak.org/en/latest/sandbox-permissions.html)).
Ajoutez-les à `targetFormats` à côté de vos formats standard : Nucleus embarque leurs bibliothèques
natives à l'avance.

```kotlin title="build.gradle.kts"
targetFormats(
    TargetFormat.Dmg, TargetFormat.Nsis, TargetFormat.Deb,
    TargetFormat.Pkg,     // avec macOS { pkg { appStore = true } }, le défaut
    TargetFormat.AppX,
    TargetFormat.Flatpak,
)
```

Un PKG avec `macOS { pkg { appStore = false } }` est un PKG Developer ID et se construit comme un
DMG. Voir [Choisir un canal PKG](/docs/packaging/macos#choisir-un-canal-pkg).

<Callout type="warn" title="Modifié en 3.0">
Un PKG n'implique plus l'App Sandbox. `TargetFormat.isStoreFormat` et `macOS.appStore` ne compilent
plus, et le code d'exécution qui conditionnait un comportement sandbox à `ExecutableRuntime.isPkg()`
doit appeler `ExecutableRuntime.isSandboxed()`. Voir [Migrer depuis 2.x](/docs/migrate/from-2.x).
</Callout>

## Conserver les natives d'une bibliothèque dans son JAR

Une bibliothèque dont le chargeur vérifie les octets extraits (nombre magique, checksum) échoue
dans le build sandboxé. Exemptez son JAR par une sous-chaîne de son nom :

```kotlin title="build.gradle.kts"
nativeDistributions {
    sandboxing {
        keepNativeLibsInJars("some-validating-lib")
    }
}
```

Sur le Mac App Store, ce chargement peut encore échouer à la validation des bibliothèques. Préférez
une option de la bibliothèque qui accepte un chemin externe quand elle existe.

## Configurer les entitlements macOS

| Entitlement par défaut | DMG, ZIP, PKG Developer ID | PKG App Store |
|---|---|---|
| `com.apple.security.cs.allow-jit` | oui | oui |
| `com.apple.security.cs.allow-unsigned-executable-memory` | oui | oui |
| `com.apple.security.cs.disable-library-validation` | oui | oui |
| `com.apple.security.app-sandbox` | | oui |
| `com.apple.security.network.client` | | oui |
| `com.apple.security.files.user-selected.read-write` | | oui |

Les entitlements du runtime, appliqués aux binaires de la JVM livrée, retirent l'accès réseau et
fichiers. Remplacez l'un ou l'autre fichier, et ajoutez les deux provisioning profiles qu'exige le
Mac App Store :

```kotlin title="build.gradle.kts"
macOS {
    entitlementsFile.set(project.file("packaging/entitlements.plist"))
    runtimeEntitlementsFile.set(project.file("packaging/runtime-entitlements.plist"))
    provisioningProfile.set(project.file("packaging/MyApp.provisionprofile"))
    runtimeProvisioningProfile.set(project.file("packaging/MyApp_Runtime.provisionprofile"))
}
```

## Configurer le sandbox Flatpak

```kotlin title="build.gradle.kts"
linux {
    flatpak {
        finishArgs = listOf(
            "--share=ipc", "--socket=wayland", "--socket=pulseaudio",
            "--device=dri", "--filesystem=home", "--share=network",
        )
    }
}
```

Voir [Construire pour Linux](/docs/packaging/linux#publier-sur-flathub-avec-flatpak) pour les
autres options Flatpak.

## Détecter le sandbox à l'exécution

```kotlin
import dev.nucleusframework.core.runtime.ExecutableRuntime

if (!ExecutableRuntime.isSandboxed()) {
    // Enregistrer un launch agent, écrire hors du conteneur, se mettre à jour, ...
}
```

`isSandboxed()` renvoie `true` dans l'App Sandbox de macOS, dans un conteneur AppX ou dans un
Flatpak. La réponse suit le sandbox, pas le format d'installation : un PKG Developer ID renvoie
`false`.

<Accordions>
<Accordion title="En coulisses">

- Le pipeline sandboxé extrait les fichiers `.dylib`, `.jnilib`, `.so` et `.dll` des JAR de
  dépendances vers `Contents/Frameworks/` (macOS) ou le répertoire de ressources de l'application,
  les remplace par des marqueurs et réécrit `System.load(String)` et `Runtime.load(String)` pour
  charger la copie livrée.
- Il définit `java.library.path`, `jna.library.path`, `jna.boot.library.path`, `jna.nounpack=true`
  et `jna.nosys=true`. L'image arrive dans `app-sandboxed/`, à côté de `app/`.
- AppX rejoint ce pipeline uniquement parce que MSIX interdit d'extraire des DLL à l'exécution.
- Sur macOS, `isSandboxed()` lit `APP_SANDBOX_CONTAINER_ID`.

</Accordion>
</Accordions>
