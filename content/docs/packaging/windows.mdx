This page covers the `windows { }` block: NSIS, MSI, AppX, and Portable builds. Windows formats
build only on a Windows host. To sign them, see [Code signing](/docs/packaging/code-signing#sign-on-windows).

## Configure the Windows build

```kotlin title="build.gradle.kts"
nativeDistributions {
    targetFormats(TargetFormat.Nsis, TargetFormat.Msi, TargetFormat.AppX, TargetFormat.Portable)
    windows {
        iconFile.set(project.file("icons/app.ico"))
        upgradeUuid = "d24e3b8d-3e9b-4cc7-a5d8-5e2d1f0c9f1b"
        menuGroup = "My Company"
    }
}
```

| Format | Output |
|--------|--------|
| `Nsis`, `Exe` | The standard NSIS installer. |
| `NsisWeb` | A small NSIS stub that downloads the payload at install time. |
| `Msi` | A Windows Installer package for managed deployment. |
| `AppX` | An MSIX/AppX package for the Microsoft Store and sideloading. |
| `Portable` | A single executable that runs without installation. |

## Customize the NSIS installer

```kotlin title="build.gradle.kts"
windows {
    nsis {
        oneClick = false
        perMachine = true
        allowToChangeInstallationDirectory = true
        createDesktopShortcut = true
        installerLanguages = listOf("en_US", "fr_FR")
        license.set(project.file("LICENSE"))
        deleteAppDataOnUninstall = true
    }
}
```

`nsis { }` maps to electron-builder's NSIS options. `script` and `includeScript` take your own
`.nsi` and `.nsh` files. `deleteAppDataOnUninstall` removes `%APPDATA%\<appId>`. With a custom
`includeScript`, delete that directory from your own `customUnInstall` macro instead.

## Build an MSI for enterprise deployment

Keep `upgradeUuid` fixed across releases. Windows matches successor versions by that UUID; without
it, each build installs as a separate product.

```kotlin title="build.gradle.kts"
windows {
    msi {
        perMachine = false        // per-user install; default is true
        oneClick = false          // assisted wizard
        createDesktopShortcut = true
    }
}
```

`perMachine`, `oneClick`, `runAfterFinish`, and both shortcut flags default to `true`.
`windows.perUserInstall` is deprecated. `windows.menu` and `windows.shortcut` do not apply to MSI.
For custom dialogs or registry changes, use NSIS.

## Build an AppX or MSIX package

```kotlin title="build.gradle.kts"
windows {
    appx {
        identityName = "MyCompany.MyApp"
        publisher = "CN=D541E802-6D30-446A-864E-2E8ABD2DAA5E"
        publisherDisplayName = "My Company"
        applicationId = "MyApp"
        square150x150Logo.set(project.file("packaging/appx/Square150x150Logo.png"))
        minVersion = "10.0.17763.0" // the Store requires more than 10.0.17134.0
    }
}
```

<Callout type="warn" title="Microsoft Store identity">
For a Store submission, `identityName`, `publisher`, and `publisherDisplayName` must match the
values Partner Center assigned to your reservation. `publisher` is the `CN=<GUID>` from Partner
Center, not your signing certificate's subject.
</Callout>

Building AppX locally needs Windows Developer Mode (Settings, System, For developers). The app runs
with `runFullTrust` and keeps Win32 access. The `build-windows-appxbundle` CI action merges amd64
and arm64 into one `.msixbundle`. AppX uses the [sandboxed pipeline](/docs/packaging/sandboxing).

## Enable Portable mode

`TargetFormat.Portable` builds one executable that needs no installer, admin rights, or registry
entries. It unpacks at each launch, so a lower compression level starts faster:

```kotlin title="build.gradle.kts"
windows {
    portable { compressionLevel = CompressionLevel.Normal }
}
```

## Add file associations and deep links

Associations and protocols declared on `nativeDistributions` reach every Windows format:

```kotlin title="build.gradle.kts"
nativeDistributions {
    protocol("MyApp", "myapp") // myapp:// deep links
    fileAssociation(mimeType = "application/x-myapp", extension = "myapp", description = "MyApp Document")
}
```

Use `windows.fileAssociation(...)` to set a Windows-specific icon.

## Ship the ANGLE libraries

Nucleus renders through ANGLE on Direct3D 11 on Windows. The DLLs come with the window module as
the transitive dependency `dev.nucleusframework:nucleus.angle-natives` (x64 and arm64), so you add
nothing. They ship [next to the app](/docs/packaging#native-libraries-next-to-the-app).

## Reference

The plugin generates `latest.yml` for NSIS, NSIS Web, MSI, and Portable; AppX updates come from the
Store. Nucleus sets the AppUserModelID at startup, so taskbar grouping and notifications work. The
full `windows { }` block is in the [Gradle DSL reference](/docs/reference/gradle-dsl).
