This page covers the `macOS { }` block: DMG and PKG builds, app extensions, and universal
binaries. You need a macOS host with Xcode Command Line Tools and an Apple Developer account.

## Configure the macOS block

```kotlin title="build.gradle.kts"
nativeDistributions {
    targetFormats(TargetFormat.Dmg, TargetFormat.Zip, TargetFormat.Pkg)
    macOS {
        bundleID = "com.example.myapp"
        appCategory = "public.app-category.utilities"
        minimumSystemVersion = "12.0"
        iconFile.set(project.file("icons/app.icns"))
        layeredIconDir.set(project.file("icons/MyApp.icon")) // macOS 26, needs Xcode CLT 26+

        signing {
            sign.set(true)
            identity.set("Developer ID Application: My Company (TEAMID)")
        }
        notarization {
            appleID.set("dev@example.com")
            password.set(System.getenv("MAC_NOTARIZATION_PASSWORD"))
            teamID.set("TEAMID")
        }
    }
}
```

The plugin picks the certificate each format needs from that one identity. For other notarization
modes, see [Code signing](/docs/packaging/code-signing#choose-a-notarization-mode).

| Format | Certificates |
|--------|--------------|
| DMG, ZIP | Developer ID Application |
| Developer ID PKG | Developer ID Application, Developer ID Installer |
| Mac App Store PKG | 3rd Party Mac Developer Application and Installer, provisioning profiles |

## Package a DMG

`./gradlew packageDmg` builds the DMG. With `notarization { }` credentials, `notarizeDmg`
notarizes and staples it, and `packageDistributionForCurrentOS` runs that task for you.

```kotlin title="build.gradle.kts"
macOS {
    dmg {
        window { x = 400; y = 100; width = 540; height = 380 }
        background.set(project.file("packaging/dmg-bg.png"))
        content(x = 130, y = 220, type = DmgContentType.File, name = "MyApp.app")
        content(x = 410, y = 220, type = DmgContentType.Link, path = "/Applications")
    }
}
```

Set `dmg { sign = true }` to sign the disk image itself with the `signing { identity }`. It
requires `signing { sign.set(true) }`, and the plugin signs the image before `notarizeDmg` runs.

`nativeDistributions.compressionLevel = CompressionLevel.Ultra` requires `minimumSystemVersion`
10.15+ and no pinned `dmg.format`. Ship a `Zip`
next to the DMG if you use [auto-update](/docs/packaging/auto-update).

## Choose a PKG channel

`macOS { pkg { appStore } }` selects the channel. The default, `true`, targets the Mac App Store.

| | `appStore = true` (default) | `appStore = false` |
|---|---|---|
| Distribution | Mac App Store (Transporter) | Direct download, MDM |
| Pipeline | [Sandboxed](/docs/packaging/sandboxing) | Same as DMG |
| Notarized | No, Apple reviews the upload | Yes, by `notarizePkg` |
| Install scripts | Fail the build | `preInstall`, `postInstall` |
| Auto-update | Store-managed | Self-updatable |

<Callout type="warn" title="Changed in 3.0">
`macOS.appStore` and `TargetFormat.isStoreFormat` no longer compile. Set `macOS { pkg { appStore = … } }`
explicitly. The old `appStore` property was ignored, so review which channel each build should
use. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

### Package for the Mac App Store

```kotlin title="build.gradle.kts"
macOS {
    entitlementsFile.set(project.file("packaging/sandbox-entitlements.plist"))
    runtimeEntitlementsFile.set(project.file("packaging/sandbox-runtime-entitlements.plist"))
    provisioningProfile.set(project.file("packaging/MyApp.provisionprofile"))
    runtimeProvisioningProfile.set(project.file("packaging/MyApp_Runtime.provisionprofile"))
}
```

Run `./gradlew packagePkg`. At runtime, `ExecutableRuntime.isSandboxed()` tells you whether the
App Sandbox applies. See [Sandboxing](/docs/packaging/sandboxing#detect-the-sandbox-at-runtime).

### Package a Developer ID PKG

```kotlin title="build.gradle.kts"
macOS {
    pkg {
        appStore = false
        preInstall.set(file("packaging/macos/preinstall"))
        postInstall.set(file("packaging/macos/postinstall"))
    }
}
```

Run `./gradlew packagePkg notarizePkg`. The Installer runs both scripts as root, once per install.
Each needs a shebang and receives `$1` package path, `$2` install target, `$3` target volume, `$4`
startup disk.

## Embed app extensions

Nucleus copies and signs prebuilt `.appex` bundles, such as a Network Extension, into
`Contents/PlugIns/`. You build the `.appex` with Xcode or Kotlin/Native.

```kotlin title="build.gradle.kts"
macOS {
    entitlementsFile.set(file("packaging/app.entitlements"))
    appExtensions {
        extension("NetworkFilter") {
            appex(file("build/appex/NetworkFilter.appex"))
            entitlements(file("packaging/extension/NetworkExtension.entitlements"))
            provisioningProfile(file("packaging/NetworkFilter.provisionprofile")) // optional
        }
    }
}
```

- Point `entitlementsFile` at a plist with `com.apple.security.cs.allow-jit` only. A host that keeps
  the default `allow-unsigned-executable-memory` and `disable-library-validation` next to a network
  extension has been reported not to launch.
- `run` cannot load extensions. Use `runDistributable`.
- A network extension needs an Apple-issued profile granting
  `com.apple.developer.networking.networkextension`.
- Nucleus does not activate the extension. Call `NEFilterManager` or `NETunnelProviderManager`.

## Enable Liquid Glass on SDK 26

macOS 26 enables Liquid Glass only for apps built against SDK 26.0. The plugin marks the launcher
with any JDK, including in `run`. Set `macOS { macOsSdkVersion = null }` to opt out. GraalVM native
images need Xcode 26 selected on the build host instead.

## Build a universal binary

Build `arm64` and `x86_64` on separate runners, then merge them with the `build-macos-universal`
action. See [CI/CD](/docs/packaging/ci-cd#merge-the-universal-macos-binary).

## Declare document types

Every `fileAssociation(...)` becomes a `CFBundleDocumentTypes` entry with a `CFBundleTypeRole`
and an `LSHandlerRank`. The defaults are `Editor` and `Default`, which clears App Store Connect's
ITMS-90788 warning. To change them, declare the association in the `macOS { }` block:

```kotlin title="build.gradle.kts"
macOS {
    fileAssociation(
        mimeType = "image/x-raw",
        extension = "raw",
        description = "RAW image",
        role = MacOSDocumentRole.Viewer,
        rank = MacOSHandlerRank.Alternate,
    )
}
```

| `role` | The app… | `rank` | Launch Services… |
| --- | --- | --- | --- |
| `Editor` | reads and writes the type | `Owner` | treats the app as the type's creator and primary handler |
| `Viewer` | only reads it | `Default` | ranks the app like any other handler |
| `Shell` | provides runtime services for it | `Alternate` | never picks the app as the default handler |
| `None` | declares it for import or export only | `None` | never offers the app |

The top-level `fileAssociation(...)` always uses `Editor` and `Default` on macOS.

## Customize Info.plist and launch agents

```kotlin title="build.gradle.kts"
macOS {
    infoPlist {
        extraKeysRawXml = """<key>NSMicrophoneUsageDescription</key><string>Voice notes.</string>"""
    }
    launchAgents {
        agent("com.example.myapp.indexer") { bundleProgram("Contents/MacOS/indexer") }
    }
}
```

Register launch agents at runtime with [Service management](/docs/lifecycle/background/service-management).

### Localize Info.plist strings

macOS reads localized `Info.plist` values, such as the text of a permission prompt, from
`Contents/Resources/<lang>.lproj/InfoPlist.strings`. Declare them per language, or copy prebuilt
`.lproj` directories:

```kotlin title="build.gradle.kts"
macOS {
    infoPlist {
        extraKeysRawXml = """<key>NSMicrophoneUsageDescription</key><string>Voice notes.</string>"""
        localization("fr", mapOf("NSMicrophoneUsageDescription" to "Notes vocales."))
        localization("de", mapOf("NSMicrophoneUsageDescription" to "Sprachnotizen."))
        localizationsDir = file("packaging/macos/localizations") // es.lproj/InfoPlist.strings, ...
    }
}
```

The plugin writes the files into the bundle before signing it, in JVM and GraalVM builds.
`localizationsDir` holds only `<lang>.lproj` directories. A language declared with
`localization(...)` must not also have an `InfoPlist.strings` in `localizationsDir`, or the build
fails.
