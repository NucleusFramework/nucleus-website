Three formats run sandboxed: the Mac App Store PKG ([App Sandbox](https://developer.apple.com/documentation/security/app-sandbox)),
`AppX` (MSIX, full trust), and `Flatpak` ([Flatpak sandbox](https://docs.flatpak.org/en/latest/sandbox-permissions.html)).
Add them to `targetFormats` next to your regular formats, and Nucleus bundles their native
libraries ahead of time.

```kotlin title="build.gradle.kts"
targetFormats(
    TargetFormat.Dmg, TargetFormat.Nsis, TargetFormat.Deb,
    TargetFormat.Pkg,     // with macOS { pkg { appStore = true } }, the default
    TargetFormat.AppX,
    TargetFormat.Flatpak,
)
```

A PKG with `macOS { pkg { appStore = false } }` is a Developer ID PKG and builds like a DMG. See
[Choose a PKG channel](/docs/packaging/macos#choose-a-pkg-channel).

<Callout type="warn" title="Changed in 3.0">
A PKG no longer implies the App Sandbox. `TargetFormat.isStoreFormat` and `macOS.appStore` no
longer compile, and runtime code that gated sandbox behavior on `ExecutableRuntime.isPkg()` should
call `ExecutableRuntime.isSandboxed()`. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

## Keep a library's natives in its JAR

A library whose loader checks the extracted bytes (magic number, checksum) fails in the sandboxed
build. Exempt its JAR by a name substring:

```kotlin title="build.gradle.kts"
nativeDistributions {
    sandboxing {
        keepNativeLibsInJars("some-validating-lib")
    }
}
```

On the Mac App Store, that load can still fail library validation. Prefer a library option that
takes an external library path when one exists.

## Configure macOS entitlements

| Default entitlement | DMG, ZIP, Developer ID PKG | App Store PKG |
|---|---|---|
| `com.apple.security.cs.allow-jit` | yes | yes |
| `com.apple.security.cs.allow-unsigned-executable-memory` | yes | yes |
| `com.apple.security.cs.disable-library-validation` | yes | yes |
| `com.apple.security.app-sandbox` | | yes |
| `com.apple.security.network.client` | | yes |
| `com.apple.security.files.user-selected.read-write` | | yes |

The runtime entitlements, applied to the bundled JVM binaries, drop network and file access. Override
either file, and add the two provisioning profiles the Mac App Store requires:

```kotlin title="build.gradle.kts"
macOS {
    entitlementsFile.set(project.file("packaging/entitlements.plist"))
    runtimeEntitlementsFile.set(project.file("packaging/runtime-entitlements.plist"))
    provisioningProfile.set(project.file("packaging/MyApp.provisionprofile"))
    runtimeProvisioningProfile.set(project.file("packaging/MyApp_Runtime.provisionprofile"))
}
```

## Configure the Flatpak sandbox

```kotlin title="build.gradle.kts"
linux {
    flatpak {
        finishArgs = listOf(
            "--share=ipc", "--socket=wayland", "--socket=pulseaudio",
            "--device=dri", "--filesystem=home", "--share=network",
        )
    }
}
```

See [Building for Linux](/docs/packaging/linux#publish-to-flathub-with-flatpak) for the other
Flatpak options.

## Detect the sandbox at runtime

```kotlin
import dev.nucleusframework.core.runtime.ExecutableRuntime

if (!ExecutableRuntime.isSandboxed()) {
    // Register a launch agent, write outside the container, self-update, ...
}
```

`isSandboxed()` returns `true` inside the macOS App Sandbox, an AppX container, or a Flatpak. It
follows the sandbox, not the installer format: a Developer ID PKG reports `false`.

<Accordions>
<Accordion title="Under the hood">

- The sandboxed pipeline extracts `.dylib`, `.jnilib`, `.so`, and `.dll` files from the dependency
  JARs into `Contents/Frameworks/` (macOS) or the app's resources directory, replaces them with
  markers, and rewrites `System.load(String)` and `Runtime.load(String)` to load the bundled copy.
- It sets `java.library.path`, `jna.library.path`, `jna.boot.library.path`, `jna.nounpack=true`
  and `jna.nosys=true`. The image lands in `app-sandboxed/` next to `app/`.
- AppX joins this pipeline only because MSIX forbids extracting DLLs at runtime.
- On macOS, `isSandboxed()` reads `APP_SANDBOX_CONTAINER_ID`.

</Accordion>
</Accordions>
