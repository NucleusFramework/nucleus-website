Two formats run sandboxed: the Mac App Store PKG ([App Sandbox](https://developer.apple.com/documentation/security/app-sandbox))
and `Flatpak` ([Flatpak sandbox](https://docs.flatpak.org/en/latest/sandbox-permissions.html)).
Add them to `targetFormats` next to your regular formats, and Nucleus bundles their native
libraries ahead of time.

```kotlin title="build.gradle.kts"
targetFormats(
    TargetFormat.Dmg, TargetFormat.Nsis, TargetFormat.Deb,
    TargetFormat.Pkg,     // with macOS { pkg { appStore = true } }, the default
    TargetFormat.Flatpak,
)
```

A PKG with `macOS { pkg { appStore = false } }` is a Developer ID PKG and builds like a DMG. See
[Choose a PKG channel](/docs/packaging/macos#choose-a-pkg-channel). `AppX` runs with full trust
and builds like the other Windows formats; see
[Build an AppX or MSIX package](/docs/packaging/windows#build-an-appx-or-msix-package).

<Callout type="warn" title="Changed in 3.0">
A PKG no longer implies the App Sandbox, and AppX no longer uses the sandboxed pipeline.
`TargetFormat.isStoreFormat` and `macOS.appStore` no longer compile, and runtime code that gated
sandbox behavior on `ExecutableRuntime.isPkg()` should call `ExecutableRuntime.isSandboxed()`. See
[Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

## Keep a library's natives in its JAR

A library whose loader checks the extracted bytes (magic number, checksum) fails in the sandboxed
build. Exempt its JAR by a name substring:

```kotlin title="build.gradle.kts"
nativeDistributions {
    sandboxing {
        keepNativeLibsInJars("some-validating-lib")
    }
}
```

On the Mac App Store, that load can still fail library validation. Prefer a library option that
takes an external library path when one exists.

## GraalVM native images

A GraalVM app gets its Mac App Store PKG from a second, sandboxed native image, built next to the
regular one only when `targetFormats` holds an App Store PKG. DMG, ZIP and Developer ID PKG keep
the regular image, unchanged.

```bash
./gradlew packageGraalvmPkg                              # the App Store PKG, from the sandboxed image
./gradlew runSandboxedGraalvmNativeDistributable          # run the sandboxed app on this Mac
```

The sandboxed image differs from the regular one in three ways, all handled by the plugin and by
`GraalVmInitializer`:

- **Native libraries** that dependency JARs extract at run time (JNA, zstd-kmp, a WebView, a tray)
  are extracted at build time, signed into `Contents/Frameworks/`, and loaded from there, as in
  the sandboxed JVM pipeline.
- **`user.home`** points at the app's container (`~/Library/Containers/<bundle id>/Data`), as on
  the JVM, instead of the account's home.
- **Signal handling**: the image runs without Substrate's signal handling, whose named semaphore
  the App Sandbox denies. SIGINT, SIGTERM and SIGHUP still run the shutdown hooks and exit with
  `128 + signal`, like the JVM. What does not work is your own `sun.misc.Signal.handle` for other
  signals (SIGUSR1, ...).

`sandboxing { keepNativeLibsInJars(...) }` does not apply to the native image, which is compiled
from a single JAR; every native library is redirected to `Contents/Frameworks/`.

<Callout title="Launch it from its bundle">
A sandboxed app must run from its `.app`, as Finder, `open` and the Dock launch it. Started through
a symlink to its binary, AppKit stops it at launch.
</Callout>

## Configure macOS entitlements

| Default entitlement | DMG, ZIP, Developer ID PKG | App Store PKG |
|---|---|---|
| `com.apple.security.cs.allow-jit` | yes | yes |
| `com.apple.security.cs.allow-unsigned-executable-memory` | yes | yes |
| `com.apple.security.cs.disable-library-validation` | yes | yes |
| `com.apple.security.app-sandbox` | | yes |
| `com.apple.security.network.client` | | yes |
| `com.apple.security.files.user-selected.read-write` | | yes |

The runtime entitlements, applied to the bundled JVM binaries, drop network and file access. Override
either file, and add the two provisioning profiles the Mac App Store requires:

```kotlin title="build.gradle.kts"
macOS {
    entitlementsFile.set(project.file("packaging/entitlements.plist"))
    runtimeEntitlementsFile.set(project.file("packaging/runtime-entitlements.plist"))
    provisioningProfile.set(project.file("packaging/MyApp.provisionprofile"))
    runtimeProvisioningProfile.set(project.file("packaging/MyApp_Runtime.provisionprofile"))
}
```

## Configure the Flatpak sandbox

```kotlin title="build.gradle.kts"
linux {
    flatpak {
        finishArgs = listOf(
            "--share=ipc", "--socket=wayland", "--socket=pulseaudio",
            "--device=dri", "--filesystem=home", "--share=network",
        )
    }
}
```

See [Building for Linux](/docs/packaging/linux#build-a-flatpak-bundle) for the other
Flatpak options.

## Detect the sandbox at runtime

```kotlin
import dev.nucleusframework.core.runtime.ExecutableRuntime

if (!ExecutableRuntime.isSandboxed()) {
    // Register a launch agent, write outside the container, self-update, ...
}
```

`isSandboxed()` returns `true` inside the macOS App Sandbox or a Flatpak. It follows the sandbox,
not the installer format: a Developer ID PKG reports `false`, and so does an AppX, which runs as a
full-trust Win32 process. Check `ExecutableRuntime.isAppX()` for the latter.

<Accordions>
<Accordion title="Under the hood">

- The sandboxed pipeline extracts `.dylib`, `.jnilib`, `.so`, and `.dll` files from the dependency
  JARs into `Contents/Frameworks/` (macOS) or the app's resources directory, replaces them with
  markers, and rewrites `System.load(String)` and `Runtime.load(String)` to load the bundled copy.
- It sets `java.library.path`, `jna.library.path`, `jna.boot.library.path`, `jna.nounpack=true`
  and `jna.nosys=true`. The image lands in `app-sandboxed/` next to `app/`.
- On macOS, `isSandboxed()` reads `APP_SANDBOX_CONTAINER_ID`.
- A sandboxed GraalVM image is recognized at run time by `Contents/Resources/nucleus-sandbox-manifest.properties`;
  its tasks are `stripGraalvmNativeLibsForSandboxing`, `extractGraalvmNativeLibsForSandboxing`,
  `nativeImageCompileSandboxed` and `createSandboxedGraalvmNativeDistributable`, which lands in
  `graalvm-app-sandboxed/`.

</Accordion>
