Cette page couvre le bloc `windows { }` : builds NSIS, MSI, AppX et Portable. Les formats Windows
se construisent uniquement sur un hôte Windows. Pour les signer, voir
[Signature du code](/docs/packaging/code-signing#signer-sur-windows).

## Configurer le build Windows

```kotlin title="build.gradle.kts"
nativeDistributions {
    targetFormats(TargetFormat.Nsis, TargetFormat.Msi, TargetFormat.AppX, TargetFormat.Portable)
    windows {
        iconFile.set(project.file("icons/app.ico"))
        upgradeUuid = "d24e3b8d-3e9b-4cc7-a5d8-5e2d1f0c9f1b"
        menuGroup = "My Company"
    }
}
```

| Format | Résultat |
|--------|----------|
| `Nsis`, `Exe` | L'installateur NSIS standard. |
| `NsisWeb` | Un petit lanceur NSIS qui télécharge le contenu à l'installation. |
| `Msi` | Un paquet Windows Installer pour le déploiement géré. |
| `AppX` | Un paquet MSIX/AppX pour le Microsoft Store et le sideloading. |
| `Portable` | Un exécutable unique qui tourne sans installation. |

## Personnaliser l'installateur NSIS

```kotlin title="build.gradle.kts"
windows {
    nsis {
        oneClick = false
        perMachine = true
        allowToChangeInstallationDirectory = true
        createDesktopShortcut = true
        installerLanguages = listOf("en_US", "fr_FR")
        license.set(project.file("LICENSE"))
        deleteAppDataOnUninstall = true
    }
}
```

`nsis { }` correspond aux options NSIS d'electron-builder. `script` et `includeScript` acceptent
vos propres fichiers `.nsi` et `.nsh`. `deleteAppDataOnUninstall` supprime `%APPDATA%\<appId>`.
Avec un `includeScript` personnalisé, supprimez ce répertoire depuis votre propre macro
`customUnInstall`.

## Construire un MSI pour le déploiement en entreprise

Gardez `upgradeUuid` fixe d'une release à l'autre. Windows reconnaît les versions successives par
cet UUID ; sans lui, chaque build s'installe comme un produit distinct.

```kotlin title="build.gradle.kts"
windows {
    msi {
        perMachine = false        // installation par utilisateur ; défaut : true
        oneClick = false          // assistant guidé
        createDesktopShortcut = true
    }
}
```

`perMachine`, `oneClick`, `runAfterFinish` et les deux options de raccourci valent `true` par
défaut. `windows.perUserInstall` est déprécié. `windows.menu` et `windows.shortcut` ne
s'appliquent pas au MSI. Pour des dialogues personnalisés ou des modifications du registre,
utilisez NSIS.

## Construire un package AppX ou MSIX

```kotlin title="build.gradle.kts"
windows {
    appx {
        identityName = "MyCompany.MyApp"
        publisher = "CN=D541E802-6D30-446A-864E-2E8ABD2DAA5E"
        publisherDisplayName = "My Company"
        applicationId = "MyApp"
        square150x150Logo.set(project.file("packaging/appx/Square150x150Logo.png"))
        minVersion = "10.0.17763.0" // le Store exige plus que 10.0.17134.0
    }
}
```

<Callout type="warn" title="Identité Microsoft Store">
Pour une soumission au Store, `identityName`, `publisher` et `publisherDisplayName` doivent
correspondre aux valeurs attribuées par Partner Center à votre réservation. `publisher` est le
`CN=<GUID>` de Partner Center, pas le sujet de votre certificat de signature.
</Callout>

Construire un AppX en local exige le mode développeur de Windows (Paramètres, Système, Pour les
développeurs). L'application tourne avec `runFullTrust` et garde l'accès Win32. L'action CI
`build-windows-appxbundle` fusionne amd64 et arm64 en un seul `.msixbundle`. AppX utilise le
[pipeline sandboxé](/docs/packaging/sandboxing).

## Activer le mode portable

`TargetFormat.Portable` construit un seul exécutable, sans installateur, droits administrateur ni
entrées de registre. Il se décompresse à chaque lancement : un niveau de compression plus faible
démarre plus vite.

```kotlin title="build.gradle.kts"
windows {
    portable { compressionLevel = CompressionLevel.Normal }
}
```

## Ajouter des associations de fichiers et des deep links

Les associations et protocoles déclarés sur `nativeDistributions` s'appliquent à chaque format
Windows :

```kotlin title="build.gradle.kts"
nativeDistributions {
    protocol("MyApp", "myapp") // deep links myapp://
    fileAssociation(mimeType = "application/x-myapp", extension = "myapp", description = "MyApp Document")
}
```

Utilisez `windows.fileAssociation(...)` pour définir une icône propre à Windows.

## Livrer les bibliothèques ANGLE

Sur Windows, Nucleus rend via ANGLE sur Direct3D 11. Les DLL arrivent avec le module de fenêtre,
via la dépendance transitive `dev.nucleusframework:nucleus.angle-natives` (x64 et arm64) : vous
n'ajoutez rien. Elles sont livrées
[à côté de l'application](/docs/packaging#bibliothèques-natives-à-côté-de-lapplication).

## Référence

Le plugin génère `latest.yml` pour NSIS, NSIS Web, MSI et Portable ; les mises à jour AppX passent
par le Store. Nucleus définit l'AppUserModelID au démarrage : le regroupement dans la barre des
tâches et les notifications fonctionnent. Le bloc `windows { }` complet se trouve dans la
[référence du DSL Gradle](/docs/reference/gradle-dsl).
