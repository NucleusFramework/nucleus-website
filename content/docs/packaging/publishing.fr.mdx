import { Tab, Tabs } from 'fumadocs-ui/components/tabs';

`publish { }`, dans `nativeDistributions { }`, indique à Nucleus où vivent vos installateurs et
leurs métadonnées de [mise à jour automatique](/docs/packaging/auto-update). Activez un backend.

## Configurer un backend de publication

<Tabs items={['GitHub Releases', 'S3', 'HTTPS générique']}>
<Tab value="GitHub Releases">

```kotlin title="build.gradle.kts"
publish {
    github {
        enabled = true
        owner = "myorg"
        repo = "myapp"
        token = System.getenv("GITHUB_TOKEN") // exige contents: write
        channel = ReleaseChannel.Latest
        releaseType = ReleaseType.Release // ou Draft, Prerelease
    }
}
```

</Tab>
<Tab value="S3">

```kotlin title="build.gradle.kts"
publish {
    s3 {
        enabled = true
        bucket = "my-updates-bucket"
        region = "us-east-1"
        path = "releases/myapp"
        acl = "public-read"
    }
}
```

Fournissez `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` et `AWS_REGION` dans l'environnement.

</Tab>
<Tab value="HTTPS générique">

```kotlin title="build.gradle.kts"
publish {
    generic {
        enabled = true
        url = "https://updates.example.com/releases/"
        channel = ReleaseChannel.Latest
        useMultipleRangeRequest = true // défaut
    }
}
```

Vous envoyez les fichiers sur n'importe quel hébergement statique. Il doit servir les requêtes HTTP
`Range` en `https`.

</Tab>
</Tabs>

`channel` choisit le YAML que lit l'updater : `Latest` (`latest-*.yml`, tag `v1.0.0`), `Beta`
(`beta-*.yml`, `v1.0.0-beta.1`) ou `Alpha` (`alpha-*.yml`, `v1.0.0-alpha.1`).

## Définir le mode de publication

```kotlin title="build.gradle.kts"
publish {
    publishMode = PublishMode.Auto
}
```

| Mode | Comportement |
|------|--------------|
| `PublishMode.Never` (défaut) | Aucun envoi. Le plugin écrit tout de même `latest-*.yml` pour chaque format qui se met à jour. |
| `PublishMode.Auto` | Envoi quand le build part d'un tag git. |
| `PublishMode.Always` | Envoi à chaque build. |

La propriété Gradle `compose.electronBuilder.publishMode` remplace la valeur du DSL le temps d'une
exécution. Le [workflow CI/CD](/docs/packaging/ci-cd#publier-la-release) de référence garde `Never`
et envoie les fichiers dans un job séparé.

## Soumettre à un store desktop

Les builds pour store n'utilisent pas `publish { }`. Envoyez le format store par le canal de
l'éditeur :

- **Mac App Store** : le PKG App Store, avec Transporter ou `xcrun altool`. Voir
  [Empaqueter pour le Mac App Store](/docs/packaging/macos#empaqueter-pour-le-mac-app-store).
- **Microsoft Store** : le `.msixbundle`, dans [Partner Center](https://partner.microsoft.com/).
  `identityName`, `publisher` (`CN=<GUID>`) et `publisherDisplayName` doivent correspondre à la
  réservation. Voir [Construire un package AppX ou MSIX](/docs/packaging/windows#construire-un-package-appx-ou-msix).
- **Snap Store** : `snapcraft upload` depuis la CI. Le confinement `classic` exige l'approbation du
  Snap Store.
- **Flathub** : une pull request de manifeste sur le [dépôt Flathub](https://github.com/flathub/flathub).
