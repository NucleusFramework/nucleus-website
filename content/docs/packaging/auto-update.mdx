`updater-runtime` checks for, downloads, verifies, and installs updates from Kotlin. The build
writes `latest-*.yml` metadata next to your installers, in electron-builder's format; you choose
where it lives in [Publishing](/docs/packaging/publishing).

## Add the dependency

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.updater-runtime:<version>")
}
```

## Check and install an update

```kotlin
val updater = NucleusUpdater {
    provider = GitHubProvider(owner = "myorg", repo = "myapp")
}

when (val result = updater.checkForUpdates()) {
    is UpdateResult.Available -> {
        var installer: File? = null
        updater.downloadUpdate(result.info).collect { progress ->
            println("${progress.percent.toInt()}%")
            progress.file?.let { installer = it }
        }
        // Installs the update and relaunches the app on the new version
        installer?.let(updater::installAndRestart)
    }
    UpdateResult.NotAvailable -> println("Up to date")
    is UpdateResult.Error -> println("Error: ${result.exception.message}")
}
```

`checkForUpdates()` suspends. In a dev run (`currentVersion` is `0.0.0-dev`) it returns
`NotAvailable`. The tag picks the channel: `v1.0.0` is `latest`, `v1.0.0-beta.1` is `beta`,
`v1.0.0-alpha.1` is `alpha`. A `beta` user sees `latest` and `beta`; an `alpha` user sees all three.

## Supported formats

| Platform | Self-updatable | Store-managed (`NotAvailable`) |
|----------|----------------|---------------|
| macOS | DMG, ZIP, Developer ID PKG | App Store PKG |
| Windows | NSIS, NSIS Web, Exe, MSI | AppX/MSIX |
| Linux | DEB, RPM, AppImage | Snap, Flatpak |

<Callout type="warn" title="Ship a ZIP on macOS">
The updater replaces the `.app` from the release's ZIP, and falls back to the DMG. Add
`TargetFormat.Zip` next to `TargetFormat.Dmg` or `TargetFormat.Pkg` so `latest-mac.yml` lists it.
</Callout>

## Update without closing the app on Windows

On a per-user NSIS install, `installAndRestart` installs the new version while the app keeps
running, starts it, and closes the old one once the new window is on screen. The user never sees
the app disappear. If the install fails, the app stays on its current version. You write no extra
code in an app built on `nucleusApplication`.

- An app with no Nucleus window (tray-only, for example) calls `UpdateHandoff.signalReady()` once
  it is usable. Otherwise the old version exits after a timeout.
- `installAndRestart(file, relaunchArguments)` starts the new version with the arguments you pass,
  for example the document this instance has open. Nucleus does not replay the original command
  line.
- When several instances run, the others learn about the installed update through
  `updater.pendingRestartVersion` without downloading anything. Offer a "Restart to update" action
  and call `restartToInstalledVersion(relaunchArguments)`.

Per-machine installs, MSI, portable builds and GraalVM native images keep the classic update: the
app closes, the installer runs, the app relaunches.

<Callout type="warn" title="Changed in 3.0">
NSIS installs now keep the launcher at the install root and the runtime and app in
`versions\<version>\`. Code that builds paths relative to the install directory must follow the
new layout. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

## Differential downloads

`downloadUpdate` fetches only the changed blocks, and falls back to a full download when it cannot.
An AppImage is differential from its first update; other formats from the second.
`progress.isDifferential` tells you which kind ran, and `totalBytes` counts bytes transferred. Turn
it off when your CDN does not serve range requests:

```kotlin
val updater = NucleusUpdater {
    provider = GitHubProvider(owner = "myorg", repo = "myapp")
    differentialDownload = false
}
```

## Post-update detection

After `installAndRestart` or `installAndQuit`, the next launch sees `wasJustUpdated()` return
`true`, and `consumeUpdateEvent()` returns an `UpdateEvent(previousVersion, newVersion, updateLevel)`
for a "What's new" screen.

## Configure enterprise networks

Behind a proxy with a private root CA, the JDK `HttpClient` fails the TLS handshake. Add
`dev.nucleusframework:nucleus.native-http` and pass a `NativeHttpClient`, which trusts the OS
certificate store:

```kotlin
val updater = NucleusUpdater {
    provider = GitHubProvider(owner = "myorg", repo = "myapp")
    httpClient = NativeHttpClient.create()
}
```

See also [Trusted CA certificates](/docs/packaging/trusted-certificates).

## Set up passwordless updates on Linux

A DEB or RPM update runs through `pkexec`, which asks for a password. With
[signed packages](/docs/packaging/code-signing#sign-on-linux), the app skips the prompt:

```kotlin title="build.gradle.kts"
linux {
    signing {
        enabled.set(true)
        keyId.set("AB12CD34EF56")
        silentUpdate.set(true) // requires enabled = true
    }
}
```

It needs an active local session. When the helper or the `.asc` signature is missing, the runtime
logs why and falls back to the password prompt.

<Accordions>
<Accordion title="Under the hood">

- Differential downloads compare electron-builder block maps with the previous artifact cached in
  `cacheDir` and fetch changed blocks with HTTP range requests. A missing map, a failed range
  request, or a digest mismatch falls back to a full download.
- The updater checks the SHA-512 after download. On Windows it runs NSIS with `/S` and MSI with
  `msiexec /passive` after the app exits.
- Silent Linux updates go through a root-owned `/opt/<App>/nucleus-update-helper` that verifies the
  detached `.asc` against your bundled public key before it runs `dpkg -i` or `rpm -U`.

</Accordion>
</Accordions>

## API reference

### Runtime methods

- `suspend fun checkForUpdates(): UpdateResult`
- `fun downloadUpdate(info: UpdateInfo): Flow<DownloadProgress>`: the last emission has `file != null`.
- `fun installAndRestart(installerFile: File, relaunchArguments: List<String> = emptyList())`: installs and relaunches on the new version. Hot update on per-user NSIS installs.
- `val pendingRestartVersion: StateFlow<String?>`: a version another instance installed, or `null`.
- `fun restartToInstalledVersion(relaunchArguments: List<String> = emptyList()): Boolean`: switches to that version.
- `fun installAndQuit(installerFile: File)`: installs silently and exits without relaunching.
- `fun isUpdateSupported(): Boolean`: whether the current install can update itself.
- `fun wasJustUpdated(): Boolean`, `fun consumeUpdateEvent(): UpdateEvent?`
- `val currentVersion: String`

### Result and level types

- `UpdateResult.Available(info: UpdateInfo, level: UpdateLevel)`, `UpdateResult.NotAvailable`,
  `UpdateResult.Error(exception: UpdateException)`
- `UpdateLevel`: `MAJOR`, `MINOR`, `PATCH`, or `PRE_RELEASE`. Use it to force a dialog for a major
  version and install patches in the background.
- `UpdateException` subtypes: `NetworkException`, `ChecksumException`, `NoMatchingFileException`,
  `ParseException`.

### Builder fields

| Field | Default | Notes |
|-------|---------|-------|
| `currentVersion` | Detected from the packaged app | Compared with the remote version |
| `provider` | Required | `GitHubProvider` or `GenericProvider` |
| `channel` | `"latest"` | Release channel name |
| `allowDowngrade` | `false` | |
| `allowPrerelease` | `false` | Treated as `true` when `currentVersion` contains `-` |
| `executableType` | Detected | Forces the artifact type to download |
| `httpClient` | JDK client following redirects | `NativeHttpClient` for private CAs |
| `differentialDownload` | `true` | |
| `cacheDir` | `%LOCALAPPDATA%/nucleus/updates/<appId>` on Windows, `~/.cache/nucleus/updates/<appId>` elsewhere | Previous artifact and block map |

### Providers

- `GitHubProvider(owner, repo, token = null)`. The token travels in the `Authorization` header.
- `GenericProvider(baseUrl)`. `baseUrl` must use `https`, or construction throws
  `IllegalArgumentException`. Plain `http` works for loopback hosts only, for local tests.
