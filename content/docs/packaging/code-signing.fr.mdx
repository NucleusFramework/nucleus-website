Chaque OS a un bloc `signing { }` dans `nativeDistributions`. Il vous faut un compte Apple
Developer sur macOS, un certificat `.pfx`/`.p12` ou un compte Azure Artifact Signing sur Windows,
et une clé GPG sur Linux.

## Signer et notariser sur macOS

```kotlin title="build.gradle.kts"
macOS {
    signing {
        sign.set(true)
        identity.set("Developer ID Application: My Company (TEAMID)")
        // keychain.set("/path/to/signing.keychain-db")
    }
    notarization {
        appleID.set("dev@example.com")
        password.set(System.getenv("MAC_NOTARIZATION_PASSWORD"))
        teamID.set("TEAMID")
    }
}
```

Le plugin choisit le type de certificat de chaque format à partir de cette seule identité :

| Format | Signature de l'application | Signature de l'installateur | Notarisé |
|--------|----------------------------|-----------------------------|----------|
| DMG, ZIP | Developer ID Application | Aucune | Oui |
| PKG Developer ID (`pkg { appStore = false }`) | Developer ID Application | Developer ID Installer | Oui |
| PKG App Store (défaut) | 3rd Party Mac Developer Application | 3rd Party Mac Developer Installer | Non |

Le build d'un PKG Developer ID échoue quand le trousseau ne contient pas de certificat Developer ID
Installer de la même équipe.

### Choisir un mode de notarisation

Configurez un seul mode ; le build refuse un mélange. Sans identifiants, les tâches de
notarisation sont ignorées.

```kotlin
notarization {
    // 1. Apple ID avec un mot de passe spécifique à l'app
    appleID.set("dev@example.com"); password.set(System.getenv("MAC_NOTARIZATION_PASSWORD")); teamID.set("TEAMID")
    // 2. Profil de trousseau notarytool, créé avec `xcrun notarytool store-credentials AC_PASSWORD`
    keychainProfile.set("AC_PASSWORD") // keychainPath optionnel
    // 3. Clé d'API App Store Connect, le choix habituel en CI
    apiKey.set("/path/to/AuthKey_ABC123.p8"); apiKeyId.set("ABC123"); apiIssuer.set("12345678-90ab-cdef-1234-567890abcdef")
}
```

Un build universel doit être re-signé après `lipo`. L'action `build-macos-universal` s'en charge ;
voir [CI/CD](/docs/packaging/ci-cd#fusionner-le-binaire-macos-universel).

## Signer sur Windows

```kotlin title="build.gradle.kts"
windows {
    signing {
        enabled = true
        certificateFile.set(file(System.getenv("WIN_CSC_LINK") ?: "certs/certificate.pfx"))
        certificatePassword = System.getenv("WIN_CSC_KEY_PASSWORD")
        algorithm = SigningAlgorithm.Sha256 // défaut ; aussi Sha1, Sha512
        timestampServer = "http://timestamp.digicert.com"
    }
}
```

Pour utiliser un certificat du magasin Windows, réglez `certificateSha1` ou
`certificateSubjectName` à la place de `certificateFile`. Pour un HSM cloud, utilisez Azure
Artifact Signing :

```kotlin title="build.gradle.kts"
windows {
    signing {
        enabled = true
        publisherName = "My Publisher"
        azureTenantId = System.getenv("AZURE_TENANT_ID")
        azureEndpoint = "https://eastus.codesigning.azure.net"
        azureCertificateProfileName = "my-profile"
        azureCodeSigningAccountName = "my-account"
    }
}
```

Renouvelez un PFX avant son expiration : SmartScreen signale un binaire à la signature expirée
jusqu'à ce que vous appliquiez une nouvelle signature horodatée.

## Signer sur Linux

Une signature GPG permet aux utilisateurs qui téléchargent votre `.deb` ou `.rpm` hors d'un dépôt
d'en vérifier l'origine. La signature reste désactivée tant que `enabled` ne vaut pas `true` et que
`keyId` n'est pas défini.

```kotlin title="build.gradle.kts"
linux {
    signing {
        enabled.set(true)
        keyId.set("AB12CD34EF56")   // donné par gpg --list-secret-keys --keyid-format=long
        // passphrase.set(System.getenv("LINUX_GPG_PASSPHRASE"))
        debMethod = DebSignMethod.Detached // défaut
        silentUpdate.set(true)      // mise à jour sans mot de passe
    }
}
```

Le build lit la clé dans votre trousseau, ou depuis `keyFile` en CI. Chaque paquet reçoit une clé
publique `.pub.asc`, et le DEB une signature détachée `.deb.asc` : publiez-les à côté des paquets.
Les utilisateurs vérifient avec `gpg --verify <pkg>.deb.asc <pkg>.deb` ou `rpm -K <pkg>.rpm` après
avoir importé la clé.

`debMethod` accepte aussi `DpkgSig` (exige `dpkg-sig` sur l'hôte de build) et `Debsig` (les clients
vérifient avec `debsig-verify`). `Detached` n'exige que `gpg`. Pour `silentUpdate`, voir les
[mises à jour sans mot de passe](/docs/packaging/auto-update#mettre-en-place-les-mises-à-jour-sans-mot-de-passe-sur-linux).

## Configurer toutes les plateformes dans un seul bloc

`nativeDistributions.signing { }` écrit dans les mêmes blocs par OS : vous pouvez mélanger les
deux styles.

```kotlin title="build.gradle.kts"
nativeDistributions {
    signing {
        macOS   { sign.set(true); identity.set("Developer ID Application: My Company (TEAMID)") }
        windows { enabled = true; certificateFile.set(file("certs/certificate.pfx")) }
        linux   { enabled.set(true); keyId.set("AB12CD34EF56") }
    }
}
```

## Gérer les secrets de signature en CI

Gardez certificats et clés hors du dépôt. Sur macOS, l'action `setup-macos-signing` importe un
`.p12` en base64 dans un trousseau temporaire ; voir
[CI/CD](/docs/packaging/ci-cd#signer-les-builds-macos). Les réglages macOS et Linux lisent aussi
des propriétés Gradle, à passer avec `-P` ou `gradle.properties` :

| Réglage | Propriété Gradle |
|---------|------------------|
| `macOS.signing.*` | `compose.desktop.mac.sign`, `compose.desktop.mac.signing.{identity,keychain,prefix}` |
| `macOS.notarization.*` | `compose.desktop.mac.notarization.{appleID,password,teamID,keychainProfile,keychainPath,apiKey,apiKeyId,apiIssuer}` |
| `linux.signing.*` | `compose.desktop.linux.sign`, `compose.desktop.linux.signing.{keyId,keyFile,passphrase,silentUpdate}` |

Pour Linux, stockez `gpg --armor --export-secret-keys <keyId>` dans un secret, puis écrivez-le dans
un fichier :

```yaml title=".github/workflows/release.yaml"
- name: Configure Linux GPG signing
  if: runner.os == 'Linux'
  shell: bash
  env:
    LINUX_GPG_PRIVATE_KEY: ${{ secrets.LINUX_GPG_PRIVATE_KEY }}
    LINUX_GPG_KEY_ID: ${{ secrets.LINUX_GPG_KEY_ID }}
  run: |
    [ -z "$LINUX_GPG_PRIVATE_KEY" ] && exit 0
    KEY_FILE="$RUNNER_TEMP/signing-key.asc"
    printf '%s' "$LINUX_GPG_PRIVATE_KEY" > "$KEY_FILE"
    {
      echo "compose.desktop.linux.sign=true"
      echo "compose.desktop.linux.signing.keyId=$LINUX_GPG_KEY_ID"
      echo "compose.desktop.linux.signing.keyFile=$KEY_FILE"
    } >> gradle.properties
```

<Accordion title="En coulisses">

- Chaque appel à `codesign` utilise `--options runtime --timestamp`. Le plugin signe de
  l'intérieur vers l'extérieur : bibliothèques natives, exécutables, bundle du runtime, puis le
  `.app`, sans `--deep`.
- Les builds non sandboxés reçoivent `allow-jit`, `allow-unsigned-executable-memory` et
  `disable-library-validation`. Voir [Sandboxing](/docs/packaging/sandboxing#configurer-les-entitlements-macos)
  pour le jeu App Store.
- La vérification du PKG Developer ID lance `pkgutil --check-signature`. Le plugin désactive la
  notarisation des PKG App Store par electron-builder.
- `keyFile` est importé dans un `GNUPGHOME` jetable. La signature RPM se trouve dans l'en-tête du
  paquet. La signature de dépôt (`Release.gpg`, `InRelease`) n'est pas couverte.
