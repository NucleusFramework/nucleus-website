Dans ce tutoriel, vous allez mettre en place un pipeline GitHub Actions qui construit, signe et
publie vos installateurs. Le dépôt [`NucleusFramework/Nucleus`](https://github.com/NucleusFramework/Nucleus)
fournit les actions composites : référencez-les sous la forme
`NucleusFramework/Nucleus/.github/actions/<name>@<ref>`, avec `<ref>` épinglé sur un tag de release
en production. Les installateurs ne se compilent pas en croisé : il vous faut un runner par OS et
par architecture.

## Construire sur chaque plateforme

```yaml title=".github/workflows/release.yaml"
name: Release
on:
  push:
    tags: ['v*']

permissions:
  contents: write

jobs:
  build:
    strategy:
      fail-fast: false
      matrix:
        include:
          - { os: ubuntu-22.04,     arch: amd64 }
          - { os: ubuntu-22.04-arm, arch: arm64 }
          - { os: windows-latest,   arch: amd64 }
          - { os: windows-11-arm,   arch: arm64 }
          - { os: macos-latest,     arch: arm64 }
          - { os: macos-15-intel,   arch: amd64 }
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: NucleusFramework/Nucleus/.github/actions/setup-nucleus@main
        with:
          java-version: '25'
          flatpak: 'true'
          snap: 'true'
      - run: ./gradlew packageReleaseDistributionForCurrentOS --stacktrace --no-daemon
      - uses: actions/upload-artifact@v4
        with:
          name: release-assets-${{ runner.os }}-${{ matrix.arch }}
          path: build/compose/binaries/**/*
```

Les jobs suivants retrouvent les artefacts par leur nom `release-assets-<os>-<arch>` : gardez cette
convention. `setup-nucleus` installe un JDK, les outils d'empaquetage Linux et Gradle :

| Entrée | Défaut | Rôle |
|--------|--------|------|
| `java-version` | `25` | JDK qui exécute Gradle et que jpackage embarque. |
| `packaging-tools` | `true` | Installer les outils d'empaquetage Linux. |
| `flatpak` / `snap` | `false` | Installer Flatpak (Freedesktop 24.08) ou Snapcraft. |
| `graalvm` | `false` | Préparer un build native-image : Xcode 26 sur macOS, MSVC sur Windows. |
| `graalvm-version` | `25i4` | Gardez-la égale à `graalvm { toolchain { version } }`. |
| `node-version` | `22` | Gardez-la égale à `nodejs { version }`. |

<Callout type="warn" title="Modifié en 3.0">
`setup-nucleus` ne lance plus `actions/setup-node`, et l'entrée `setup-node` disparaît. Retirez
`actions/setup-node` de vos jobs et mettez `~/.gradle/nucleus/nodejs` en cache. Voir
[Migrer depuis 2.x](/docs/migrate/from-2.x).
</Callout>

## Signer les builds macOS

```yaml
- uses: NucleusFramework/Nucleus/.github/actions/setup-macos-signing@main
  id: signing
  with:
    certificate-base64: ${{ secrets.MAC_CERTIFICATES_P12 }}
    certificate-password: ${{ secrets.MAC_CERTIFICATES_PASSWORD }}
```

| Secret | Rôle |
|--------|------|
| `MAC_CERTIFICATES_P12`, `MAC_CERTIFICATES_PASSWORD` | Bundle `.p12` en base64 et son mot de passe. |
| `MAC_DEVELOPER_ID_APPLICATION` | Identité Developer ID Application (DMG, ZIP). |
| `MAC_APP_STORE_APPLICATION`, `MAC_APP_STORE_INSTALLER` | Identités 3rd Party Mac Developer (PKG App Store). |
| `MAC_PROVISIONING_PROFILE`, `MAC_RUNTIME_PROVISIONING_PROFILE` | Profils en base64 pour l'application et le runtime JVM. |
| `MAC_NOTARIZATION_APPLE_ID`, `MAC_NOTARIZATION_PASSWORD`, `MAC_NOTARIZATION_TEAM_ID` | Identifiants `notarytool`. |

Sans les secrets `MAC_*`, le pipeline signe en ad hoc. Voir
[Signature du code](/docs/packaging/code-signing#gérer-les-secrets-de-signature-en-ci).

## Fusionner le binaire macOS universel

`build-macos-universal` fusionne les builds arm64 et x64 et réempaquette un ZIP, un DMG et un PKG
universels signés. Récupérez d'abord le dépôt Nucleus, à la ref qui correspond à votre version du
plugin :

```yaml
- uses: actions/checkout@v4
  with:
    repository: NucleusFramework/Nucleus
    ref: main
    path: nucleus
    sparse-checkout: plugin-build/plugin/src/main/resources/nucleus/electron-builder
- uses: NucleusFramework/Nucleus/.github/actions/build-macos-universal@main
  with:
    arm64-path: artifacts/release-assets-macOS-arm64
    x64-path: artifacts/release-assets-macOS-amd64
    output-path: artifacts/release-assets-macOS-universal
    signing-identity: ${{ secrets.MAC_DEVELOPER_ID_APPLICATION }}
    app-store-identity: ${{ secrets.MAC_APP_STORE_APPLICATION }}
    installer-identity: ${{ secrets.MAC_APP_STORE_INSTALLER }}
    keychain-path: ${{ steps.signing.outputs.keychain-path }}
    electron-builder-toolchain-dir: nucleus/plugin-build/plugin/src/main/resources/nucleus/electron-builder
```

Notarisez avec `xcrun notarytool submit --wait`. Agrafez le DMG et laissez le ZIP non agrafé, pour
que la block map de l'[updater](/docs/packaging/auto-update) reste valide. Sur un dépôt privé, les
minutes macOS comptent dix fois dans votre quota ; un runner macOS auto-hébergé évite ce coût.

## Regrouper Windows pour le Microsoft Store

```yaml
- uses: NucleusFramework/Nucleus/.github/actions/build-windows-appxbundle@main
  with:
    amd64-path: artifacts/release-assets-Windows-amd64
    arm64-path: artifacts/release-assets-Windows-arm64
    output-path: artifacts/release-assets-Windows-bundle
```

## Publier la release

`generate-update-yml` écrit `<canal>-mac.yml`, `<canal>.yml` et `<canal>-linux.yml`.
`publish-release` crée la GitHub Release et envoie le tout :

```yaml
- uses: NucleusFramework/Nucleus/.github/actions/generate-update-yml@main
  with:
    artifacts-path: artifacts
    version: ${{ env.VERSION }}
    channel: ${{ env.CHANNEL }} # latest, beta ou alpha
- uses: NucleusFramework/Nucleus/.github/actions/publish-release@main
  with:
    artifacts-path: artifacts
    tag: ${{ env.TAG }}
    release-type: ${{ env.RELEASE_TYPE }} # release, draft ou prerelease
```

Le workflow de référence [`release-desktop.yaml`](https://github.com/NucleusFramework/Nucleus/blob/main/.github/workflows/release-desktop.yaml)
assemble tous ces jobs. Il déduit la version et le canal du tag avec `release-tag-info`, et
`validate-release-ref` refuse un tag `-alpha`, `-beta` ou `-rc` qui ne pointe pas vers un commit
d'une branche de release `nucleus-*`.

<Accordions>
<Accordion title="En coulisses">

- `setup-nucleus` installe le Microsoft Build of OpenJDK sur Windows et Temurin ailleurs. Sur Linux,
  il installe `rpm`, `fakeroot`, `libarchive-tools`, `patchelf`, les en-têtes GTK, GLib, D-Bus et
  X11, et démarre un affichage virtuel avec `xvfb`.
- Le plugin Nucleus télécharge lui-même Node.js et le JDK GraalVM ; `setup-nucleus` se contente de
  mettre `~/.gradle/nucleus/nodejs` et `~/.gradle/nucleus/graalvm` en cache.
- `build-macos-universal` lance `lipo` sur chaque fichier Mach-O, re-signe de l'intérieur vers
  l'extérieur et exécute electron-builder hors de Gradle, installé avec `npm ci` depuis
  `electron-builder-toolchain-dir`.

</Accordion>
