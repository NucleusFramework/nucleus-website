Each OS has a `signing { }` block in `nativeDistributions`. You need an Apple Developer account on
macOS, a `.pfx`/`.p12` certificate or an Azure Artifact Signing account on Windows, and a GPG key
on Linux.

## Sign and notarize on macOS

```kotlin title="build.gradle.kts"
macOS {
    signing {
        sign.set(true)
        identity.set("Developer ID Application: My Company (TEAMID)")
        // keychain.set("/path/to/signing.keychain-db")
    }
    notarization {
        appleID.set("dev@example.com")
        password.set(System.getenv("MAC_NOTARIZATION_PASSWORD"))
        teamID.set("TEAMID")
    }
}
```

The plugin picks the certificate type per format from that one identity:

| Format | App signature | Installer signature | Notarized |
|--------|---------------|---------------------|-----------|
| DMG, ZIP | Developer ID Application | None | Yes |
| Developer ID PKG (`pkg { appStore = false }`) | Developer ID Application | Developer ID Installer | Yes |
| App Store PKG (default) | 3rd Party Mac Developer Application | 3rd Party Mac Developer Installer | No |

A Developer ID PKG build fails when the keychain lacks a Developer ID Installer certificate for the
same team.

### Choose a notarization mode

Configure one mode only; the build rejects a mix. Without credentials, the notarization tasks skip.

```kotlin
notarization {
    // 1. Apple ID with an app-specific password
    appleID.set("dev@example.com"); password.set(System.getenv("MAC_NOTARIZATION_PASSWORD")); teamID.set("TEAMID")
    // 2. notarytool keychain profile, stored with `xcrun notarytool store-credentials AC_PASSWORD`
    keychainProfile.set("AC_PASSWORD") // keychainPath optional
    // 3. App Store Connect API key, the usual choice in CI
    apiKey.set("/path/to/AuthKey_ABC123.p8"); apiKeyId.set("ABC123"); apiIssuer.set("12345678-90ab-cdef-1234-567890abcdef")
}
```

A universal build must re-sign after `lipo`. The `build-macos-universal` action does it; see
[CI/CD](/docs/packaging/ci-cd#merge-the-universal-macos-binary).

## Sign on Windows

```kotlin title="build.gradle.kts"
windows {
    signing {
        enabled = true
        certificateFile.set(file(System.getenv("WIN_CSC_LINK") ?: "certs/certificate.pfx"))
        certificatePassword = System.getenv("WIN_CSC_KEY_PASSWORD")
        algorithm = SigningAlgorithm.Sha256 // default; also Sha1, Sha512
        timestampServer = "http://timestamp.digicert.com"
    }
}
```

To use a certificate from the Windows store, set `certificateSha1` or `certificateSubjectName`
instead of `certificateFile`. For a cloud HSM, use Azure Artifact Signing:

```kotlin title="build.gradle.kts"
windows {
    signing {
        enabled = true
        publisherName = "My Publisher"
        azureTenantId = System.getenv("AZURE_TENANT_ID")
        azureEndpoint = "https://eastus.codesigning.azure.net"
        azureCertificateProfileName = "my-profile"
        azureCodeSigningAccountName = "my-account"
    }
}
```

Renew a PFX before it expires: SmartScreen flags a binary with an expired signature until you apply
a fresh, timestamped one.

## Sign on Linux

A GPG signature lets users who download your `.deb` or `.rpm` outside a repository verify its
origin. Signing stays off until `enabled` is `true` and `keyId` is set.

```kotlin title="build.gradle.kts"
linux {
    signing {
        enabled.set(true)
        keyId.set("AB12CD34EF56")   // from gpg --list-secret-keys --keyid-format=long
        // passphrase.set(System.getenv("LINUX_GPG_PASSPHRASE"))
        debMethod = DebSignMethod.Detached // default
        silentUpdate.set(true)      // passwordless self-update
    }
}
```

The build reads the key from your keyring, or from `keyFile` in CI. Each package gets a
`.pub.asc` public key, and DEB also a detached `.deb.asc`; publish them next to the packages. Users
verify with `gpg --verify <pkg>.deb.asc <pkg>.deb` or `rpm -K <pkg>.rpm` after importing the key.

`debMethod` also accepts `DpkgSig` (needs `dpkg-sig` on the build host) and `Debsig` (clients
verify with `debsig-verify`). `Detached` needs only `gpg`. For `silentUpdate`, see
[passwordless updates](/docs/packaging/auto-update#set-up-passwordless-updates-on-linux).

## Configure all platforms in one block

`nativeDistributions.signing { }` writes to the same per-OS blocks, so you can mix both styles:

```kotlin title="build.gradle.kts"
nativeDistributions {
    signing {
        macOS   { sign.set(true); identity.set("Developer ID Application: My Company (TEAMID)") }
        windows { enabled = true; certificateFile.set(file("certs/certificate.pfx")) }
        linux   { enabled.set(true); keyId.set("AB12CD34EF56") }
    }
}
```

## Manage signing secrets in CI

Keep certificates and keys out of the repository. On macOS, the `setup-macos-signing` action
imports a base64 `.p12` into a temporary keychain; see [CI/CD](/docs/packaging/ci-cd#sign-macos-builds).
macOS and Linux settings also read Gradle properties, which you pass with `-P` or `gradle.properties`:

| Setting | Gradle property |
|---------|-----------------|
| `macOS.signing.*` | `compose.desktop.mac.sign`, `compose.desktop.mac.signing.{identity,keychain,prefix}` |
| `macOS.notarization.*` | `compose.desktop.mac.notarization.{appleID,password,teamID,keychainProfile,keychainPath,apiKey,apiKeyId,apiIssuer}` |
| `linux.signing.*` | `compose.desktop.linux.sign`, `compose.desktop.linux.signing.{keyId,keyFile,passphrase,silentUpdate}` |

For Linux, store `gpg --armor --export-secret-keys <keyId>` as a secret, then write it to a file:

```yaml title=".github/workflows/release.yaml"
- name: Configure Linux GPG signing
  if: runner.os == 'Linux'
  shell: bash
  env:
    LINUX_GPG_PRIVATE_KEY: ${{ secrets.LINUX_GPG_PRIVATE_KEY }}
    LINUX_GPG_KEY_ID: ${{ secrets.LINUX_GPG_KEY_ID }}
  run: |
    [ -z "$LINUX_GPG_PRIVATE_KEY" ] && exit 0
    KEY_FILE="$RUNNER_TEMP/signing-key.asc"
    printf '%s' "$LINUX_GPG_PRIVATE_KEY" > "$KEY_FILE"
    {
      echo "compose.desktop.linux.sign=true"
      echo "compose.desktop.linux.signing.keyId=$LINUX_GPG_KEY_ID"
      echo "compose.desktop.linux.signing.keyFile=$KEY_FILE"
    } >> gradle.properties
```

<Accordion title="Under the hood">

- Every `codesign` call uses `--options runtime --timestamp`. The plugin signs inside-out: native
  libraries, executables, the runtime bundle, then the `.app`, without `--deep`.
- Non-sandboxed builds get `allow-jit`, `allow-unsigned-executable-memory`, and
  `disable-library-validation`. See [Sandboxing](/docs/packaging/sandboxing#configure-macos-entitlements)
  for the App Store set.
- The Developer ID PKG check runs `pkgutil --check-signature`. The plugin turns off
  electron-builder's notarization of App Store PKGs.
- `keyFile` is imported into a throwaway `GNUPGHOME`. RPM signatures live in the package header.
  Repository signing (`Release.gpg`, `InRelease`) is out of scope.

</Accordion>
