`updater-runtime` vérifie, télécharge, contrôle et installe les mises à jour depuis Kotlin. Le build
écrit des métadonnées `latest-*.yml` à côté de vos installateurs, au format d'electron-builder ;
vous choisissez leur emplacement dans [Publication](/docs/packaging/publishing).

## Ajouter la dépendance

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.updater-runtime:<version>")
}
```

## Vérifier et installer une mise à jour

```kotlin
val updater = NucleusUpdater {
    provider = GitHubProvider(owner = "myorg", repo = "myapp")
}

when (val result = updater.checkForUpdates()) {
    is UpdateResult.Available -> {
        var installer: File? = null
        updater.downloadUpdate(result.info).collect { progress ->
            println("${progress.percent.toInt()}%")
            progress.file?.let { installer = it }
        }
        // Installe la mise à jour et relance l'application sur la nouvelle version
        installer?.let(updater::installAndRestart)
    }
    UpdateResult.NotAvailable -> println("Up to date")
    is UpdateResult.Error -> println("Error: ${result.exception.message}")
}
```

`checkForUpdates()` est une fonction `suspend`. En exécution de développement (`currentVersion`
vaut `0.0.0-dev`), elle renvoie `NotAvailable`. Les métadonnées de build ne comptent jamais :
`1.2.3+42` se compare comme `1.2.3`.

## Lire les mises à jour depuis GitHub Releases

`GitHubProvider` lit les releases d'un dépôt public par les routes web de GitHub, qui ne demandent
ni token ni quota de l'API REST. Pour un dépôt privé ou un GitHub Enterprise Server, utilisez
`PrivateGitHubProvider`, qui passe par l'API REST avec un token :

```kotlin
// Dépôt public, sur github.com ou un GitHub Enterprise Server
provider = GitHubProvider(owner = "myorg", repo = "myapp", host = "github.example.com")

// Dépôt privé
provider = PrivateGitHubProvider(
    owner = "myorg",
    repo = "myapp",
    token = "github_pat_...", // lecture du contenu du dépôt uniquement : il est livré dans l'application
)
```

Le quota du token, 5 000 requêtes par heure, est partagé par toutes les installations. Une
vérification coûte une requête, un téléchargement une par fichier. Les deux providers acceptent
`host` (défaut `github.com`) et `protocol` (défaut `https` ; `http` seulement pour un hôte
loopback). Chaque fichier provient de la release dont le manifeste a été lu : les tags n'ont pas
besoin du préfixe `v`.

<Callout type="warn" title="Modifié en 3.0">
`GitHubProvider` ne prend plus de token. `GitHubProvider(owner, repo, token)` ne compile plus :
passez les dépôts privés à `PrivateGitHubProvider(owner, repo, token)`, et nommez l'argument `host`.
</Callout>

### Choisir un canal de release

Le tag fixe le canal d'une release : `v1.0.0` est une release, `v1.0.0-beta.1` est `beta`,
`v1.0.0-alpha.1` est `alpha`. Le canal du client est `channel`, ou, pour `channel = "latest"`,
l'identifiant de pré-release de `currentVersion`.

| Canal du client | Suit |
|---|---|
| `alpha` | `alpha`, `beta` et les releases |
| `beta` | `beta` et les releases |
| Tout autre nom | Ses propres tags uniquement |

Parmi les tags qu'il suit, le client prend la version la plus haute, puis lit le manifeste de ce
canal (`beta.yml` pour `v1.1.0-beta.4`), ou `latest*.yml` quand la release ne le publie pas.
`channel = "beta"` active à lui seul les pré-releases. Les noms de canal respectent la casse, et
les tags qui ne sont pas des versions SemVer sont ignorés. Pour trouver une pré-release,
`GitHubProvider` lit les 10 releases les plus récentes et `PrivateGitHubProvider` les 100 plus
récentes : un canal sans tag parmi elles reste introuvable.

## Formats pris en charge

| Plateforme | Mise à jour intégrée | Gérée par le store (`NotAvailable`) |
|------------|----------------------|--------------------|
| macOS | DMG, ZIP, PKG Developer ID | PKG App Store |
| Windows | NSIS, NSIS Web, Exe, MSI | AppX/MSIX |
| Linux | DEB, RPM, AppImage | Snap, Flatpak |

<Callout type="warn" title="Livrez un ZIP sur macOS">
L'updater remplace le `.app` à partir du ZIP de la release, et se rabat sur le DMG. Ajoutez
`TargetFormat.Zip` à côté de `TargetFormat.Dmg` ou `TargetFormat.Pkg` pour que `latest-mac.yml` le
référence.
</Callout>

## Mettre à jour sans fermer l'application sous Windows

Sur une installation NSIS par utilisateur, `installAndRestart` installe la nouvelle version
pendant que l'application tourne, la démarre, puis ferme l'ancienne dès que la nouvelle fenêtre
est à l'écran. L'utilisateur ne voit jamais l'application disparaître. Si l'installation échoue,
l'application reste sur sa version actuelle. Une application construite sur `nucleusApplication`
n'a aucun code à ajouter.

- Une application sans fenêtre Nucleus (uniquement dans la zone de notification, par exemple)
  appelle `UpdateHandoff.signalReady()` dès qu'elle est utilisable. Sinon, l'ancienne version
  quitte après un délai.
- `installAndRestart(file, relaunchArguments)` démarre la nouvelle version avec les arguments que
  vous passez, par exemple le document ouvert dans cette instance. Nucleus ne rejoue pas la ligne
  de commande d'origine.
- Quand plusieurs instances tournent, les autres apprennent la mise à jour installée via
  `updater.pendingRestartVersion`, sans rien télécharger. Proposez une action « Redémarrer pour
  mettre à jour » et appelez `restartToInstalledVersion(relaunchArguments)`.

Les installations par machine, le MSI, les builds portables et les images natives GraalVM gardent
la mise à jour classique : l'application se ferme, l'installateur tourne, l'application se relance.

<Callout type="warn" title="Modifié en 3.0">
Les installations NSIS gardent désormais le launcher à la racine et placent le runtime et
l'application dans `versions\<version>\`. Le code qui construit des chemins relatifs au répertoire
d'installation doit suivre cette nouvelle disposition. Voir [Migrer depuis 2.x](/docs/migrate/from-2.x).
</Callout>

## Téléchargements différentiels

`downloadUpdate` ne récupère que les blocs modifiés, et se rabat sur un téléchargement complet
quand il ne peut pas. Un AppImage est différentiel dès sa première mise à jour, les autres formats
à partir de la deuxième. `progress.isDifferential` indique le type de téléchargement, et
`totalBytes` compte les octets transférés. Désactivez l'option si votre CDN ne sert pas les
requêtes range :

```kotlin
val updater = NucleusUpdater {
    provider = GitHubProvider(owner = "myorg", repo = "myapp")
    differentialDownload = false
}
```

## Détection après mise à jour

Après `installAndRestart` ou `installAndQuit`, au lancement suivant, `wasJustUpdated()` renvoie
`true` et `consumeUpdateEvent()` renvoie un `UpdateEvent(previousVersion, newVersion, updateLevel)`
pour un écran « Nouveautés ».

## Configurer les réseaux d'entreprise

Derrière un proxy avec une autorité racine privée, le `HttpClient` du JDK échoue à la poignée de
main TLS. Ajoutez `dev.nucleusframework:nucleus.native-http` et passez un `NativeHttpClient`, qui
fait confiance au magasin de certificats de l'OS :

```kotlin
val updater = NucleusUpdater {
    provider = GitHubProvider(owner = "myorg", repo = "myapp")
    httpClient = NativeHttpClient.create()
}
```

Voir aussi [Certificats d'autorité de confiance](/docs/packaging/trusted-certificates).

## Mettre en place les mises à jour sans mot de passe sur Linux

Une mise à jour DEB ou RPM passe par `pkexec`, qui demande un mot de passe. Avec des
[paquets signés](/docs/packaging/code-signing#signer-sur-linux), l'application s'en passe :

```kotlin title="build.gradle.kts"
linux {
    signing {
        enabled.set(true)
        keyId.set("AB12CD34EF56")
        silentUpdate.set(true) // exige enabled = true
    }
}
```

Il faut une session locale active. Si le helper ou la signature `.asc` manque, le runtime
journalise la raison et revient à la demande de mot de passe.

<Accordions>
<Accordion title="En coulisses">

- Les téléchargements différentiels comparent les block maps electron-builder à l'artefact
  précédent mis en cache dans `cacheDir` et récupèrent les blocs modifiés avec des requêtes HTTP
  range. Une map manquante, une requête range en échec ou un digest incorrect entraînent un
  téléchargement complet.
- L'updater calcule le hash d'un téléchargement complet pendant son écriture, puis compare le
  SHA-512 au manifeste. Sur Windows, il lance NSIS avec `/S` et MSI avec `msiexec /passive` après
  la fermeture de l'application.
- Le script de mise à jour DEB et RPM passe chaque chemin en littéral entre apostrophes, car le nom
  du package vient du manifeste.
- Les mises à jour Linux silencieuses passent par un helper appartenant à root,
  `/opt/<App>/nucleus-update-helper`, qui vérifie la signature `.asc` avec votre clé publique
  livrée avant de lancer `dpkg -i` ou `rpm -U`.

</Accordion>

## Référence de l'API

### Méthodes runtime

- `suspend fun checkForUpdates(): UpdateResult`
- `fun downloadUpdate(info: UpdateInfo): Flow<DownloadProgress>` : la dernière émission a `file != null`.
- `fun installAndRestart(installerFile: File, relaunchArguments: List<String> = emptyList())` : installe et relance sur la nouvelle version. Mise à jour à chaud sur les installations NSIS par utilisateur.
- `val pendingRestartVersion: StateFlow<String?>` : une version installée par une autre instance, ou `null`.
- `fun restartToInstalledVersion(relaunchArguments: List<String> = emptyList()): Boolean` : bascule sur cette version.
- `fun installAndQuit(installerFile: File)` : installe en silence et quitte sans relancer.
- `fun isUpdateSupported(): Boolean` : indique si l'installation courante peut se mettre à jour.
- `fun wasJustUpdated(): Boolean`, `fun consumeUpdateEvent(): UpdateEvent?`
- `val currentVersion: String`

### Types de résultat et de niveau

- `UpdateResult.Available(info: UpdateInfo, level: UpdateLevel)`, `UpdateResult.NotAvailable`,
  `UpdateResult.Error(exception: UpdateException)`
- `UpdateLevel` : `MAJOR`, `MINOR`, `PATCH` ou `PRE_RELEASE`. Servez-vous-en pour imposer une boîte
  de dialogue sur une version majeure et installer les correctifs en arrière-plan.
- Sous-types de `UpdateException` : `NetworkException`, `ChecksumException`,
  `NoMatchingFileException`, `ParseException`. `downloadUpdate` lève `ParseException` avant tout
  téléchargement quand le manifeste désigne un artefact qui n'est pas un simple nom de fichier, comme
  `../app.zip`.

### Champs du builder

| Champ | Défaut | Notes |
|-------|--------|-------|
| `currentVersion` | Détectée dans l'application empaquetée | Comparée à la version distante |
| `provider` | Obligatoire | `GitHubProvider`, `PrivateGitHubProvider` ou `GenericProvider` |
| `channel` | `"latest"` | `latest`, `beta`, `alpha` ou un canal à vous |
| `allowDowngrade` | `false` | |
| `allowPrerelease` | `false` | Considéré comme `true` si `currentVersion` contient `-` ou si `channel` n'est pas `latest` |
| `executableType` | Détecté | Impose le type d'artefact à télécharger |
| `httpClient` | Client JDK qui suit les redirections | `NativeHttpClient` pour les autorités privées |
| `differentialDownload` | `true` | |
| `cacheDir` | `%LOCALAPPDATA%/nucleus/updates/<appId>` sur Windows, `~/.cache/nucleus/updates/<appId>` ailleurs | Artefact précédent et block map |

### Providers

- `GitHubProvider(owner, repo, host = "github.com", protocol = "https")` : dépôts publics.
- `PrivateGitHubProvider(owner, repo, token, host = "github.com", protocol = "https")` : dépôts
  privés et GitHub Enterprise Server, via l'API REST.
- `GenericProvider(baseUrl)`. `baseUrl` doit utiliser `https`, sinon la construction lève
  `IllegalArgumentException`. `http` n'est accepté que pour les tests locaux sur un hôte loopback :
  `localhost`, un littéral IPv4 de `127.0.0.0/8` ou `[::1]`.
