Le plugin Gradle Nucleus construit les installateurs desktop à partir d'un seul bloc
`nativeDistributions { }`. Le DSL d'empaquetage est fourni avec le plugin : vous n'ajoutez aucune
dépendance.

## Déclarer les formats

```kotlin title="build.gradle.kts"
nucleus.application {
    mainClass = "com.example.MainKt"
    nativeDistributions {
        packageName = "MyApp"
        packageVersion = "1.0.0"
        targetFormats(TargetFormat.Dmg, TargetFormat.Nsis, TargetFormat.Deb, TargetFormat.AppImage)
    }
}
```

```shell
./gradlew packageDistributionForCurrentOS
```

La tâche construit chaque format que l'hôte prend en charge et ignore les autres : un même script
tourne sur les trois OS. Les fichiers arrivent dans `build/compose/binaries/main/<format>/`. Chaque
format a aussi sa tâche (`packageDmg`, `packageNsis`), et `packageReleaseDistributionForCurrentOS`
lance ProGuard avant.

## Formats pris en charge

| OS | Distribution directe | Store | Archives |
|----|----------------------|-------|----------|
| macOS | DMG, PKG (Developer ID) | PKG (Mac App Store) | ZIP, TAR, 7z |
| Windows | Exe, NSIS, NSIS Web, MSI, Portable | AppX (Microsoft Store) | ZIP, TAR, 7z |
| Linux | DEB, RPM, AppImage, Pacman | Snap, Flatpak | ZIP, TAR, 7z |

`TargetFormat.RawAppImage` construit l'image d'application brute, sans installateur. Les formats
pour store utilisent une [disposition sandboxée](/docs/packaging/sandboxing).

## Provisionner Node.js

Le plugin télécharge Node.js à la première utilisation et le met en cache dans
`~/.gradle/nucleus/nodejs`. Vous n'installez rien, et la CI n'a plus besoin de
`actions/setup-node`.

```kotlin title="build.gradle.kts"
nativeDistributions {
    nodejs {
        version = "22"        // défaut : une ligne majeure, "lts", ou une release précise comme "22.11.0"
        autoDownload = true   // false : utiliser node et npm du PATH
    }
}
```

La propriété Gradle `compose.electronBuilder.nodePath` et la variable d'environnement
`NUCLEUS_NODE_HOME` passent avant le téléchargement. Une version flottante reste sur la release
téléchargée la première fois : supprimez son répertoire de cache pour la mettre à jour.

## Bibliothèques natives à côté de l'application

Le plugin place les bibliothèques JNI des modules Nucleus à côté de l'application : l'application
empaquetée n'extrait rien au démarrage. Pour les fat JAR et l'IDE, voir
[Chargeur de bibliothèques natives](/docs/performance/native-library-loader).

<Callout type="warn" title="Modifié en 3.0">
Les applications empaquetées ne portent plus les bibliothèques JNI de Nucleus dans leurs JAR. Le
code qui les lisait comme ressources du classpath doit les charger via `NativeLibraryLoader`. Voir
[Migrer depuis la 2.x](/docs/migrate/from-2.x).
</Callout>

## Alléger l'image runtime

<Callout type="warn" title="Modifié en 3.0">
`stripJreFonts` vaut `true` par défaut : l'image runtime perd les polices du JRE, puisque Compose
dessine le texte avec les siennes. Une application qui dessine du texte avec AWT ou Swing doit
régler `stripJreFonts = false`. Voir [Migrer depuis la 2.x](/docs/migrate/from-2.x).
</Callout>

Avec `includeAllModules = true`, le plugin écarte `jdk.jlink`, que les JDK construits sans
`jmods/` (comme Temurin 24+) refusent de lier.
