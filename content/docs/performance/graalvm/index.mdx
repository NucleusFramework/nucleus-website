GraalVM Native Image compiles a Compose Desktop app into one binary that runs without a JVM. The
Nucleus plugin downloads GraalVM and generates the reflection metadata, so the source that builds
your JVM app also builds the native image.

```kotlin title="build.gradle.kts"
nucleus.application {
    mainClass = "com.example.MainKt"
    graalvm {
        isEnabled = true
        imageName = "myapp"
    }
}
```

Run it with `./gradlew runGraalvmNative`. See [Tasks and CI](/docs/performance/graalvm/tasks-ci)
for packaging.

## Know the limits

[Runtimes and performance](/docs/performance#compare-the-runtimes) helps you choose between a
native image and the JDK build. On the native side:

- **Closed world.** No `Class.forName` on values computed at run time, no custom class loaders,
  no scripting engines, no bytecode generation. Spring, Groovy, ByteBuddy mocking and heavy JNA
  use do not fit.
- **No JIT.** Sustained CPU-heavy work runs slower than on HotSpot. Oracle GraalVM's PGO closes
  most of the gap.
- **One build per OS.** You compile on each target OS, so a release needs a CI matrix.

Ktor, kotlinx.serialization, Coil, SQLite, Jewel, Compose and SLF4J work without extra
configuration. For a daemon or a CLI, see
[Build a headless image](/docs/performance/graalvm/configuration#build-a-headless-image).

## Requirements

| Platform | Required |
|----------|----------|
| **macOS** | Xcode Command Line Tools |
| **Windows** | MSVC (Visual Studio Build Tools) |
| **Linux** | GCC, `patchelf`, and `xvfb` for headless builds |

The plugin downloads GraalVM Community Edition (25.4 by default) on the first native build. CE is
GPLv2 with the Classpath Exception, so you can ship it inside a paid app. See
[Provision the toolchain](/docs/performance/graalvm/configuration#provision-the-toolchain) to pick
another version or Oracle GraalVM.

<Callout type="info">
If your `main()` does not go through `nucleusApplication`, add `nucleus.graalvm-runtime` and call
`GraalVmInitializer.initialize()` before any AWT or Compose code runs.
</Callout>
