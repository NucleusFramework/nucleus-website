Les tâches GraalVM reprennent le pipeline JVM, avec en plus une tâche d'empaquetage par format
d'installeur.

## Tâches Gradle

| Tâche | Équivalent JVM | Description |
|-------|----------------|-------------|
| `runGraalvmNative` | `run` | Boucle de développement : quick-build (`-Ob`) avec l'[accessibilité exacte](/docs/performance/graalvm/configuration#repérer-les-enregistrements-manquants-pendant-le-développement), puis lancement du binaire. |
| `createGraalvmNativeDistributable` | `createDistributable` | Construit le dossier d'application pour l'OS courant, sans installeur. |
| `runGraalvmNativeDistributable` | `runDistributable` | Compile avec l'optimisation configurée et lance le dossier d'application. |
| `packageGraalvmNativeDistributionForCurrentOS` | `packageDistributionForCurrentOS` | Empaquette tous les formats configurés pour l'OS courant. |

### Métadonnées, installeurs et utilitaires

| Tâche | Description |
|-------|-------------|
| `packageGraalvm<Format>` | Un installeur par format de `nativeDistributions.targetFormats`, nommé d'après la constante de l'enum : `TargetFormat.Deb` donne `packageGraalvmDeb`. |
| `runWithNativeAgent` | Lance l'application sous l'agent de traçage pour enregistrer les métadonnées. Voir [Métadonnées automatiques](/docs/performance/graalvm/automatic-metadata#combler-les-manques-avec-lagent-de-traçage). |
| `cleanupGraalvmMetadata` | Retire les entrées manuelles déjà couvertes par les métadonnées générées. |
| `runWithPgoInstrument` | Enregistre un profil PGO. Oracle GraalVM uniquement. |

Les installeurs n'exigent pas Node.js sur la machine de build : le plugin le télécharge. Voir
`nativeDistributions { nodejs { } }` dans la [référence du DSL Gradle](/docs/reference/gradle-dsl#nodejs).

<Callout type="warn">
`packageGraalvmDeb` échoue si `nativeDistributions { homepage }` n'est pas défini.
</Callout>

## Organisation de la sortie

Le dossier d'application arrive dans `build/compose/binaries/main/graalvm-app/` : un `<app>.app`
signé sous macOS, `<app>.exe` sous Windows, `<app>` sous Linux, avec les bibliothèques JNI de
Nucleus à côté de l'exécutable. Les installeurs arrivent dans
`build/compose/binaries/main/graalvm-<format>/`, par exemple `graalvm-dmg`.

## Compiler en CI avec GitHub Actions

Une image native ne se compile pas en croisé. Lancez une matrice sur les trois OS et préparez
chaque runner avec l'action `setup-nucleus` :

```yaml title=".github/workflows/graalvm-release.yml"
name: GraalVM release

on:
  push:
    tags: ["v*"]

jobs:
  graalvm:
    name: GraalVM - ${{ matrix.name }}
    runs-on: ${{ matrix.os }}
    timeout-minutes: 60
    strategy:
      fail-fast: false
      matrix:
        include:
          - { name: Linux x64,   os: ubuntu-latest,  task: packageGraalvmDeb }
          - { name: macOS ARM64, os: macos-latest,   task: packageGraalvmDmg }
          - { name: Windows x64, os: windows-latest, task: packageGraalvmNsis }

    steps:
      - uses: actions/checkout@v4

      - name: Set up Nucleus
        uses: NucleusFramework/Nucleus/.github/actions/setup-nucleus@main
        with:
          graalvm: 'true'
          setup-gradle: 'true'

      - name: Build the native package
        run: ./gradlew :myapp:${{ matrix.task }} --no-daemon

      - uses: actions/upload-artifact@v4
        with:
          name: graalvm-${{ runner.os }}
          path: myapp/build/compose/binaries/**/graalvm-*/**
```

- `graalvm: 'true'` installe l'outillage Xcode ou MSVC et met la toolchain GraalVM en cache.
  Alignez les entrées `graalvm-version` et `graalvm-distribution` (défauts `25i4`, `community`)
  sur votre bloc `toolchain { }` : ce sont des clés de cache.
- `setup-gradle: 'true'` met en cache les dépendances et sorties Gradle. L'étape `native-image`
  elle-même prend 5 à 15 minutes par plateforme.

<Callout type="info">
`setup-nucleus` n'installe plus Node.js, et l'entrée `setup-node` a disparu. `node-version` ne
sert plus qu'à la clé de cache et doit correspondre à `nodejs { version }`.
</Callout>

## Déboguer une réflexion manquante à l'exécution

Lancez le binaire depuis un terminal. Un enregistrement manquant se traduit par
`ClassNotFoundException`, `NoSuchFieldException` ou, sous `runGraalvmNative`,
`MissingReflectionRegistrationError`. Passez le chemin fautif sous `./gradlew runWithNativeAgent`,
puis recompilez.

<Accordions>
<Accordion title="En coulisses">

- `packageGraalvmNative` est l'assembleur interne derrière ces tâches : il compile l'image et
  dispose le binaire, les bibliothèques JNI, Skiko et AWT, les icônes et `appResources`.
- `filterGraalvmLibraryMetadata`, `resolveGraalvmReachabilityMetadata`,
  `generateGraalvmPlatformMetadata` et `analyzeGraalvmStaticMetadata` s'exécutent à chaque build
  natif.
- Le mode quick-build est une entrée de tâche : passer de `runGraalvmNative` aux tâches de
  distribution recompile.
- L'image se compile à partir d'une copie de l'uber JAR privée des bibliothèques JNI de Nucleus.
  `NativeLibraryLoader` les charge depuis le dossier de l'exécutable sans jamais les extraire. Voir
  [Chargeur de bibliothèques natives](/docs/performance/native-library-loader).
- Node.js arrive dans `<gradle-user-home>/nucleus/nodejs` pour electron-builder.

</Accordion>
