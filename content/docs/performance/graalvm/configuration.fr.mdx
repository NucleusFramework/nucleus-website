Le bloc `graalvm { }`, placé dans `nucleus.application { }`, configure les builds native-image.
Définissez `isEnabled = true` et le plugin fournit tout le reste :

```kotlin title="build.gradle.kts"
nucleus.application {
    mainClass = "com.example.MainKt"
    graalvm {
        isEnabled = true
        imageName = "myapp"
        optimization = NativeImageOptimization.SIZE // facultatif, -O2 par défaut
    }
}
```

## Construire une image headless

Pour un démon ou une CLI, définissez `headless = true`. L'image laisse de côté AWT, Java2D, Skiko
et Compose, et s'exécute avec `-Djava.awt.headless=true`. Gardez `false` pour toute application
dotée d'une fenêtre ou d'une icône de barre d'état.

## Fournir la toolchain

Le plugin télécharge **GraalVM Community Edition** dans `<gradle-user-home>/nucleus/graalvm` à la
première tâche native-image. Un `GRAALVM_HOME` qui correspond à la distribution demandée l'emporte.

```kotlin title="build.gradle.kts"
graalvm {
    toolchain {
        distribution = GraalvmDistribution.COMMUNITY // défaut, ou ORACLE
        channel = GraalvmChannel.INNOVATION          // défaut 25i4 ; LTS donne 25
        // version = "25.0.1"                        // remplace channel
    }
}
```

- `autoDownload = false` passe plutôt par les toolchains Gradle (`javaLanguageVersion`,
  `jvmVendor`). Utilisez-le, ou `GRAALVM_HOME`, pour Liberica NIK ou Mandrel.
- Les Mac Intel reçoivent BellSoft Liberica NIK 25.0.x (`macosIntelFallback`) : GraalVM ne publie
  plus pour macOS Intel après 25.0.1.
- Les versions flottantes (`"25"`, `"25i4"`) restent figées une fois téléchargées. Supprimez leur
  dossier sous `installDir` pour les mettre à jour.

### Revenir à GraalVM 25.3

Si un build régresse avec le `25i4` par défaut, définissez `toolchain { version = "25i3" }`.

### Choisir une distribution

Oracle GraalVM ajoute la Profile-Guided Optimization, `-O3`, les profils inférés par ML,
`advancedObfuscation` et le collecteur G1. Sur Community Edition, le build les ignore avec un
avertissement.

## Choisir un garbage collector

Une image native fixe son collecteur à la compilation. Serial, le défaut, convient aux tas d'une
application de bureau. Passez à G1 au-delà de 1 à 2 Go de tas environ.

```kotlin title="build.gradle.kts"
nucleus.application {
    garbageCollector = GarbageCollector.Z                  // distribution JVM et tâche run
    graalvm {
        garbageCollector = NativeImageGarbageCollector.G1  // inscrit dans l'image
    }
}
```

| `NativeImageGarbageCollector` | Disponibilité |
|-------------------------------|---------------|
| `SERIAL` | Toutes les toolchains. Le défaut. |
| `G1` | Oracle GraalVM uniquement. Linux depuis 25.0 ; Windows et macOS depuis 25.4. Ailleurs, repli sur Serial avec un avertissement. |
| `EPSILON` | Ne libère jamais la mémoire. Réservé aux benchmarks et aux processus courts. |

Un `-XX:+Use…GC` explicite dans `jvmArgs` l'emporte sur le `garbageCollector` côté JVM. Le
[pack de démarrage](/docs/performance/startup) active aussi le
[GC au repos](/docs/performance/startup#gc-au-repos) dans l'image native.

## Repérer les enregistrements manquants pendant le développement

`runGraalvmNative` s'exécute avec `--exact-reachability-metadata` pour les packages de
`exactReachabilityMetadata`. Une recherche non enregistrée y lève
`MissingReflectionRegistrationError` en nommant l'élément manquant. Les tâches de distribution et
d'empaquetage ne reçoivent jamais l'option.

```kotlin title="build.gradle.kts"
graalvm {
    exactReachabilityMetadata = ExactReachabilityMetadata.APP_PACKAGES // défaut : package de mainClass
    // ExactReachabilityMetadata.packages("com.example", "com.example.shared")
    // ExactReachabilityMetadata.OFF
}
```

Passez `-Pnucleus.graalvm.missingRegistration=warn|exit|throw` (défaut `warn`) pour lister tous
les enregistrements manquants en une exécution.

## Définir les arguments de build

Les `buildArgs` partent tels quels vers `native-image` et l'emportent sur les propriétés typées.
Réservez-les aux options sans propriété, comme `-H:-IncludeMethodData` (plusieurs Mo gagnés).
Nucleus initialise SLF4J à l'exécution ; pour le passer à la compilation avec un backend fixe,
ajoutez `buildArgs.add("--initialize-at-build-time=org.slf4j")`.

## Optimiser avec un profil PGO

La Profile-Guided Optimization exige Oracle GraalVM.

1. Lancez `./gradlew runWithPgoInstrument`, parcourez les chemins chauds, puis quittez. Le profil
   est écrit dans `pgo { profile }` (défaut `graalvm/pgo/default.iprof`).
2. Committez le fichier `.iprof`. Les builds complets et les tâches d'empaquetage l'appliquent ;
   `runGraalvmNative` non.

Passez `-Pnucleus.graalvm.pgo=off` pour un build sans profil, ou définissez `pgo { enabled = false }`.

## Configurer le dépôt de métadonnées

```kotlin title="build.gradle.kts"
graalvm {
    metadataRepository {
        // enabled = true, version = "1.1.4" par défaut
        moduleToConfigVersion.put("io.ktor:ktor-client-core", "3.0.0")
        excludedModules.add("com.example:noisy-lib")
    }
}
```

## Configurer macOS et Windows

- `macOS { minimumSystemVersion }` vaut `"12.0"` par défaut. `macOsSdkVersion` vaut `"26.0"` ;
  Liquid Glass exige le SDK 26. `cStubsSrc` lie des stubs C supplémentaires.
- Sous Windows, le plugin copie `vcruntime140.dll`, `vcruntime140_1.dll` et `msvcp140.dll` à côté
  du `.exe` : l'application se passe du Visual C++ Redistributable. Réglez-le avec
  `windows { bundleCRuntime; dlls; sourceDir }`.

## Pas de variante release

Il n'existe pas de `packageReleaseGraalvmNative`. `native-image` élimine déjà le code mort, et
ProGuard pourrait renommer des classes que les métadonnées référencent. Utilisez
`NativeImageOptimization.SIZE` pour réduire l'image.

<Accordions>
<Accordion title="En coulisses">

- Un build headless ignore les métadonnées de plateforme et les packs graphiques (`jdk-awt`,
  `jdk-fonts`, `jdk-graphics2d`, Skiko, Compose, tray, lecteur multimédia, webview) et ne copie
  aucune bibliothèque graphique.
- Les dossiers d'installation portent le nom de la distribution (`graalvm-community-jdk-*`,
  `graalvm-jdk-*`). Un `GRAALVM_HOME` de l'autre distribution est ignoré avec un avertissement.
- Le plugin lit `GRAALVM_VERSION` dans le fichier `release` de la toolchain pour décider de G1.
  GraalVM 25.3 échoue à lier G1 sous Windows et macOS (`g1gc-cr.lib`).
- `maxHeapSizePercent` devient `-R:MaximumHeapSizePercent` (Serial, Epsilon) ou
  `-R:MaxRAMPercentage` (G1).
- Avant le JDK 23, l'accessibilité exacte se rabat sur `-H:ThrowMissingRegistrationErrors=` ou
  est ignorée.
- Sous Linux et macOS, le plugin retire les symboles de l'exécutable, ce qui fait gagner des
  dizaines de Mo.

</Accordion>

## Référence de graalvm { }

| Propriété | Défaut | Notes |
|-----------|--------|-------|
| `isEnabled` | `false` | Interrupteur principal. |
| `headless` | `false` | Voir [Construire une image headless](#construire-une-image-headless). |
| `imageName` | nom du package | Nom du binaire produit. |
| `march` | selon la plateforme | `NATIVE` cible le CPU de build, `COMPATIBILITY` les CPU plus anciens. Non défini : `COMPATIBILITY`, sauf `NATIVE` sur Apple Silicon. |
| `optimization` | `-O2` | `QUICK_BUILD` (`-Ob`), `NONE`, `LEVEL_1`, `LEVEL_2`, `LEVEL_3` (Oracle), `SIZE` (`-Os`). |
| `allCharsets` | `false` | Ajoute `-H:+AddAllCharsets`. Encodages anciens uniquement. |
| `mlProfileInference` | `true` | `false` ajoute `-H:-MLProfileInference`. Oracle uniquement. |
| `advancedObfuscation` | `false` | Ajoute `-H:AdvancedObfuscation=`. Oracle uniquement. |
| `autoIncludeResources` | `true` | Embarque les ressources du projet et de ses dépendances `project(...)`. |
| `maxHeapSizePercent` | `25` | Tas maximal par défaut en pourcentage de la RAM. |
| `maxHeapSize` | non défini | Tas maximal absolu (`"2g"`). Prioritaire sur le pourcentage. |
| `garbageCollector` | Serial | Voir [Choisir un garbage collector](#choisir-un-garbage-collector). |
| `exactReachabilityMetadata` | `APP_PACKAGES` | `runGraalvmNative` uniquement. Voir [plus haut](#repérer-les-enregistrements-manquants-pendant-le-développement). |
| `detectOrphanProjectClasses` | `true` | Voir [Métadonnées automatiques](/docs/performance/graalvm/automatic-metadata#détecter-les-classes-orphelines-du-projet). |
| `reflectionForProjectClasses` | `false` | Enregistre toutes les classes du projet dotées d'un constructeur public sans argument. Alourdit l'image. |
| `buildArgs` | vide | Ajoutés tels quels. |
| `javaLanguageVersion`, `jvmVendor` | `25`, non défini | Avec `toolchain { autoDownload = false }` uniquement. |
| `nativeImageConfigBaseDir` | non défini | Dossier de votre propre `reachability-metadata.json`. |
| `toolchain { }` | téléchargement auto | Voir [Fournir la toolchain](#fournir-la-toolchain). |
| `pgo { }` | activé | Voir [Optimiser avec un profil PGO](#optimiser-avec-un-profil-pgo). |
| `metadataRepository { }` | activé | Voir [Configurer le dépôt de métadonnées](#configurer-le-dépôt-de-métadonnées). |
| `macOS { }`, `windows { }` | | Voir [Configurer macOS et Windows](#configurer-macos-et-windows). |
