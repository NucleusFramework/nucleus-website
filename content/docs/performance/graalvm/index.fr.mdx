GraalVM Native Image compile une application Compose Desktop en un binaire qui s'exécute sans
JVM. Le plugin Nucleus télécharge GraalVM et génère les métadonnées de réflexion : le code qui
produit votre application JVM produit aussi l'image native.

```kotlin title="build.gradle.kts"
nucleus.application {
    mainClass = "com.example.MainKt"
    graalvm {
        isEnabled = true
        imageName = "myapp"
    }
}
```

Lancez-la avec `./gradlew runGraalvmNative`. Pour l'empaquetage, voir
[Tâches et CI](/docs/performance/graalvm/tasks-ci).

## Connaître les limites

[Runtimes et performance](/docs/performance#comparer-les-runtimes) vous aide à choisir entre
l'image native et l'image JDK. Côté natif :

- **Monde fermé.** Pas de `Class.forName` sur des valeurs calculées à l'exécution, pas de class
  loaders personnalisés, pas de moteurs de script, pas de génération de bytecode. Spring, Groovy,
  les mocks ByteBuddy et un usage intensif de JNA ne conviennent pas.
- **Pas de JIT.** Un calcul lourd et soutenu tourne moins vite que sur HotSpot. La PGO d'Oracle
  GraalVM comble l'essentiel de l'écart.
- **Un build par OS.** Vous compilez sur chaque OS cible : une release demande une matrice CI.

Ktor, kotlinx.serialization, Coil, SQLite, Jewel, Compose et SLF4J fonctionnent sans
configuration supplémentaire. Pour un démon ou une CLI, voir
[Construire une image headless](/docs/performance/graalvm/configuration#construire-une-image-headless).

## Prérequis

| Plateforme | Requis |
|------------|--------|
| **macOS** | Xcode Command Line Tools |
| **Windows** | MSVC (Visual Studio Build Tools) |
| **Linux** | GCC, `patchelf`, et `xvfb` pour les builds headless |

Le plugin télécharge GraalVM Community Edition (25.4 par défaut) au premier build natif. CE est
sous GPLv2 avec la Classpath Exception : vous pouvez l'embarquer dans une application payante.
Pour choisir une autre version ou Oracle GraalVM, voir
[Fournir la toolchain](/docs/performance/graalvm/configuration#fournir-la-toolchain).

<Callout type="info">
Si votre `main()` ne passe pas par `nucleusApplication`, ajoutez `nucleus.graalvm-runtime` et
appelez `GraalVmInitializer.initialize()` avant tout code AWT ou Compose.
</Callout>
