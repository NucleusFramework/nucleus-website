The GraalVM tasks mirror the JVM pipeline, plus one packaging task per installer format.

## Gradle tasks

| Task | JVM counterpart | Description |
|------|-----------------|-------------|
| `runGraalvmNative` | `run` | Dev loop: quick-build (`-Ob`) with [exact reachability](/docs/performance/graalvm/configuration#catch-missing-registrations-in-the-dev-loop), then runs the binary. |
| `createGraalvmNativeDistributable` | `createDistributable` | Builds the app folder for the current OS, without an installer. |
| `runGraalvmNativeDistributable` | `runDistributable` | Builds with the configured optimization and runs the app folder. |
| `packageGraalvmNativeDistributionForCurrentOS` | `packageDistributionForCurrentOS` | Packages every configured format for the current OS. |

### Metadata, installers and helpers

| Task | Description |
|------|-------------|
| `packageGraalvm<Format>` | One installer per format in `nativeDistributions.targetFormats`, named after the enum constant: `TargetFormat.Deb` gives `packageGraalvmDeb`. |
| `runWithNativeAgent` | Runs the app under the tracing agent to record metadata. See [Automatic metadata](/docs/performance/graalvm/automatic-metadata#fill-gaps-with-the-tracing-agent). |
| `cleanupGraalvmMetadata` | Removes manual entries the generated metadata already covers. |
| `runWithPgoInstrument` | Records a PGO profile. Oracle GraalVM only. |

Installers need no Node.js on the build machine: the plugin downloads it. See
`nativeDistributions { nodejs { } }` in the [Gradle DSL reference](/docs/reference/gradle-dsl#nodejs).

<Callout type="warn">
`packageGraalvmDeb` fails unless `nativeDistributions { homepage }` is set.
</Callout>

## Output layout

The app folder lands in `build/compose/binaries/main/graalvm-app/`: a signed `<app>.app` on macOS,
`<app>.exe` on Windows, `<app>` on Linux, with the Nucleus JNI libraries next to the executable.
Installers land in `build/compose/binaries/main/graalvm-<format>/`, for example `graalvm-dmg`.

## Build in CI with GitHub Actions

You cannot cross-compile a native image. Run a matrix over the three OSes and set up each runner
with the `setup-nucleus` action:

```yaml title=".github/workflows/graalvm-release.yml"
name: GraalVM release

on:
  push:
    tags: ["v*"]

jobs:
  graalvm:
    name: GraalVM - ${{ matrix.name }}
    runs-on: ${{ matrix.os }}
    timeout-minutes: 60
    strategy:
      fail-fast: false
      matrix:
        include:
          - { name: Linux x64,   os: ubuntu-latest,  task: packageGraalvmDeb }
          - { name: macOS ARM64, os: macos-latest,   task: packageGraalvmDmg }
          - { name: Windows x64, os: windows-latest, task: packageGraalvmNsis }

    steps:
      - uses: actions/checkout@v4

      - name: Set up Nucleus
        uses: NucleusFramework/Nucleus/.github/actions/setup-nucleus@main
        with:
          graalvm: 'true'
          setup-gradle: 'true'

      - name: Build the native package
        run: ./gradlew :myapp:${{ matrix.task }} --no-daemon

      - uses: actions/upload-artifact@v4
        with:
          name: graalvm-${{ runner.os }}
          path: myapp/build/compose/binaries/**/graalvm-*/**
```

- `graalvm: 'true'` installs Xcode tooling or MSVC and caches the GraalVM toolchain. Keep the
  `graalvm-version` and `graalvm-distribution` inputs (defaults `25i4`, `community`) in line with
  your `toolchain { }` block: they are cache keys.
- `setup-gradle: 'true'` caches Gradle dependencies and outputs. The `native-image` step itself
  takes 5 to 15 minutes per platform.

<Callout type="info">
`setup-nucleus` no longer installs Node.js, and the `setup-node` input is gone. `node-version` only
feeds the cache key and should match `nodejs { version }`.
</Callout>

## Debug missing reflection at run time

Run the binary from a terminal. A missing registration shows up as `ClassNotFoundException`,
`NoSuchFieldException` or, under `runGraalvmNative`, `MissingReflectionRegistrationError`. Run
`./gradlew runWithNativeAgent` through the failing path, then rebuild.

<Accordion title="Under the hood">

- `packageGraalvmNative` is the internal assembler behind these tasks: it compiles the image and
  lays out the binary, JNI, Skiko and AWT libraries, icons and `appResources`.
- `filterGraalvmLibraryMetadata`, `resolveGraalvmReachabilityMetadata`,
  `generateGraalvmPlatformMetadata` and `analyzeGraalvmStaticMetadata` run on every native build.
- The quick-build mode is a task input, so switching between `runGraalvmNative` and the
  distributable tasks recompiles.
- The image compiles from a copy of the uber JAR without the Nucleus JNI libraries.
  `NativeLibraryLoader` loads them from next to the executable and never extracts them. See
  [Native library loader](/docs/performance/native-library-loader).
- Node.js lands in `<gradle-user-home>/nucleus/nodejs` for electron-builder.
