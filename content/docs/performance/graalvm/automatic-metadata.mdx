The Nucleus plugin generates the reflection, resource and JNI metadata that `native-image` needs,
so a native build works without a hand-written `reachability-metadata.json`. It covers Compose,
Ktor, kotlinx.serialization, SQLite, Coil and the JDK, your other dependencies through the
[GraalVM Reachability Metadata Repository](https://github.com/oracle/graalvm-reachability-metadata),
and the literal `Class.forName()`, `getResource()` and native calls in your own code.

## Detect orphan project classes

Room `*_Impl`, Dagger `*_Factory` and Moshi adapters are loaded by name, so no bytecode references
them. The plugin registers such a class when it is public, has a public no-arg constructor, and
your code references one of its supertypes. The build log prints `[orphan] <fqcn>` for each.

`detectOrphanProjectClasses` is on by default. `reflectionForProjectClasses = true` registers every
project class with a public no-arg constructor; use it only to unblock a build, since it grows the
image.

## Fill gaps with the tracing agent

Reflection driven by run-time values escapes the build-time analysis. Run the agent once before a
release and walk through every screen:

```shell
./gradlew runWithNativeAgent
```

The agent merges new entries into your `reachability-metadata.json` and keeps the ones you edited.
Commit that file. To keep it in another folder, set `graalvm { nativeImageConfigBaseDir }`. To spot
gaps earlier, see
[Catch missing registrations](/docs/performance/graalvm/configuration#catch-missing-registrations-in-the-dev-loop).

## Clean up manual entries

```shell
./gradlew cleanupGraalvmMetadata
# Also remove entries whose types are on no classpath
./gradlew cleanupGraalvmMetadata -Pnucleus.graalvm.cleanup.removeUnresolvable=true
# Report without rewriting the file
./gradlew cleanupGraalvmMetadata -Pnucleus.graalvm.cleanup.dryRun=true
```

The task removes the entries the generated metadata already covers and lists what it kept. A
`kept` entry is covered by nothing else, so check it.

<Accordion title="Under the hood">

The plugin merges five sources, each passed through its own `-H:ConfigurationFileDirectories=`:

1. 29 metadata files in the plugin JAR, kept when their `matchPackages` are on the classpath
   (`filterGraalvmLibraryMetadata`). Headless builds drop the GUI packs.
2. The Reachability Metadata Repository, version `1.1.4` (`resolveGraalvmReachabilityMetadata`).
3. Platform metadata for `sun.awt.windows.*`, `sun.lwawt.macosx.*` or `sun.awt.X11.*`, Java2D,
   font managers, security providers and `main` (`generateGraalvmPlatformMetadata`).
4. A bytecode scan of the runtime classpath (`analyzeGraalvmStaticMetadata`). It also catches
   `MethodHandles.Lookup.findClass()`, JNI callbacks and `@Serializable` companions. The orphan
   detector reads the app's JVM target folders, such as `desktopMainClasses`.
5. Metadata inside `nucleus.graalvm-runtime`: resource globs (`**/*.svg`, `**/*.ttf`,
   `composeResources/**`, `META-INF/services/**`, …), `-H:+SharedArenaSupport`, and AWT font and
   splash-screen substitutions.

`cleanupGraalvmMetadata` compares your file with sources 1 to 4. It always drops the Kotlin
phantoms the agent records (`kotlin.Any`, `FunctionN`, …) and never drops types under the
`exactReachabilityMetadata` packages.
