The Nucleus plugin can generate a [Project Leyden](https://openjdk.org/projects/leyden/) AOT cache
during a training run of your app and ship it in every installer. At launch the JVM reuses the
recorded class loading and profiles, so the first window appears sooner. The runtime API comes
with `nucleus-application`.

## Enable the cache

```kotlin title="build.gradle.kts"
nucleus.application {
    mainClass = "com.example.MainKt"
    nativeDistributions {
        enableAotCache = true
    }
}
```

<Callout type="error" title="JDK 25 or later">
AOT cache generation needs JDK 25 or later as the packaging JDK. An older JDK fails the build.
</Callout>

The plugin runs the app in training mode after `createDistributable`, then ships `app.aot` in every
installer and wires it into the launcher.

## Write a training run

The JVM writes the cache when the training process exits, so your app must exit on its own, with
code 0, within 300 s. After that the plugin kills it. Inside `nucleusApplication`, arm the exit timer with
`aotTraining`:

```kotlin
fun main(args: Array<String>) = nucleusApplication(args) {
    // No-op outside training. Calls exitApplication() after 45 seconds.
    aotTraining(duration = 45.seconds)

    if (isAotTraining) {
        // Each screen the run touches adds profiled methods to the cache
        preloadNavigationScreens()
        preloadFontsAndImages()
    }

    DecoratedWindow(onCloseRequest = ::exitApplication, title = "MyApp") {
        App()
    }
}
```

Walk through the screens a real session opens: more coverage gives a shorter cold start.

Without `nucleusApplication`, check `AotRuntime.isTraining()` and call `exitProcess(0)` yourself
once the run is done.

## Pin the platform and JDK

A cache only loads on the platform and JDK build that produced it. Build on each target platform,
typically in a CI matrix, and release a fresh cache with each app version. The plugin trains with
the JDK it bundles, including OpenJDK 27 when
[`lastJdk`](/docs/performance/startup#package-with-the-latest-jdk) is on.

### Choose a compatibility profile

Set `nativeDistributions { aotCache { compatibility } }`:

| `AotCacheCompatibility` | Behavior |
|-------------------------|----------|
| `COMPATIBILITY` | No cached machine code. Runs on any CPU of the architecture. The default. |
| `NATIVE` | Keeps machine code for the build CPU, for a small startup gain. A user CPU with fewer instruction-set extensions crashes with `SIGILL` or `EXCEPTION_ILLEGAL_INSTRUCTION`. JDK 27 checks this at load time; the plugin warns below 27. |

To measure the gain, time a build with `enableAotCache = false` against one with it on, same JDK,
from process spawn to the first frame.

<Accordions>
<Accordion title="Under the hood">

- The training run records into `app.aot` with `-XX:AOTCacheOutput`. The launcher gets
  `-XX:AOTCache=$APPDIR/app.aot`.
- The plugin sets `-Dnucleus.aot.mode=training` for the training run. The shipped launcher sets
  nothing, so a packaged app reports `OFF` unless you add `-Dnucleus.aot.mode=runtime` to
  `jvmArgs`.
- On Linux without `DISPLAY`, the plugin starts Xvfb for the training run.

</Accordion>
</Accordions>

## API reference

| Gradle property | Default | Notes |
|-----------------|---------|-------|
| `nativeDistributions.enableAotCache` | `false` | Shorthand for `aotCache { enabled }`. |
| `aotCache.enabled` | `false` | Trains, bundles, and wires the cache into the launcher. |
| `aotCache.compatibility` | `COMPATIBILITY` | See [Choose a compatibility profile](#choose-a-compatibility-profile). |
| `aotCache.extraTrainingJvmArgs` | empty | Extra JVM arguments for the training run only. |

| Kotlin API | Notes |
|------------|-------|
| `AotRuntime.mode()` / `aotMode` | `AotRuntimeMode.OFF`, `TRAINING` or `RUNTIME` |
| `AotRuntime.isTraining()` / `isAotTraining` | `true` during a training run |
| `AotRuntime.isRuntime()` / `isAotRuntime` | `true` when `nucleus.aot.mode` is `runtime` |
| `aotTraining(duration, onTimeout)` | Exit timer, `nucleusApplication` scope. Defaults: 15 s, `exitApplication()`. Only the first call arms it. |

`AotRuntime` lives in `dev.nucleusframework.aot.runtime`.
