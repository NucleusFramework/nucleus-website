Les modules HTTP natifs font qu'un client HTTP accorde sa confiance au magasin de certificats du
système via [`NativeTrustManager`](/docs/performance/native-ssl). Les appels HTTPS vers des hôtes
signés par une racine d'entreprise, un profil MDM ou un proxy d'inspection SSL aboutissent alors.

## Ajouter la dépendance

Choisissez l'adaptateur de votre client. Chacun apporte `native-ssl` avec lui.

| Artefact | Client |
|----------|--------|
| `dev.nucleusframework:nucleus.native-http` | `java.net.http.HttpClient` |
| `dev.nucleusframework:nucleus.native-http-okhttp` | OkHttp 5 |
| `dev.nucleusframework:nucleus.native-http-ktor` | Client Ktor 3, avec le moteur que vous déclarez |

## Utiliser le HttpClient du JDK

`NativeHttpClient.create()` renvoie un `HttpClient` qui fait confiance au magasin de l'OS et suit
les redirections. Pour garder votre propre builder, appelez `withNativeSsl()` dessus, avant tout
`sslParameters(...)` de votre part :

```kotlin
import dev.nucleusframework.nativehttp.NativeHttpClient
import dev.nucleusframework.nativehttp.NativeHttpClient.withNativeSsl

val client = NativeHttpClient.create()

val custom = HttpClient.newBuilder()
    .withNativeSsl()
    .followRedirects(HttpClient.Redirect.NORMAL)
    .build()
```

<Callout type="warn">
`withNativeSsl()` n'active pas les redirections. Sans `followRedirects(...)`, un hôte qui répond
302 renvoie la réponse 302 à votre code.
</Callout>

## Utiliser OkHttp

Utilisez `NativeOkHttpClient.create()`, ou appelez `withNativeSsl()` sur votre propre
`OkHttpClient.Builder` (import `dev.nucleusframework.nativehttp.okhttp.NativeOkHttpClient.withNativeSsl`).

## Utiliser Ktor

`native-http-ktor` n'embarque aucun moteur. Déclarez-en un parmi CIO, Java, OkHttp ou Apache5 :

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.native-http-ktor:<version>")
    implementation("io.ktor:ktor-client-cio:<ktor-version>")
}
```

```kotlin
import dev.nucleusframework.nativehttp.ktor.installNativeSsl

val client = HttpClient(CIO) {
    installNativeSsl()
}
```

Avec un autre moteur, `installNativeSsl()` ne change rien.

<Accordions>
<Accordion title="En coulisses">

- Chaque adaptateur ne remplace que le matériel de confiance. Le pooling, HTTP/2, les intercepteurs
  et les timeouts restent tels que vous les configurez.
- `withNativeSsl()` sur le builder du JDK définit `sslContext(NativeTrustManager.sslContext)` et
  remplace les `SSLParameters` par un jeu qui ne demande pas de certificat client.
- Sur OkHttp, il appelle `sslSocketFactory(NativeTrustManager.sslSocketFactory, NativeTrustManager.trustManager)`.
- `installNativeSsl()` règle `https { trustManager }` sur CIO, `sslContext` sur Java et Apache5,
  et `sslSocketFactory` sur OkHttp.

</Accordion>
</Accordions>

## Référence de l'API

| API | Renvoie |
|-----|---------|
| `NativeHttpClient.create()` | `HttpClient` avec la confiance native et `Redirect.NORMAL` |
| `HttpClient.Builder.withNativeSsl()` | Le builder, avec la confiance native |
| `NativeOkHttpClient.create()` | `OkHttpClient` avec la confiance native |
| `OkHttpClient.Builder.withNativeSsl()` | Le builder, avec la confiance native |
| `HttpClientConfig<T>.installNativeSsl()` | `Unit` ; configure le moteur Ktor |
