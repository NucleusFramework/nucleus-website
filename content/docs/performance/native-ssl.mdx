`native-ssl` reads the root certificates the operating system trusts on macOS, Windows and Linux,
merges them with the JVM defaults, and exposes the result as one `X509TrustManager`. HTTPS
handshakes to hosts signed by an enterprise root, an MDM profile or a TLS-inspection proxy then
succeed.

## Add the dependency

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.native-ssl:<version>")
}
```

<Callout type="tip">
For `java.net.http`, OkHttp or Ktor, add a [Native HTTP](/docs/performance/native-http) adapter
instead. It wires `native-ssl` into the client.
</Callout>

## Get a trust manager

Read the property your TLS stack expects:

```kotlin
import dev.nucleusframework.nativessl.NativeTrustManager

val trustManager: X509TrustManager = NativeTrustManager.trustManager
val sslContext: SSLContext = NativeTrustManager.sslContext
val sslSocketFactory: SSLSocketFactory = NativeTrustManager.sslSocketFactory
```

The first read builds the trust manager and caches it for the life of the process. Certificates
added to the OS store after that stay invisible until the app restarts. You cannot plug in a
custom certificate source.

## ProGuard

The default ProGuard rules of the Nucleus plugin cover this module. If you replace them with your
own, keep the two bridges:

```proguard
-keep class dev.nucleusframework.nativessl.mac.NativeSslBridge {
    native <methods>;
}
-keep class dev.nucleusframework.nativessl.windows.WindowsSslBridge {
    native <methods>;
}
```

## Logging

The module logs certificate counts and sources at `FINE` under the `dev.nucleusframework.nativessl`
logger. Set that logger to `FINE`, or set `allowNucleusRuntimeLogging = true`
(`dev.nucleusframework.core.runtime.tools`) from `main()`.

<Accordions>
<Accordion title="Under the hood">

- The trust manager loads the JVM default issuers and the OS certificates into an in-memory
  `KeyStore`. When the OS reports none, `trustManager` is the JVM default.
- macOS and Windows read the store through the `nucleus_ssl` JNI library. If it fails to load,
  macOS contributes nothing, and Windows falls back to the `SunMSCAPI` keystores
  (`Windows-ROOT`, `Windows-CA`, `Windows-MY`).
- **macOS:** system anchors plus the user and admin trust-settings domains, filtered with the
  rules of [JetBrains jvm-native-trusted-roots](https://github.com/JetBrains/jvm-native-trusted-roots)
  (self-signed `TrustRoot` entries, SSL policy only, unknown constraints rejected).
- **Windows:** the `ROOT` and `CA` stores of `CURRENT_USER`, `LOCAL_MACHINE`, both Group Policy
  locations and `LOCAL_MACHINE_ENTERPRISE`, which covers Active Directory deployments that
  `SunMSCAPI` misses. `ROOT` entries are kept as is; `CA` entries must pass chain validation.
  Duplicates are removed by SHA-1 thumbprint.
- **Linux:** every readable PEM bundle or directory from the list Go's `crypto/x509` uses, such as
  `/etc/ssl/certs/ca-certificates.crt` (Debian, Ubuntu), `/etc/pki/tls/certs/ca-bundle.crt`
  (Fedora) and `/etc/ssl/cert.pem` (Alpine), deduplicated by DER content. No native library.

</Accordion>
</Accordions>

## API reference

| Property | Value |
|----------|-------|
| `trustManager: X509TrustManager` | JVM default roots plus the OS roots |
| `sslContext: SSLContext` | A `TLS` context initialized with `trustManager` |
| `sslSocketFactory: SSLSocketFactory` | `sslContext.socketFactory` |
