Le plugin Nucleus peut générer un cache AOT [Project Leyden](https://openjdk.org/projects/leyden/)
pendant une exécution d'entraînement de votre application, et le livrer dans chaque installeur. Au
lancement, la JVM réutilise le chargement de classes et les profils enregistrés : la première
fenêtre apparaît plus tôt. L'API d'exécution est fournie avec `nucleus-application`.

## Activer le cache

```kotlin title="build.gradle.kts"
nucleus.application {
    mainClass = "com.example.MainKt"
    nativeDistributions {
        enableAotCache = true
    }
}
```

<Callout type="error" title="JDK 25 ou plus récent">
La génération du cache AOT exige un JDK 25 ou plus récent comme JDK d'empaquetage. Un JDK plus
ancien fait échouer le build.
</Callout>

Le plugin lance l'application en mode entraînement après `createDistributable`, puis livre
`app.aot` dans chaque installeur et le branche au lanceur.

## Écrire une exécution d'entraînement

La JVM écrit le cache quand le processus d'entraînement se termine : votre application doit donc
quitter d'elle-même, avec le code 0, en moins de 300 s. Au-delà, le plugin la tue. Dans
`nucleusApplication`, armez le minuteur de sortie avec `aotTraining` :

```kotlin
fun main(args: Array<String>) = nucleusApplication(args) {
    // Sans effet hors entraînement. Appelle exitApplication() après 45 secondes.
    aotTraining(duration = 45.seconds)

    if (isAotTraining) {
        // Chaque écran parcouru ajoute des méthodes profilées au cache
        preloadNavigationScreens()
        preloadFontsAndImages()
    }

    DecoratedWindow(onCloseRequest = ::exitApplication, title = "MyApp") {
        App()
    }
}
```

Parcourez les écrans qu'ouvre une vraie session : plus la couverture est large, plus le démarrage
à froid est court.

Sans `nucleusApplication`, testez `AotRuntime.isTraining()` et appelez vous-même
`exitProcess(0)` à la fin de l'exécution.

## Figer la plateforme et le JDK

Un cache ne se charge que sur la plateforme et le build de JDK qui l'ont produit. Compilez sur
chaque plateforme cible, en général dans une matrice CI, et publiez un nouveau cache à chaque
version de l'application. Le plugin entraîne avec le JDK qu'il embarque, y compris OpenJDK 27 quand
[`lastJdk`](/docs/performance/startup#empaqueter-avec-le-dernier-jdk) est actif.

### Choisir un profil de compatibilité

Définissez `nativeDistributions { aotCache { compatibility } }` :

| `AotCacheCompatibility` | Comportement |
|-------------------------|--------------|
| `COMPATIBILITY` | Aucun code machine en cache. Fonctionne sur tout CPU de l'architecture. Le défaut. |
| `NATIVE` | Conserve le code machine du CPU de build, pour un léger gain au démarrage. Un CPU utilisateur doté de moins d'extensions de jeu d'instructions plante avec `SIGILL` ou `EXCEPTION_ILLEGAL_INSTRUCTION`. Le JDK 27 le vérifie au chargement ; le plugin avertit en dessous de 27. |

Pour mesurer le gain, chronométrez un build avec `enableAotCache = false` et un build avec
l'option, sur le même JDK, du lancement du processus à la première image affichée.

<Accordions>
<Accordion title="En coulisses">

- L'exécution d'entraînement enregistre dans `app.aot` avec `-XX:AOTCacheOutput`. Le lanceur
  reçoit `-XX:AOTCache=$APPDIR/app.aot`.
- Le plugin définit `-Dnucleus.aot.mode=training` pour l'entraînement. Le lanceur livré ne définit
  rien : une application empaquetée renvoie `OFF`, sauf si vous ajoutez
  `-Dnucleus.aot.mode=runtime` à `jvmArgs`.
- Sous Linux sans `DISPLAY`, le plugin démarre Xvfb pour l'entraînement.

</Accordion>
</Accordions>

## Référence de l'API

| Propriété Gradle | Défaut | Notes |
|------------------|--------|-------|
| `nativeDistributions.enableAotCache` | `false` | Raccourci pour `aotCache { enabled }`. |
| `aotCache.enabled` | `false` | Entraîne, embarque et branche le cache au lanceur. |
| `aotCache.compatibility` | `COMPATIBILITY` | Voir [Choisir un profil de compatibilité](#choisir-un-profil-de-compatibilité). |
| `aotCache.extraTrainingJvmArgs` | vide | Arguments JVM supplémentaires pour l'entraînement uniquement. |

| API Kotlin | Notes |
|------------|-------|
| `AotRuntime.mode()` / `aotMode` | `AotRuntimeMode.OFF`, `TRAINING` ou `RUNTIME` |
| `AotRuntime.isTraining()` / `isAotTraining` | `true` pendant un entraînement |
| `AotRuntime.isRuntime()` / `isAotRuntime` | `true` quand `nucleus.aot.mode` vaut `runtime` |
| `aotTraining(duration, onTimeout)` | Minuteur de sortie, portée `nucleusApplication`. Défauts : 15 s, `exitApplication()`. Seul le premier appel l'arme. |

`AotRuntime` se trouve dans `dev.nucleusframework.aot.runtime`.
