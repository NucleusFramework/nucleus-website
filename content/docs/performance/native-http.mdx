The native HTTP modules make an HTTP client trust the operating system certificate store through
[`NativeTrustManager`](/docs/performance/native-ssl). HTTPS calls to hosts signed by a corporate
root, an MDM profile or an SSL-inspection proxy then succeed.

## Add the dependency

Pick the adapter for your client. Each one brings `native-ssl` with it.

| Artifact | Client |
|----------|--------|
| `dev.nucleusframework:nucleus.native-http` | `java.net.http.HttpClient` |
| `dev.nucleusframework:nucleus.native-http-okhttp` | OkHttp 5 |
| `dev.nucleusframework:nucleus.native-http-ktor` | Ktor client 3, with the engine you declare |

## Use the JDK HttpClient

`NativeHttpClient.create()` returns an `HttpClient` that trusts the OS store and follows
redirects. To keep your own builder, call `withNativeSsl()` on it, before any `sslParameters(...)`
of your own:

```kotlin
import dev.nucleusframework.nativehttp.NativeHttpClient
import dev.nucleusframework.nativehttp.NativeHttpClient.withNativeSsl

val client = NativeHttpClient.create()

val custom = HttpClient.newBuilder()
    .withNativeSsl()
    .followRedirects(HttpClient.Redirect.NORMAL)
    .build()
```

<Callout type="warn">
`withNativeSsl()` does not turn on redirects. Without `followRedirects(...)`, a host that answers
302 returns the 302 response to your code.
</Callout>

## Use OkHttp

Use `NativeOkHttpClient.create()`, or call `withNativeSsl()` on your own `OkHttpClient.Builder`
(import `dev.nucleusframework.nativehttp.okhttp.NativeOkHttpClient.withNativeSsl`).

## Use Ktor

`native-http-ktor` ships no engine. Declare one of CIO, Java, OkHttp or Apache5:

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.native-http-ktor:<version>")
    implementation("io.ktor:ktor-client-cio:<ktor-version>")
}
```

```kotlin
import dev.nucleusframework.nativehttp.ktor.installNativeSsl

val client = HttpClient(CIO) {
    installNativeSsl()
}
```

With any other engine, `installNativeSsl()` changes nothing.

<Accordions>
<Accordion title="Under the hood">

- Each adapter swaps only the trust material. Pooling, HTTP/2, interceptors and timeouts stay as
  you configure them.
- `withNativeSsl()` on the JDK builder sets `sslContext(NativeTrustManager.sslContext)` and
  replaces the `SSLParameters` with a set that does not request a client certificate.
- On OkHttp it calls `sslSocketFactory(NativeTrustManager.sslSocketFactory, NativeTrustManager.trustManager)`.
- `installNativeSsl()` sets `https { trustManager }` on CIO, `sslContext` on Java and Apache5,
  and `sslSocketFactory` on OkHttp.

</Accordion>
</Accordions>

## API reference

| API | Returns |
|-----|---------|
| `NativeHttpClient.create()` | `HttpClient` with native trust and `Redirect.NORMAL` |
| `HttpClient.Builder.withNativeSsl()` | The builder, with native trust |
| `NativeOkHttpClient.create()` | `OkHttpClient` with native trust |
| `OkHttpClient.Builder.withNativeSsl()` | The builder, with native trust |
| `HttpClientConfig<T>.installNativeSsl()` | `Unit`; configures the Ktor engine |
