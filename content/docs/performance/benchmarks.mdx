The [`benchmark-demo`](https://github.com/NucleusFramework/Nucleus/tree/main/examples/benchmark-demo)
example runs one suite inside a Compose desktop app: 13 CPU kernels, three rendering ramps and a
list-load test. The same kernels are ported to SwiftUI, Tauri and Flutter. Every variant ran on an
Apple M4 on 2026-07-16.

<Callout type="info">
Higher is better for CPU and GFX; lower is better for list, peak RAM and app size. Composite
scores compare only within this suite.
</Callout>

## Read the results

- **CPU.** GraalVM JIT scores highest (146.7). Tauri (142), SwiftUI (139) and OpenJDK C2 (138 to
  140) sit close together. GraalVM Native reaches that group only with PGO (100.8 to 132.7).
- **PGO.** `aot-o3-pgo` reaches 132.7 CPU with 269 MB of peak RAM, against 616 to 695 MB for the
  JVM variants. The cost is the PGO workflow: an instrumented build, a GUI run, then a rebuild.
  The profile also shrinks the image from 174 MB to 129 MB.
- **RAM.** Flutter uses the least (196 MB), then SwiftUI (268) and GraalVM Native (269 to 326).
  The JVM variants use 616 to 695 MB, and Tauri 794 MB (†).
- **List load.** GraalVM Native takes about 17 ms, the JVM about 21 ms, SwiftUI 14 ms and Tauri
  233 ms.
- **Flutter** has the lowest CPU score (57.3) but one of the highest GFX scores (15133).

## Reproduce

```shell title="terminal"
cd examples/benchmark-demo

# JVM and native matrix
JAVA_HOME=<jbr-21> GRAALVM_HOME=<graalvm-25> JDK_C2_HOME=<jdk-26> \
  ONLY="jvm-c2 jvm-c2-pg jvm-graal aot-os aot-o2 aot-o3 aot-o3-pgo" ./run-all.sh

# Ports
ONLY="swiftui tauri flutter" ./run-all.sh
```

Run the native builds with `JAVA_HOME` pointing at GraalVM, or Gradle may pick a cached Oracle
JDK 25 without `native-image` and the compile fails. Each variant writes a result JSON, and the
example's `RESULTS.md` holds the full per-variant appendix.

<Accordions>
<Accordion title="Under the hood">

- **Setup:** Apple M4, 10 cores, on AC power. Oracle GraalVM 25.1.3+9.1 (Java 25.0.3), OpenJDK
  26.0.1, Gradle daemon on JBR 21.
- **Protocol:** 3 discarded warmups, then the best of 5 over the CPU kernels. Variants run one at
  a time in one session, peak RSS is sampled during each run, and every self-check passes.
- **Tauri (†):** the Tauri process alone has a 177 MB RSS. The 794 MB sums the WebKit processes
  (`WebContent`, `GPU`, `Networking`) and counts shared `WebKit.framework` pages more than once.
  Its list goes through the DOM and a canvas.
- **Kernels:** without PGO, `matmul` drops to 3877 MFLOP/s against 12225 with it. Graal does well
  on `blur` and `sieve`, less well on `fft` and `sha256`, and PGO regresses `mandelbrot` (1.98
  against 3.32).
- **Reproduce:** Gradle picks the wrong JDK because a cached Oracle JDK 25 matches the
  `vendor=ORACLE`, `version=25` toolchain spec.

</Accordion>
</Accordions>
