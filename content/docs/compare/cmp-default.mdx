Nucleus extends the `org.jetbrains.compose` plugin. The Compose UI runtime, Skia rendering, Compose
Hot Reload, `compose.desktop.currentOs` and the Gradle tasks stay the same, and
`compose.desktop.application { }` becomes `nucleus.application { }`.

## What Nucleus replaces

Nucleus opens native windows and never creates an AWT window. Your composables run unchanged, but
the entry point, windows, dialogs, tray and `SwingPanel` change, and native callbacks run on the
host UI thread instead of the AWT event dispatch thread. The migration guide
[maps each AWT API](/docs/migrate/from-jb-compose#replace-the-entry-point-and-windows) to its
replacement.

## What Nucleus adds

| Area | Vanilla CMP | Nucleus |
| --- | --- | --- |
| Formats | DMG, PKG, MSI, EXE, DEB, RPM, raw app image | Those, plus NSIS, NSIS Web, AppX, Portable, AppImage, Pacman, Snap, Flatpak, ZIP, TAR, 7Z: 18 in total |
| Stores | | Mac App Store PKG, AppX and Flatpak through a [sandboxed pipeline](/docs/packaging/sandboxing), plus a Developer ID PKG |
| Auto-update | None | Differential updates from electron-builder `latest-*.yml` metadata. See [Auto-update](/docs/packaging/auto-update) |
| Runtime | JVM | [GraalVM native image](/docs/performance/graalvm), or JVM with the JDK 25+ [AOT cache](/docs/performance/aot-cache) (`enableAotCache = true`) |
| Code signing | | Windows PFX or Azure Artifact Signing, and universal macOS binaries through the `build-macos-universal` action |
| Deep links and file types | Per-OS configuration | `protocol(…)` and `fileAssociation(…)` reach NSIS, MSI, AppX, DEB, RPM and the macOS `Info.plist` |
| Installer options | | `splashImage`, `artifactName` template, `compressionLevel` |
| Runtime libraries | | `nucleusApplication` (single instance, deep links, GraalVM setup), decorated windows with macOS, Fluent, Yaru, Jewel and Material toolkits, and OS modules such as notifications, hotkeys, media controls and spell check |

DEB builds need `homepage`, where vanilla CMP did not:
[set it during the migration](/docs/migrate/from-jb-compose#move-the-build-to-the-nucleus-dsl).

Hello World on Windows 11:

| | Nucleus, GraalVM | Nucleus, JVM with AOT cache | Vanilla CMP |
| --- | --- | --- | --- |
| Cold start | ~0.2 s | ~1.0 s | 1 to 2 s |
| Installer size | ~40 MB | ~60 MB | 80 to 120 MB |

## Stay on vanilla CMP when

- DMG, MSI and DEB from jpackage cover your distribution.
- You don't need auto-update, GraalVM, store distribution, or native decorations.
- Your UI relies on `SwingPanel`, Swing components, or a library that needs an AWT window.
- Your pipeline already has signing and upload scripts you want to keep.

## Move to Nucleus when

- You ship to the Mac App Store, Microsoft Store, Snapcraft, or Flathub.
- You want auto-update or a GraalVM native image.
- You want native decorations, trackpad gestures, pen input, and native Wayland.
- You want OS integration modules without building them yourself.

<Accordion title="Under the hood">

- Vanilla Compose Desktop draws into a `ComposeWindow`, which is a `JFrame`.
- The plugin builds the app image with jpackage, then hands it to electron-builder's
  `--prepackaged` mode for the other formats. It downloads the Node.js electron-builder needs.
- The store pipeline signs each native library, adds sandbox-aware JVM arguments, and applies the
  entitlements.
- The native build uses about 30 MB of RAM. Installer sizes come from NSIS at maximum compression.
- `core-runtime` provides `NucleusApp`, `ExecutableRuntime`, and the deep-link and single-instance
  primitives.
