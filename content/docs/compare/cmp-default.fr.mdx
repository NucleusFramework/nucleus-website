Nucleus étend le plugin `org.jetbrains.compose`. Le runtime Compose UI, le rendu Skia, Compose Hot
Reload, `compose.desktop.currentOs` et les tâches Gradle ne changent pas, et
`compose.desktop.application { }` devient `nucleus.application { }`.

## Ce que Nucleus remplace

Nucleus ouvre des fenêtres natives et ne crée jamais de fenêtre AWT. Vos composables tournent sans
changement, mais le point d'entrée, les fenêtres, les dialogues, le tray et `SwingPanel` changent,
et les callbacks natifs s'exécutent sur le thread UI de l'hôte au lieu de l'EDT AWT. Le guide de
migration [associe chaque API AWT](/docs/migrate/from-jb-compose#remplacer-le-point-dentrée-et-les-fenêtres)
à son remplaçant.

## Ce que Nucleus ajoute

| Domaine | CMP seul | Nucleus |
| --- | --- | --- |
| Formats | DMG, PKG, MSI, EXE, DEB, RPM, image d'application brute | Ceux-là, plus NSIS, NSIS Web, AppX, Portable, AppImage, Pacman, Snap, Flatpak, ZIP, TAR, 7Z : 18 au total |
| Stores | | PKG Mac App Store, AppX et Flatpak via un [pipeline sandboxé](/docs/packaging/sandboxing), plus un PKG Developer ID |
| Mise à jour automatique | Aucune | Mises à jour différentielles depuis les métadonnées `latest-*.yml` d'electron-builder. Voir [Mise à jour automatique](/docs/packaging/auto-update) |
| Runtime | JVM | [Image native GraalVM](/docs/performance/graalvm), ou JVM avec le [cache AOT](/docs/performance/aot-cache) de JDK 25+ (`enableAotCache = true`) |
| Signature de code | | PFX ou Azure Artifact Signing sous Windows, et binaires macOS universels via l'action `build-macos-universal` |
| Liens profonds et types de fichiers | Configuration par OS | `protocol(…)` et `fileAssociation(…)` atteignent NSIS, MSI, AppX, DEB, RPM et l'`Info.plist` macOS |
| Options d'installateur | | `splashImage`, modèle `artifactName`, `compressionLevel` |
| Bibliothèques d'exécution | | `nucleusApplication` (instance unique, liens profonds, configuration GraalVM), fenêtres décorées avec les toolkits macOS, Fluent, Yaru, Jewel et Material, et modules OS comme les notifications, les raccourcis globaux, le contrôle média et le correcteur orthographique |

Les builds DEB exigent `homepage`, contrairement à CMP seul :
[renseignez-le pendant la migration](/docs/migrate/from-jb-compose#passer-le-build-au-dsl-nucleus).

Hello World sous Windows 11 :

| | Nucleus, GraalVM | Nucleus, JVM avec cache AOT | CMP seul |
| --- | --- | --- | --- |
| Démarrage à froid | ~0,2 s | ~1,0 s | 1 à 2 s |
| Taille de l'installateur | ~40 Mo | ~60 Mo | 80 à 120 Mo |

## Rester sur CMP seul si

- DMG, MSI et DEB produits par jpackage couvrent votre distribution.
- Vous n'avez besoin ni de mise à jour automatique, ni de GraalVM, ni de distribution store, ni de
  décorations natives.
- Votre interface repose sur `SwingPanel`, des composants Swing ou une bibliothèque qui exige une
  fenêtre AWT.
- Votre pipeline a déjà des scripts de signature et d'envoi que vous voulez garder.

## Passer à Nucleus si

- Vous publiez sur le Mac App Store, le Microsoft Store, Snapcraft ou Flathub.
- Vous voulez la mise à jour automatique ou une image native GraalVM.
- Vous voulez des décorations natives, les gestes du trackpad, le stylet et Wayland natif.
- Vous voulez des modules d'intégration OS sans les construire vous-même.

- Compose Desktop seul dessine dans une `ComposeWindow`, qui est un `JFrame`.
- Le plugin construit l'image d'application avec jpackage, puis la confie au mode `--prepackaged`
  d'electron-builder pour les autres formats. Il télécharge le Node.js dont electron-builder a
  besoin.
- Le pipeline store signe chaque bibliothèque native, ajoute des arguments JVM adaptés au sandbox
  et applique les entitlements.
- Le build natif utilise environ 30 Mo de RAM. Les tailles d'installateur viennent de NSIS en
  compression maximale.
- `core-runtime` fournit `NucleusApp`, `ExecutableRuntime` et les primitives de liens profonds et
  d'instance unique.
