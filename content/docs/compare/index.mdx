[Nucleus and vanilla Compose Multiplatform](/docs/compare/cmp-default) and
[Packaging compared](/docs/compare/packaging).

## Electron and Tauri

| | **Nucleus** | Electron | Tauri |
| --- | --- | --- | --- |
| Languages | Kotlin | JavaScript and Node (C++ for native modules) | JavaScript and Rust |
| UI | Compose, Skia on the GPU | Chromium | OS WebView |
| OS APIs | Kotlin modules, one process | Node native modules, IPC | Rust commands over IPC |
| Shared with mobile | The same Kotlin as Android and iOS | Web bundle | Web bundle |
| Packaging formats | 18 | 5 to 7 through electron-builder | 5 through tauri-bundler |
| Cold start | ~0.2 s (GraalVM) | 2 to 3 s | under 1 s |
| Idle RAM | 30 to 120 MB | 200 to 500 MB | ~87 MB |

Pick Electron when shipping speed and a JavaScript hiring pool outweigh memory use. Pick Tauri
when you accept platform WebViews and a Rust and JavaScript split for small binaries. Pick Nucleus
when your team writes Kotlin and wants Compose from the UI down to the installer.

### Measured startup, RAM, and process count

A Hello World window in each stack, timed from process launch to the first window.

| Windows 11 | Stack | Cold start | Warm start | RAM (private WS) | Processes |
| --- | --- | --- | --- | --- | --- |
| **Nucleus** | GraalVM native image | ~0.17 s | ~0.10 s | **~30 MB** | 1 |
| WinUI 3 | .NET 9 and Windows App SDK | ~0.20 s | ~0.28 s | ~32 MB | 1 |
| Flutter | Dart AOT and Skia | ~0.28 s | ~0.28 s | ~33 MB | 1 |
| Tauri | Rust and WebView2 | ~0.74 s | ~0.12 s | ~87 MB | 7 |

| macOS 26 (Apple silicon) | Stack | Cold start | Warm start | RAM (RSS, all processes) | Processes |
| --- | --- | --- | --- | --- | --- |
| **Nucleus** | GraalVM native image | ~0.32 s | ~0.20 s | ~115 MB | 1 |
| SwiftUI | native reference | ~0.14 s | ~0.14 s | ~78 MB | 1 |
| Flutter | Dart AOT and Skia | ~0.79 s | ~0.17 s | ~100 MB | 1 |
| Tauri | Rust and WKWebView | ~0.91 s | ~0.19 s | ~173 MB | 4 |

<Callout type="info">
The macOS RAM column counts shared framework pages, so compare rows within one table only. Cold
start and RAM grow with what your app loads. Electron figures come from public benchmarks; the
others were measured first-hand. See [Performance](/docs/performance).
</Callout>
