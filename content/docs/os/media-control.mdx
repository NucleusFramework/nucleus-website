`media-control` publishes track metadata to the system media center and receives playback
commands: Now Playing on macOS, the System Media Transport Controls (SMTC) on Windows, and MPRIS
on Linux.

## Add the dependency

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.media-control:<version>")
}
```

## Publish now-playing metadata

```kotlin
if (MediaControlService.isAvailable()) {
    MediaControlService.configure()
    MediaControlService.setMetadata(
        MediaMetadata(
            title = "Strobe",
            artist = "deadmau5",
            coverUrl = "file:///tmp/cover.png",
            duration = 10 * 60 * 1_000L,
        ),
    )
    MediaControlService.setPlaybackState(
        MediaPlaybackState(status = MediaPlaybackStatus.PLAYING, positionMs = 0),
    )
}
```

Push metadata when the track changes, and a state on each play, pause, stop and seek. Times are
in milliseconds. When the native library does not load, every call does nothing.

## Handle playback commands

```kotlin
MediaControlService.attach { event ->
    when (event) {
        MediaControlEvent.Play -> player.play()
        MediaControlEvent.Pause -> player.pause()
        MediaControlEvent.Next -> player.skipToNext()
        is MediaControlEvent.SetPosition -> player.seekTo(event.positionMs)
        else -> {}
    }
}
```

The listener runs on the UI thread and can change Compose state directly. A second `attach`
replaces the first listener. `detach()` unregisters the app from the media center.

<Callout type="warn" title="Changed in 3.0">
The `attach` listener ran on the AWT event dispatch thread in 2.x. It now runs on the host UI
thread (the Tao main thread). See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

| Event | Linux | macOS | Windows |
| --- | --- | --- | --- |
| `Play`, `Pause`, `Next`, `Previous`, `Stop`, `SetPosition` | yes | yes | yes |
| `Toggle` | yes | yes | no |
| `SeekBy` | yes | no | yes |
| `SetVolume`, `OpenUri`, `Raise`, `Quit` | yes | no | no |

## Platform notes

- **macOS**: set `appCategory = "public.app-category.music"` under
  `nucleus.application.nativeDistributions.macOS` so Now Playing treats the app as a media player.
  Hardware media keys then send Play, Pause, Next and Previous.
- **Windows**: test with the installed app, since SMTC identifies it through its Start Menu
  shortcut. `coverUrl` accepts `file://`, a bare path or `http(s)://`.
- **Linux**: the player appears as `org.mpris.MediaPlayer2.<suffix>`, derived from
  `NucleusApp.appId`, for `playerctl` and desktop indicators. A local `coverUrl` must use
  `file://`. If the session bus is unreachable or `dbusName` is invalid, `attach` logs a
  warning and returns, while `isAvailable()` still returns `true`.

<Accordions>
<Accordion title="Under the hood">

- macOS uses `MPNowPlayingInfoCenter` and `MPRemoteCommandCenter`; the app bundle provides the
  identity.
- SMTC uses the AUMID the Nucleus plugin stamps on the Start Menu shortcut, or the MSIX package
  identity. It treats the most recent publisher as the current source.
- On Linux, `configure` registers the MPRIS bus name over D-Bus. Illegal characters in `appId`
  become `_`, elements that start with a digit get an `_` prefix, empty elements drop out, and
  the suffix stays under 255 characters.

</Accordion>
</Accordions>

## API reference

| Symbol | Notes |
| --- | --- |
| `isAvailable()` | `true` when the native library loaded |
| `configure(dbusName, displayName)` | Both optional; `displayName` defaults to `NucleusApp.appName`, or `"Nucleus App"` |
| `setMetadata(MediaMetadata)` | `title`, `artist`, `album`, `coverUrl`, `duration`; each defaults to `null` |
| `setPlaybackState(MediaPlaybackState)` | `status` (`STOPPED`, `PAUSED`, `PLAYING`), optional `positionMs` |
| `setVolume(value)` | Clamped to `0.0..1.0`. macOS ignores it |
| `attach(listener)` / `detach()` | Receive `MediaControlEvent`s / stop and unregister |
