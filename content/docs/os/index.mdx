The OS integration modules give you native desktop features from Kotlin: notifications, the
system tray, global hotkeys, media controls, dark mode, accent color, and more. Each feature ships
as its own Gradle artifact, so you add only the modules you use.

## Coverage

| Feature | Module | macOS | Windows | Linux |
| --- | --- | --- | --- | --- |
| Cross-platform notifications | `notification-common` | yes | yes | yes |
| Native notifications | `notification-macos`, `notification-windows`, `notification-linux` | yes | yes | yes |
| System tray | `composenativetray` | yes | yes | yes |
| Tray popup apps | `composenativetray-app` | yes | yes | yes |
| Global hotkeys | `global-hotkey` | yes | yes | yes |
| Media controls | `media-control` | yes | yes | yes |
| Dark mode | `darkmode-detector` | yes | yes | yes |
| Accent color and high contrast | `system-color` | yes | yes | yes |
| Hardware and OS info | `system-info` | yes | yes | yes |
| macOS menu bar | `menu-macos` | yes | no | no |
| Spell check | `spellcheck` | yes | yes | yes |
| SF Symbols names | `sf-symbols` | yes | no | no |
| FreeDesktop icon names | `freedesktop-icons` | no | no | yes |

Modules use the group `dev.nucleusframework` and the artifact name `nucleus.<module-name>`. The
two tray modules drop the `nucleus.` prefix: `composenativetray` holds the icon and menu,
`composenativetray-app` holds `TrayApp`.

`nucleus-application` already includes `darkmode-detector` and `spellcheck`. For notifications,
start with `notification-common`; add a platform module when you need a feature it leaves out,
such as Windows toast progress bars, macOS scheduled delivery, or Linux urgency hints.

## Callback threads

`notification-common`, `notification-linux`, `notification-windows`, `media-control`,
`menu-macos`, and `global-hotkey` call your code on the UI thread. The `notification-macos`
delegate runs on a native thread: move the work to `Dispatchers.Main` before you touch UI state.

<Callout type="warn" title="Changed in 3.0">
In 2.x, `notification-linux`, `notification-windows`, and `media-control` called back on the AWT
event dispatch thread. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>
