import { Callout } from 'fumadocs-ui/components/callout';

`spellcheck` marks misspelled words in a Compose text field and injects suggestions into the
field's existing Cut/Copy/Paste menu. Wrap the field with `SpellcheckContextMenu`. The engine
is Hunspell on Linux; on macOS and Windows — and on Linux when Hunspell or a matching
dictionary is missing — every call is a no-op.

`nucleus-application` depends on `spellcheck` as an `api` dependency, so the wrap and the
engine are on the classpath whenever you use `nucleusApplication`. Add the coordinate
explicitly only when you use the engine outside that umbrella.

## Add the dependency

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.nucleus-application:<version>")
    // Optional — only if you use SpellChecker / SpellcheckSession without the umbrella:
    // implementation("dev.nucleusframework:nucleus.spellcheck:<version>")
}
```

## Wrap a text field

Pass the current text and a write-back, or a `TextFieldState`. The wrap draws the underline
from the IME layout (never from the Material / Jewel decoration box, so a floating label is
never marked as a misspelling) and appends suggestions to the field's context menu.

```kotlin
import androidx.compose.foundation.text.BasicTextField
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import dev.nucleusframework.application.spellcheck.SpellcheckContextMenu

@Composable
fun NotesField() {
    var text by remember { mutableStateOf("") }
    SpellcheckContextMenu(text = text, onTextChange = { text = it }) {
        BasicTextField(value = text, onValueChange = { text = it })
    }
}
```

```kotlin
import androidx.compose.material.Text
import androidx.compose.material.TextField
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import dev.nucleusframework.application.spellcheck.SpellcheckContextMenu

@Composable
fun MaterialNotesField() {
    var text by remember { mutableStateOf("") }
    SpellcheckContextMenu(text = text, onTextChange = { text = it }) {
        TextField(
            value = text,
            onValueChange = { text = it },
            label = { Text("Notes") }, // never underlined
        )
    }
}
```

Right-click a misspelled word: suggestions, a separator, then **Add to dictionary**. The
session is created on a background dispatcher; the first right-click before the dictionary
is loaded shows the stock menu only.

## Menu placement

Compose walks context-menu data inner-first, so a parent `ContextMenuDataProvider` always
lands at the **bottom** of the menu. `menuPlacement` chooses the visible order:

```kotlin
import dev.nucleusframework.application.spellcheck.SpellcheckMenuPlacement

SpellcheckContextMenu(
    state = state,
    menuPlacement = SpellcheckMenuPlacement.Top,
) {
    TextField(state = state)
}
```

| Placement | Order |
|-----------|--------|
| `Bottom` (default) | Cut/Copy/Paste and app items, then a separator, then suggestions |
| `Top` | Suggestions, then a separator, then Cut/Copy/Paste and app items |

`Top` prepends at draw time and keeps the ambient `LocalContextMenuRepresentation` (Jewel or
any custom chrome). Provide a custom `LocalTextContextMenu` / representation **outside** the
wrap. If you replace those locals inside the wrap, `Top` cannot inject items.

## Jewel

`JewelDecoratedWindow` and `JewelDecoratedDialog` install `ProvideJewelSpellcheckMenu`, which
sets `LocalSpellcheckMenuSeparator` to Jewel's `ContextMenuDivider`. Separators render as
Jewel hairlines; the wrap does not replace Jewel's menu chrome.

If you build Jewel chrome around a plain `DecoratedWindow`, wrap the content yourself:

```kotlin
import dev.nucleusframework.window.jewel.ProvideJewelSpellcheckMenu

ProvideJewelSpellcheckMenu {
    SpellcheckContextMenu(state = state) {
        TextField(state = state)
    }
}
```

## Custom context menus

Apps that already build the item list (icons, keybindings, extra actions) should insert the
returned block at the matching index instead of relying on the wrap to inject items:

```kotlin
import androidx.compose.foundation.ContextMenuDataProvider
import dev.nucleusframework.application.spellcheck.NucleusSpellcheckInstaller
import dev.nucleusframework.application.spellcheck.SpellcheckMenuPlacement
import dev.nucleusframework.spellcheck.SpellChecker
import org.jetbrains.jewel.ui.component.ContextMenuDivider

ContextMenuDataProvider(
    items = {
        buildList {
            val session = SpellChecker.sessionIfReady
            if (session != null) {
                addAll(
                    NucleusSpellcheckInstaller.menuItems(
                        word = selectedWord,
                        session = session,
                        onSuggestion = { replacement -> /* rewrite the field */ },
                        onAddToDictionary = { session.addToDictionary(selectedWord) },
                        separator = ContextMenuDivider,
                        menuPlacement = SpellcheckMenuPlacement.Top,
                    ),
                )
            }
            // app items…
        }
    },
) {
    // field
}
```

Do not combine that insertion with a wrap that also injects menu items — you would get the
block twice. You can still wrap the field for the underline only if you insert items yourself;
in that case keep the wrap outside any `LocalTextContextMenu` override so the IME interceptor
sees the field.

## How it works

- **Linux** — JNI `dlopen` of `libhunspell-1.7.so.0`. Dictionaries are the system
  `.aff` / `.dic` pair (`/usr/share/hunspell`, `/usr/share/myspell`, `DICPATH`,
  `$XDG_DATA_HOME/hunspell`). The locale is `Locale.getDefault()`, with language-only
  fallbacks (`fr` → `fr_FR`).
- **User dictionary** — words added from the menu persist under
  `~/.config/nucleus/spellcheck/<tag>.dic` (`$XDG_CONFIG_HOME` when set).
- **macOS / Windows** — no-op. `check` returns `false`, `suggest` is empty, the wrap
  renders the field unchanged.
- **Missing Hunspell or dictionary** — same no-op. The field keeps its stock menu.
- **Underlines** — drawn from `PlatformTextInputMethodRequest.textLayoutResult` and clipped
  to the IME text rect. The Material / Jewel decoration box is never measured.
- **GraalVM** — the module ships JNI reachability metadata. There is no reflection.

## Engine API

Use `SpellChecker` when you need check / suggest without a Compose wrap. Prefer
`sessionIfReady` / `ensureSession()` on a background dispatcher; `session` loads Hunspell
on first access and must not run on the UI thread.

```kotlin
import dev.nucleusframework.spellcheck.SpellChecker
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext

suspend fun loadSpellcheck() {
    val session = withContext(Dispatchers.IO) { SpellChecker.ensureSession() }
    if (!session.isAvailable) return
    session.check("hello")          // true
    session.suggest("helo")         // ["hello", …]
    session.misspellings("helo world")
    session.addToDictionary("helo")
}
```

`SpellcheckSession` is the isolated handle behind `SpellChecker`. Construct your own only
when you need a different locale or user-dictionary path than the process-wide instance.

## Notes

<Callout type="warn">
On Linux, install Hunspell and a dictionary for the JVM locale (`hunspell` and
`hunspell-en-us`, `hunspell-fr`, …). Without both, the wrap is silent.
</Callout>

<Callout type="info">
The wrap uses Compose Desktop's classic context menu (`ContextMenuDataProvider` /
`LocalTextContextMenu`). It does not participate in
`ComposeFoundationFlags.isNewContextMenuEnabled`.
</Callout>
