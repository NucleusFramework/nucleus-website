`global-hotkey` registers keyboard shortcuts that fire whichever app has focus, on macOS, Windows
and Linux.

## Add the dependency

```kotlin title="build.gradle.kts"
dependencies {
    implementation("dev.nucleusframework:nucleus.global-hotkey:<version>")
}
```

## Register a hotkey

```kotlin
DisposableEffect(Unit) {
    GlobalHotKeyManager.initialize()
    val handle = GlobalHotKeyManager.register(
        keyCode = KeyEvent.VK_K,
        modifiers = HotKeyModifier.CONTROL + HotKeyModifier.SHIFT,
    ) { _, _ ->
        showQuickSwitcher()
    }
    onDispose { GlobalHotKeyManager.unregister(handle) }
}
```

- `register` returns a handle, or `-1` when the system refuses the binding. `lastError` says why.
- `keyCode` takes the `java.awt.event.KeyEvent` constants. The module does not start AWT.
- The listener runs on the UI thread, so it can update Compose state directly. A press still
  queued when you call `unregister` is dropped.
- `GlobalHotKeyManager.register(MediaKey.PLAY_PAUSE) { … }` binds a media key on Windows and
  Linux. On macOS it returns `-1`; use [media controls](/docs/os/media-control) there.

## Track presses and releases

The two-parameter listener above receives presses only, auto-repeats included. Pass a
`HotKeyEventListener` to receive every `HotKeyEvent` instead:

```kotlin
val handle = GlobalHotKeyManager.register(
    keyCode = KeyEvent.VK_SPACE,
    modifiers = HotKeyModifier.CONTROL + HotKeyModifier.ALT,
    description = "Peek",
    listener = HotKeyEventListener { event ->
        when (event.state) {
            HotKeyState.PRESSED -> if (!event.isRepeat) showPeek()
            HotKeyState.RELEASED -> hidePeek()
        }
    },
)
```

- Only Linux reports `RELEASED`, on X11 and Wayland. macOS and Windows deliver presses only.
- Holding the chord on Linux repeats the press. `isRepeat` is `true` for those repeats, and always
  `false` on macOS and Windows.
- `timestamp` is in the platform's millisecond clock, or `0` when the platform gives none. Compare
  it only with other events of the same hotkey.
- `register(MediaKey, listener)` accepts a `HotKeyEventListener` too.

## Bring a window to the front

Call `requestFocus()` or `toFront()` on the window from the listener. On Wayland, the compositor
lets a window take focus only with the activation token it issued for the hotkey press, and the
window uses that token on its own:

```kotlin
val window = LocalNucleusWindow.current
DisposableEffect(window) {
    val handle = GlobalHotKeyManager.register(
        keyCode = KeyEvent.VK_SPACE,
        modifiers = HotKeyModifier.CONTROL + HotKeyModifier.ALT,
        description = "Show the app",
        listener = HotKeyEventListener { event ->
            if (event.state == HotKeyState.PRESSED && !event.isRepeat) {
                window.show()
                window.requestFocus()
            }
        },
    )
    onDispose { GlobalHotKeyManager.unregister(handle) }
}
```

- Request focus from the listener. The token is single-use and expires after a few seconds.
- The portal sends a token from xdg-desktop-portal 1.21 on. With an older portal, the compositor
  can refuse the focus request and flag the window instead.
- `event.activationToken` exposes the token for an app that hands it on itself, for example to
  another process. It is `null` on X11, macOS and Windows, which need none.

## Linux portal registrations

On Wayland, the desktop portal asks the user to approve your shortcuts, once per chord. Nucleus
batches `register` calls into one dialog, and `description` labels each shortcut in it. Call
`commitRegistrations()` to show the dialog now and learn whether the portal accepted the set.

The portal needs a reverse-DNS `.desktop` file, and the app must start from it. Compositors
without the portal do not deliver global shortcuts.

<Callout type="warn" title="macOS permissions">
macOS can ask the user to allow your app under System Settings > Privacy & Security > Input
Monitoring, and sometimes Accessibility. Callbacks stay silent until the user accepts. Open that
pane with `x-apple.systempreferences:com.apple.preference.security?Privacy_ListenEvent`.
</Callout>

<Accordion title="Under the hood">

- Backends: `RegisterHotKey` on Windows, Carbon `RegisterEventHotKey` on macOS, `XGrabKey` on
  X11, `org.freedesktop.portal.GlobalShortcuts` on Wayland.
- The portal remembers each grant per `(app_id, shortcut_id)`. Nucleus derives the id from the
  chord (`nucleus_m{mods}_k{keyCode}`), so it stays stable across launches.
  `portalShortcutId(handle)` returns it, or `null` off Linux.
- Releases come from the portal's `Deactivated` signal on Wayland and from the grabbed key's
  `KeyRelease` on X11. GNOME re-emits `Activated` for each auto-repeat, each with a fresh token.
- Hotkeys and Linux notification clicks hand their `xdg-activation` token to a shared mailbox in
  `core-runtime` (`ActivationToken`). A window's focus request takes the latest one.

## API reference

| Symbol | Notes |
| --- | --- |
| `initialize()` | Loads the native library and starts the event source |
| `register(keyCode, modifiers = 0, description = null, listener): Long` | Also `register(MediaKey, listener)`: `PLAY_PAUSE`, `STOP`, `NEXT_TRACK`, `PREV_TRACK`. `listener` is a `HotKeyListener` (presses) or a `HotKeyEventListener` (every event) |
| `HotKeyEvent` | `keyCode`, `modifiers`, `state` (`HotKeyState.PRESSED` / `RELEASED`), `isRepeat`, `timestamp`, `activationToken: String?` |
| `HotKeyModifier.ALT` / `CONTROL` / `SHIFT` / `META` | Combine with `+`; `0 + META` for one. On macOS `ALT` is Option and `META` is Command, elsewhere `META` is Windows or Super |
| `commitRegistrations()` | Shows the Wayland portal dialog now |
| `isAvailable` / `lastError` | Native library loaded; last failure message, `null` after a success |
| `unregister(handle): Boolean` / `shutdown()` | Release one binding / all of them. Call `shutdown()` on exit |
