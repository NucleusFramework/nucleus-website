Les applications Nucleus utilisent [FileKit](https://filekit.mintlify.app) pour les sélecteurs
natifs d'ouverture, d'enregistrement et de dossier. Ajoutez la dépendance et appelez FileKit :
Nucleus s'occupe de la configuration. Pour l'API complète (types de fichiers, sélection multiple,
enregistrement, `PlatformFile`), consultez la
[documentation de FileKit](https://filekit.mintlify.app/dialogs/setup).

```kotlin title="build.gradle.kts"
dependencies {
    implementation("io.github.vinceglb:filekit-dialogs:<filekit-version>")
}
```

## Choisir un fichier

```kotlin
val scope = rememberCoroutineScope()

Button(onClick = {
    scope.launch {
        val file = FileKit.openFilePicker(type = FileKitType.Image)
        // file vaut null si l'utilisateur annule
    }
}) {
    Text("Ouvrir une image")
}
```

## Ce que Nucleus fait pour vous

- **Initialisation.** `nucleusApplication` appelle `FileKit.init(NucleusApp.appId)` quand FileKit
  est sur le classpath. Les lancements en dev, les apps empaquetées et les images natives partagent
  un même répertoire de fichiers.
- **Désinstallation.** Sous Windows, ce répertoire est `%APPDATA%\<appId>`, que le désinstalleur
  NSIS supprime si vous activez `deleteAppDataOnUninstall`.
- **Image native.** Le plugin Nucleus fournit les métadonnées GraalVM de FileKit : les sélecteurs
  fonctionnent dans une image native sans configuration.

<Callout type="warn" title="Modifié en 3.0">
L'appel automatique à `FileKit.init` est nouveau. Votre propre `FileKit.init(…)` avant
`nucleusApplication` reste prioritaire, un appel dans `content` remplace l'appel automatique, et
`nucleusApplication(args, initializeFileKit = false)` le désactive. Voir
[Migrer depuis Nucleus 2.x](/docs/migrate/from-2.x#vérifier-linitialisation-de-filekit).
</Callout>

## Rattacher le dialogue à une fenêtre

Enveloppez l'appel FileKit dans `withFileKitDialogSettings` sur la fenêtre qui l'ouvre. Le
sélecteur reste alors au-dessus de cette fenêtre au lieu de flotter seul :

```kotlin
val window = LocalNucleusWindow.current

scope.launch {
    val file = window.withFileKitDialogSettings { settings ->
        FileKit.openFilePicker(dialogSettings = settings)
    }
}
```

Passez vos propres `FileKitDialogSettings` en premier argument pour garder un titre ou des options
macOS : Nucleus ne renseigne que `parent`, et ne touche pas des réglages qui en ont déjà un. Cela
fonctionne sous Windows, X11 et Wayland. macOS n'a pas besoin de parent : le sélecteur y est déjà
modal pour l'application.
