`fs-watcher` watches files and directories on macOS, Windows and Linux and delivers create,
modify, remove and move events as a coroutine `Flow`. Add
`dev.nucleusframework:nucleus.fs-watcher`; it exposes `kotlinx-coroutines-core`.

## Watch a directory

```kotlin
suspend fun watchDownloads() = coroutineScope {
    if (!FsWatchers.isSupported()) return@coroutineScope
    val watcher = FsWatchers.create()

    // Collect before registering so no early event is lost.
    launch {
        watcher.events.collect { event ->
            when (event) {
                is FsWatchEvent.Created -> println("created ${event.path}")
                is FsWatchEvent.Modified -> println("modified ${event.path}")
                is FsWatchEvent.Removed -> println("removed ${event.path}")
                is FsWatchEvent.Moved -> println("moved ${event.from} -> ${event.to}")
                is FsWatchEvent.Overflow -> println("events dropped, rescan needed")
                is FsWatchEvent.Other -> println("other ${event.paths}")
            }
        }
    }

    watcher.watch(Path.of(System.getProperty("user.home"), "Downloads"), recursive = true)
}
```

- `events` and `errors` are hot flows without replay: collect before you call `watch`.
- `watch` returns an `FsWatchRegistration`; close it to stop watching that path. Closing the
  `FsWatcher` closes every registration.
- On `Overflow`, events were dropped: re-list the tree instead of trusting the stream.
- Events come back under the path you registered, even when it goes through a symlink.

## Handle renames

In the default `Debounced` mode, a rename arrives as `FsWatchEvent.Moved(from, to)` when the OS
lets Nucleus pair both halves, and as `Removed(old)` then `Created(new)` otherwise.
`FsWatchDeliveryMode.Raw` never emits `Moved`.

<Callout type="warn" title="Changed in 3.0">
On macOS, a rename used to arrive as a bare `Created` for the new path, and a delete of an older
file as `Modified`. `Debounced` delivery now reports `Moved`, or `Removed` + `Created`, and
`Removed` for deletes.
</Callout>

<Accordions>
<Accordion title="Under the hood">

- Each `FsWatcher` owns one native watcher (inotify, FSEvents, `ReadDirectoryChangesW`) shared by
  its registrations. It starts on the first `watch()` and stops after the last registration closes.
- Registering one directory under two spellings creates two independent registrations.
- On macOS, `Raw` mode delivers the FSEvents flags as they come, historical ones included.
- Polling runs in the same native library. Without it, `isSupported()` returns `false` and
  `create()` throws `FsWatchException` for every strategy.

</Accordion>
</Accordions>

## API reference

| Member | Description |
|---|---|
| `FsWatchers.create(config = FsWatcherConfig())` | Builds a watcher. Throws `FsWatchException` when no backend fits. |
| `FsWatchers.isSupported(config)` | Whether a backend is available for `config`. |
| `FsWatcher.events` / `errors` | Hot `Flow<FsWatchEvent>` / `Flow<FsWatchError>` across all registrations. |
| `FsWatcher.registrations` | `Set<FsWatchSource>` of the registered roots. |
| `FsWatcher.watch(path, recursive = true, name = null)` | Returns an `FsWatchRegistration` (`source`, `active`, `close()`). `name` tells registrations of the same root apart. |

`FsWatcherConfig` fields:

| Field | Default | Description |
|---|---|---|
| `followSymlinks` | `false` | Descend into symlinks inside a watched tree. |
| `backend` | `Auto` | `Auto` or `NativeOnly` (native, no polling fallback), or `Polling(interval = 2 s, compareContents = false)`. |
| `eventBufferCapacity` | `64` | Event buffer size. A full buffer emits `Overflow`. |
| `errorBufferCapacity` | `32` | Error buffer size. |
| `deliveryMode` | `Debounced(window = 150 ms)` | Merges bursts per path and pairs renames. `Raw` delivers every event as it comes. |

Every `FsWatchEvent` carries `source` and `needsRescan`. `Created`, `Modified` and `Removed` have
`path`, `Moved` has `from` and `to`, `Other` has `paths`; all but `Overflow` have `isDirectory: Boolean?`.
`FsWatchError` has `message`, `source` (`null` for watcher-wide errors), `recoverable` and `cause`.
