`ExecutableRuntime` reports how the current process was packaged (DMG, APPX, Flatpak, Snap,
`./gradlew run`, and so on) and whether it runs in an OS sandbox. Branch on it to pick an update
channel or turn off a feature the sandbox forbids. It ships in `core-runtime`, which comes with
`nucleus-application`.

## Detect the packaging format

```kotlin
when (ExecutableRuntime.type()) {
    ExecutableType.APPX    -> showMicrosoftStoreUpdate()
    ExecutableType.SNAP    -> showSnapStoreUpdate()
    ExecutableType.FLATPAK -> showFlathubUpdate()
    ExecutableType.DEV     -> Unit // no updates in development
    else                   -> checkForUpdatesDirectly()
}
```

For a single format, use the matching check, such as `ExecutableRuntime.isDev()`. Any unpackaged
run returns `DEV`, and so does an unknown or missing type, so `DEV` cannot tell an IDE run from a
misconfigured package. In dev, `nucleusApplication` skips the
[single-instance lock](/docs/lifecycle/single-instance) and
[`AutoLaunch.wasStartedAtLogin`](/docs/lifecycle/background/launch-at-login) returns `false`.

## Detect a sandbox

`isSandboxed()` returns `true` inside the macOS App Sandbox, an AppX container, or a Flatpak.
Gate sandbox-sensitive code on it, not on the format: on macOS, a PKG built with
`macOS { pkg { appStore = false } }` is not sandboxed, while the App Store PKG is.

```kotlin
if (!ExecutableRuntime.isSandboxed()) {
    registerLaunchdTask()
}
```

<Callout type="warn" title="Changed in 3.0">
Code that tested `isPkg()` to detect the Mac App Store sandbox now misfires on Developer ID
PKGs. Test `isSandboxed()` instead. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

Which formats build sandboxed apps is covered in [Sandboxing](/docs/packaging/sandboxing).

<Accordions>
<Accordion title="Under the hood">

- The plugin records the format at build time: `-Dnucleus.executable.type=<kind>` in the
  launcher's `.cfg` for JVM apps, or a `.nucleus-executable-type` marker next to a native-image
  executable (`Contents/Resources/` on macOS). `type()` reads the property, then the marker.
- On macOS, `isSandboxed()` reads `APP_SANDBOX_CONTAINER_ID`, which macOS sets in every
  sandboxed process.
- `aot-runtime` re-exports both types as type aliases for AOT-only code.

</Accordion>
</Accordions>

## API reference

| Member | Returns | Notes |
|---|---|---|
| `type()` | `ExecutableType` | The packaging format. |
| `type(propertyName)` | `ExecutableType` | Reads the format from another system property. |
| `parseType(rawValue)` | `ExecutableType` | Parses a raw string. Unknown input maps to `DEV`. |
| `isSandboxed()` | `Boolean` | `true` in the macOS App Sandbox, an AppX container, or a Flatpak. |
| `markerVersion()` | `String?` | App version from the marker file (native images). For the version in general, read [`NucleusApp.version`](/docs/lifecycle/app-metadata). |
| `isGraalVmNativeImage` | `Boolean` | `true` in a GraalVM native image. |
| `isExe()` … `isDev()` | `Boolean` | One check per `ExecutableType` value. |

`ExecutableType` values:

- Windows: `EXE`, `MSI`, `NSIS`, `NSIS_WEB`, `PORTABLE`, `APPX`
- macOS: `DMG`, `PKG`
- Linux: `DEB`, `RPM`, `SNAP`, `FLATPAK`, `APPIMAGE`, `PACMAN`
- Archives: `ZIP`, `TAR`, `SEVEN_Z`
- Development: `DEV`
