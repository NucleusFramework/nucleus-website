Les deep links vous permettent d'enregistrer un schéma d'URL `myapp://` et de recevoir l'URI
entrant en Kotlin. `DeepLinkHandler` est fourni par `core-runtime`, qu'apporte
`nucleus-application`.

## Déclarer le schéma d'URL

Le plugin enregistre le schéma auprès de l'OS dans chaque installeur qu'il produit :

```kotlin title="build.gradle.kts"
nucleus.application {
    nativeDistributions {
        // protocol(name, vararg schemes) : name apparaît dans l'UI de l'OS, schemes sans "://".
        protocol("MyApp", "myapp")
    }
}
```

## Traiter les URI entrants

`onDeepLink` se déclenche pour l'URI qui a lancé l'app et pour chaque activation suivante. Sous
Windows et Linux, une activation suivante atteint le process en cours via le verrou
d'[instance unique](/docs/lifecycle/single-instance).

```kotlin
fun main(args: Array<String>) = nucleusApplication(args) {
    onDeepLink { uri: URI -> navigateTo(uri) }

    DecoratedWindow(onCloseRequest = ::exitApplication) { /* ... */ }
}
```

Un URI reçu avant l'enregistrement est rejoué dès que vous enregistrez. L'URI de lancement ne se
déclenche qu'une fois par process, même si l'enregistrement se rejoue à la recomposition.

Testez avec un build empaqueté, puisque l'installeur enregistre le schéma : `open myapp://test`
(macOS), `start myapp://test` (Windows) ou `xdg-open myapp://test` (Linux). En dev, passez
`enableSingleInstance = true` pour tester la transmission.

## Utiliser DeepLinkHandler sans nucleusApplication

Dans un hôte Compose Desktop ou Swing classique, câblez `DeepLinkHandler` vous-même. Sur macOS,
installez aussi le handler Apple Events d'AWT :

```kotlin
fun main(args: Array<String>) {
    DeepLinkHandler.setHandler(args) { uri -> navigateTo(uri) }
    DeepLinkHandler.installAwtAppleEventHandler() // macOS, hôtes AWT uniquement
    startUi()
}
```

<Callout type="warn">
N'appelez jamais `installAwtAppleEventHandler` dans une app `nucleusApplication` : sur macOS, AWT
et la boucle d'événements Tao se bloquent mutuellement. `onDeepLink { }` y reçoit déjà les Apple
Events.
</Callout>

Pour les associations de fichiers, comme ouvrir les `.csv` avec votre app, utilisez le DSL
`fileAssociation(...)` du plugin.

<Accordions>
<Accordion title="En coulisses">

- macOS enregistre `CFBundleURLTypes` dans `Info.plist` et livre un Apple Event à l'app en cours.
  Windows écrit `HKCU\Software\Classes\<scheme>`. Linux ajoute
  `MimeType=x-scheme-handler/<scheme>;` au fichier `.desktop`, plus une association `xdg-mime`.
  Ces deux derniers démarrent un nouveau process avec l'URL en argument.
- `setHandler` lit la première entrée de `args` qui ressemble à un deep link. Il accepte
  `myapp://path` et la forme opaque `myapp:?query=…` (fréquente avec `xdg-open`), et rejette les
  chemins de lecteur Windows.
- Un second lancement enregistre son URI avec `captureFromArgs`, l'écrit avec `writeUriTo(path)`
  puis se termine. Le process principal le relit avec `readUriFrom(path)`, qui déclenche votre
  callback.

</Accordion>
</Accordions>

## Référence de l'API

| Symbole | Notes |
|---|---|
| `protocol(name, vararg schemes)` | DSL Gradle dans `nativeDistributions`. |
| `NucleusApplicationScope.onDeepLink(block: (URI) -> Unit)` | Apple Events sur macOS et `args` passés à `nucleusApplication`. |
| `DeepLinkHandler.setHandler(args, onDeepLink)` | Enregistre le callback et livre l'URI de lancement une fois. Ne touche pas AWT. |
| `DeepLinkHandler.installAwtAppleEventHandler()` | macOS, hôtes AWT. Initialise AWT. |
| `DeepLinkHandler.captureFromArgs(args)` | Enregistre un URI depuis `args` sans callback. |
| `DeepLinkHandler.writeUriTo(path)` / `readUriFrom(path)` | Transmettent un URI via un fichier. `readUriFrom` déclenche le callback. |
| `DeepLinkHandler.deliver(newUri)` | Pousse un URI dans le handler, pour d'autres voies de livraison et les tests. |
| `DeepLinkHandler.uri` | Le dernier URI reçu, y compris l'URI de lancement. |
| `DeepLinkHandler.register(args, onDeepLink)` | Déprécié : installe toujours le handler AWT. Utilisez `onDeepLink { }` ou `setHandler`. |
