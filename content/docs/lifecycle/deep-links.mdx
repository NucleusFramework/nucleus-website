Deep links let you register a `myapp://` URL scheme and receive the incoming URI in Kotlin.
`DeepLinkHandler` ships in `core-runtime`, which comes with `nucleus-application`.

## Declare the URL scheme

The plugin registers the scheme with the OS in every installer it builds:

```kotlin title="build.gradle.kts"
nucleus.application {
    nativeDistributions {
        // protocol(name, vararg schemes): name appears in OS UI, schemes have no "://".
        protocol("MyApp", "myapp")
    }
}
```

## Handle incoming URIs

`onDeepLink` fires for the URI that launched the app and for every later activation. On Windows
and Linux, a later activation reaches the running process through the
[single-instance](/docs/lifecycle/single-instance) lock.

```kotlin
fun main(args: Array<String>) = nucleusApplication(args) {
    onDeepLink { uri: URI -> navigateTo(uri) }

    DecoratedWindow(onCloseRequest = ::exitApplication) { /* ... */ }
}
```

A URI that arrives before you register is replayed once you do. The launch URI fires once per
process, even if the registration re-runs on recomposition.

Test with a packaged build, since the installer registers the scheme: `open myapp://test`
(macOS), `start myapp://test` (Windows), or `xdg-open myapp://test` (Linux). In a dev run, pass
`enableSingleInstance = true` to test the forwarding.

## Use DeepLinkHandler without nucleusApplication

In a plain Compose Desktop or Swing host, wire `DeepLinkHandler` yourself. On macOS, also install
the AWT Apple Events handler:

```kotlin
fun main(args: Array<String>) {
    DeepLinkHandler.setHandler(args) { uri -> navigateTo(uri) }
    DeepLinkHandler.installAwtAppleEventHandler() // macOS, AWT hosts only
    startUi()
}
```

<Callout type="warn">
Never call `installAwtAppleEventHandler` in a `nucleusApplication` app: on macOS, AWT and the Tao
event loop deadlock. `onDeepLink { }` already receives Apple Events there.
</Callout>

For file associations, such as opening `.csv` files, use the plugin's `fileAssociation(...)` DSL.

<Accordions>
<Accordion title="Under the hood">

- macOS registers `CFBundleURLTypes` in `Info.plist` and delivers an Apple Event to the running
  app. Windows writes `HKCU\Software\Classes\<scheme>`. Linux adds
  `MimeType=x-scheme-handler/<scheme>;` to the `.desktop` file plus an `xdg-mime` association.
  Both start a new process with the URL as an argument.
- `setHandler` reads the first deep-link-shaped entry of `args`. It accepts `myapp://path` and
  the opaque form `myapp:?query=…` (common from `xdg-open`), and rejects Windows drive paths.
- A second launch records its URI with `captureFromArgs`, writes it with `writeUriTo(path)`, and
  exits. The primary reads it with `readUriFrom(path)`, which fires your callback.

</Accordion>
</Accordions>

## API reference

| Symbol | Notes |
|---|---|
| `protocol(name, vararg schemes)` | Gradle DSL in `nativeDistributions`. |
| `NucleusApplicationScope.onDeepLink(block: (URI) -> Unit)` | Apple Events on macOS and the `args` passed to `nucleusApplication`. |
| `DeepLinkHandler.setHandler(args, onDeepLink)` | Registers the callback and delivers the launch URI once. Does not touch AWT. |
| `DeepLinkHandler.installAwtAppleEventHandler()` | macOS, AWT hosts. Initializes AWT. |
| `DeepLinkHandler.captureFromArgs(args)` | Records a URI from `args` without a callback. |
| `DeepLinkHandler.writeUriTo(path)` / `readUriFrom(path)` | Hand a URI over through a file. `readUriFrom` fires the callback. |
| `DeepLinkHandler.deliver(newUri)` | Pushes a URI through the handler, for other delivery paths and tests. |
| `DeepLinkHandler.uri` | The last URI received, including the launch URI. |
| `DeepLinkHandler.register(args, onDeepLink)` | Deprecated: always installs the AWT handler. Use `onDeepLink { }` or `setHandler`. |
