`EnergyManager` lowers your app's CPU and I/O priority while it sits in the background, and keeps
the system or display awake during long work, on Windows, macOS and Linux. Add
`dev.nucleusframework:nucleus.energy-manager` to call it; `Modifier.keepScreenOn()` works without it.

## Throttle a background window

Light mode lowers CPU priority only. Full mode also throttles I/O, and network on macOS:

```kotlin
LaunchedEffect(isMinimized, isFocused) {
    when {
        isMinimized -> {
            EnergyManager.disableLightEfficiencyMode()
            EnergyManager.enableEfficiencyMode()       // CPU and I/O throttled
        }
        !isFocused -> {
            EnergyManager.disableEfficiencyMode()
            EnergyManager.enableLightEfficiencyMode()  // CPU only
        }
        else -> {
            EnergyManager.disableEfficiencyMode()
            EnergyManager.disableLightEfficiencyMode()
        }
    }
}
```

Inside a `DecoratedWindow`, read `isMinimized` and `isFocused` from `nucleusWindow`
(`minimizedFlow`, `focusFlow`). Manual `enable` and `disable` calls are yours to pair.

## Run a block at reduced priority

```kotlin
// Dedicated low-priority thread; I/O not throttled
val report = EnergyManager.withEfficiencyMode { computeHeavyReport() }

// Process-level light mode for the block, on the calling coroutine
EnergyManager.withLightEfficiencyMode { syncDataFromServer() }
```

Both helpers restore the previous mode when the block returns or throws.

## Keep the system awake

```kotlin
EnergyManager.keepAwake(AwakeMode.SYSTEM_AND_DISPLAY) // screen stays on (default)
EnergyManager.keepAwake(AwakeMode.SYSTEM_ONLY)        // screen may blank or lock
EnergyManager.releaseAwake()
```

`keepAwake` holds a single slot: a second call replaces the mode, and one `releaseAwake()` drops
the request. On macOS, closing the lid still sleeps in `SYSTEM_ONLY`.

## Hold several awake requests at once

Take one handle per independent feature, such as a player and a download:

```kotlin
val playback = EnergyManager.acquireAwake(AwakeMode.SYSTEM_AND_DISPLAY)
EnergyManager.acquireAwake(AwakeMode.SYSTEM_ONLY).use { exportProject() }
playback.close()
```

The OS request uses the strongest mode any live handle asked for, and ends once every handle is
closed and no `keepAwake` is left. `close()` is idempotent and thread-safe.

## Keep the screen on from a composable

```kotlin
Box(Modifier.keepScreenOn()) { Player() }
```

The display stays awake while the modifier is in the composition. Requests from several windows
never release each other or your `keepAwake` slot.

<Accordion title="Under the hood">

- Windows: EcoQoS plus `IDLE_PRIORITY_CLASS` for full mode (green leaf in Task Manager 22H2+).
  Windows 10 1709+ applies EcoQoS on battery only; Windows 11 on AC too.
- macOS: full mode runs on E-cores with I/O and network throttling on Apple Silicon.
- Linux: full mode is `nice +19`, idle I/O priority and a 100 ms timer slack; light mode is
  `nice +10`. `libdbus-1`, `libX11` and `libXss` load on demand, and a missing library turns the
  matching feature off. `SYSTEM_ONLY` needs a session bus or systemd-logind; the X11 screen-saver
  fallback cannot serve it.
- `Modifier.keepScreenOn()` shares one `acquireAwake(SYSTEM_AND_DISPLAY)` handle across windows
  and popups. When the OS refuses, it logs at `FINE` and does nothing else.

## API reference

| Method | Description |
|---|---|
| `isAvailable(): Boolean` | Whether the native bridge loaded. |
| `enableEfficiencyMode()` / `disableEfficiencyMode()` | Full process mode. |
| `enableLightEfficiencyMode()` / `disableLightEfficiencyMode()` | Light process mode. |
| `enableThreadEfficiencyMode()` / `disableThreadEfficiencyMode()` | The calling thread only. |
| `withEfficiencyMode { }` (suspend) | Runs the block on a dedicated thread in thread-level mode. |
| `withLightEfficiencyMode { }` (suspend) | Applies light process mode for the block. |
| `keepAwake(mode = SYSTEM_AND_DISPLAY)` / `releaseAwake()` | One shared awake slot; the last mode wins. |
| `acquireAwake(mode = SYSTEM_AND_DISPLAY): AwakeHandle` | An independent request, released by `close()`. |
| `isAwakeActive(): Boolean` | Whether an awake request is held. |
| `keepScreenAwake()` / `releaseScreenAwake()` / `isScreenAwakeActive()` | Deprecated forwarders to `keepAwake`, `releaseAwake`, `isAwakeActive`. |

`enable`, `disable`, `keepAwake` and `releaseAwake` return an `EnergyManager.Result` with
`success`, `errorCode` and `message`. On an unsupported platform, `success` is `false` and
`errorCode` is `-1`. `AwakeHandle` has `mode`, `isActive` and `close()`.
