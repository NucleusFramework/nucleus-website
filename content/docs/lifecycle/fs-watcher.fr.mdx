`fs-watcher` surveille fichiers et dossiers sous macOS, Windows et Linux et livre les événements
de création, modification, suppression et déplacement dans un `Flow` de coroutines. Ajoutez
`dev.nucleusframework:nucleus.fs-watcher` ; le module expose `kotlinx-coroutines-core`.

## Surveiller un dossier

```kotlin
suspend fun watchDownloads() = coroutineScope {
    if (!FsWatchers.isSupported()) return@coroutineScope
    val watcher = FsWatchers.create()

    // Collecter avant d'enregistrer pour ne perdre aucun événement précoce.
    launch {
        watcher.events.collect { event ->
            when (event) {
                is FsWatchEvent.Created -> println("created ${event.path}")
                is FsWatchEvent.Modified -> println("modified ${event.path}")
                is FsWatchEvent.Removed -> println("removed ${event.path}")
                is FsWatchEvent.Moved -> println("moved ${event.from} -> ${event.to}")
                is FsWatchEvent.Overflow -> println("events dropped, rescan needed")
                is FsWatchEvent.Other -> println("other ${event.paths}")
            }
        }
    }

    watcher.watch(Path.of(System.getProperty("user.home"), "Downloads"), recursive = true)
}
```

- `events` et `errors` sont des flows chauds sans replay : collectez avant d'appeler `watch`.
- `watch` renvoie un `FsWatchRegistration` ; fermez-le pour arrêter de surveiller ce chemin.
  Fermer le `FsWatcher` ferme toutes ses registrations.
- Sur `Overflow`, des événements ont été perdus : relistez l'arborescence au lieu de vous fier
  au flux.
- Les événements reviennent sous le chemin que vous avez enregistré, même s'il passe par un lien
  symbolique.

## Gérer les renommages

En mode `Debounced`, celui par défaut, un renommage arrive en `FsWatchEvent.Moved(from, to)`
quand l'OS permet à Nucleus d'apparier les deux moitiés, et en `Removed(old)` puis
`Created(new)` sinon. `FsWatchDeliveryMode.Raw` n'émet jamais `Moved`.

<Callout type="warn" title="Modifié en 3.0">
Sur macOS, un renommage arrivait en simple `Created` pour le nouveau chemin, et la suppression
d'un fichier ancien en `Modified`. La livraison `Debounced` signale désormais `Moved`, ou
`Removed` + `Created`, et `Removed` pour les suppressions.
</Callout>

<Accordions>
<Accordion title="En coulisses">

- Chaque `FsWatcher` possède un watcher natif (inotify, FSEvents, `ReadDirectoryChangesW`)
  partagé par ses registrations. Il démarre au premier `watch()` et s'arrête après la fermeture
  de la dernière registration.
- Enregistrer un même dossier sous deux écritures crée deux registrations indépendantes.
- Sur macOS, le mode `Raw` livre les flags FSEvents tels quels, historiques compris.
- Le polling tourne dans la même bibliothèque native. Sans elle, `isSupported()` renvoie `false`
  et `create()` lève `FsWatchException` quelle que soit la stratégie.

## Référence de l'API

| Membre | Description |
|---|---|
| `FsWatchers.create(config = FsWatcherConfig())` | Crée un watcher. Lève `FsWatchException` si aucun backend ne convient. |
| `FsWatchers.isSupported(config)` | Indique si un backend est disponible pour `config`. |
| `FsWatcher.events` / `errors` | `Flow<FsWatchEvent>` / `Flow<FsWatchError>` chauds, toutes registrations confondues. |
| `FsWatcher.registrations` | `Set<FsWatchSource>` des racines enregistrées. |
| `FsWatcher.watch(path, recursive = true, name = null)` | Renvoie un `FsWatchRegistration` (`source`, `active`, `close()`). `name` distingue les registrations d'une même racine. |

Champs de `FsWatcherConfig` :

| Champ | Défaut | Description |
|---|---|---|
| `followSymlinks` | `false` | Descendre dans les liens symboliques d'une arborescence surveillée. |
| `backend` | `Auto` | `Auto` ou `NativeOnly` (natif, sans repli sur le polling), ou `Polling(interval = 2 s, compareContents = false)`. |
| `eventBufferCapacity` | `64` | Taille du tampon d'événements. Un tampon plein émet `Overflow`. |
| `errorBufferCapacity` | `32` | Taille du tampon d'erreurs. |
| `deliveryMode` | `Debounced(window = 150 ms)` | Fusionne les rafales par chemin et apparie les renommages. `Raw` livre chaque événement tel quel. |

Chaque `FsWatchEvent` porte `source` et `needsRescan`. `Created`, `Modified` et `Removed` ont
`path`, `Moved` a `from` et `to`, `Other` a `paths` ; tous sauf `Overflow` ont
`isDirectory: Boolean?`. `FsWatchError` a `message`, `source` (`null` pour les erreurs globales
au watcher), `recoverable` et `cause`.
