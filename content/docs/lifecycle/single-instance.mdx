A packaged Nucleus app runs as one process. A second launch hands its
[deep link](/docs/lifecycle/deep-links) to the running process, which raises and focuses every
`DecoratedWindow`, then exits before Compose starts. `nucleusApplication` does this with no code,
the same way on macOS, Windows, and Linux.

## Enable it in dev runs

`./gradlew run` and IDE launches skip the lock, so a second debug copy starts normally. Turn it on
to test the hand-off, or pass `false` to turn it off in packaged builds too:

```kotlin
fun main(args: Array<String>) = nucleusApplication(args, enableSingleInstance = true) {
    // ...
}
```

<Callout type="warn" title="Changed in 3.0">
In 2.x, `enableSingleInstance` defaulted to `true` in dev runs as well. It now defaults to
`!ExecutableRuntime.isDev()`. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

## React to a second launch

When your main surface is not a `DecoratedWindow`, such as a tray popup, restore it yourself.
The callback runs on the UI thread:

```kotlin
SingleInstanceRestoreEffect { popupVisible = true }
```

## Wire it manually

Without `nucleusApplication`, call `SingleInstanceManager.isSingleInstance` at the top of `main`,
before you build any UI:

```kotlin
fun main(args: Array<String>) {
    val isPrimary = SingleInstanceManager.isSingleInstance(
        onRestoreFileCreated = {
            // Second instance. `this` is the restore-request Path: write the payload.
        },
        onRestoreRequest = {
            // Primary, on a background thread.
            NucleusUiThread.post { bringMainWindowToFront() }
        },
    )
    if (!isPrimary) exitProcess(0)
    startUi(args)
}
```

`onRestoreFileCreated` is optional. To pass a URI, use
[`DeepLinkHandler.writeUriTo`](/docs/lifecycle/deep-links).

The lock is named after the app id and lives in the per-user temp directory, so two apps never
collide and two users can each run the app.

<Accordions>
<Accordion title="Under the hood">

- The lock is a `java.nio.channels.FileLock` on `<lockIdentifier>.lock`. The kernel releases it
  when the JVM exits or crashes, so a killed primary does not lock the app out.
- A second launch writes `<lockIdentifier>.restore_request` next to it. The primary watches the
  directory with a `WatchService` and calls `onRestoreRequest`.
- A stale or unreadable lock file is deleted and retried once. Only an unrecoverable error makes
  the process continue as the primary.

</Accordion>
</Accordions>

## API reference

| Symbol | Notes |
|---|---|
| `SingleInstanceManager.isSingleInstance(onRestoreFileCreated, onRestoreRequest): Boolean` | `true` in the primary. `onRestoreRequest` runs on a daemon thread. |
| `SingleInstanceManager.configuration` | Assign before the first `isSingleInstance` call, or it throws `IllegalStateException`. |
| `Configuration.lockFilesDir` | Lock directory. Default `java.io.tmpdir`. |
| `Configuration.lockIdentifier` | Base name of the lock files. Default: the app id. |
| `SingleInstanceRestoreEffect(onRestore)` | Composable in `dev.nucleusframework.application`. Runs on each second launch. |
