`EnergyManager` abaisse la priorité CPU et I/O de votre app quand elle est en arrière-plan, et
garde le système ou l'écran éveillé pendant un long travail, sous Windows, macOS et Linux. Ajoutez
`dev.nucleusframework:nucleus.energy-manager` pour l'appeler ; `Modifier.keepScreenOn()`
fonctionne sans.

## Ralentir une fenêtre en arrière-plan

Le mode léger abaisse seulement la priorité CPU. Le mode complet ralentit aussi les I/O, et le
réseau sur macOS :

```kotlin
LaunchedEffect(isMinimized, isFocused) {
    when {
        isMinimized -> {
            EnergyManager.disableLightEfficiencyMode()
            EnergyManager.enableEfficiencyMode()       // CPU et I/O ralentis
        }
        !isFocused -> {
            EnergyManager.disableEfficiencyMode()
            EnergyManager.enableLightEfficiencyMode()  // CPU seulement
        }
        else -> {
            EnergyManager.disableEfficiencyMode()
            EnergyManager.disableLightEfficiencyMode()
        }
    }
}
```

Dans une `DecoratedWindow`, lisez `isMinimized` et `isFocused` depuis `nucleusWindow`
(`minimizedFlow`, `focusFlow`). Les appels manuels à `enable` et `disable` sont à apparier
vous-même.

## Exécuter un bloc à priorité réduite

```kotlin
// Thread dédié de basse priorité ; I/O non ralenties
val report = EnergyManager.withEfficiencyMode { computeHeavyReport() }

// Mode léger au niveau du process pendant le bloc, sur la coroutine appelante
EnergyManager.withLightEfficiencyMode { syncDataFromServer() }
```

Les deux helpers rétablissent le mode précédent quand le bloc se termine ou lève une exception.

## Garder le système éveillé

```kotlin
EnergyManager.keepAwake(AwakeMode.SYSTEM_AND_DISPLAY) // l'écran reste allumé (défaut)
EnergyManager.keepAwake(AwakeMode.SYSTEM_ONLY)        // l'écran peut s'éteindre ou se verrouiller
EnergyManager.releaseAwake()
```

`keepAwake` occupe un seul emplacement : un second appel remplace le mode, et un seul
`releaseAwake()` supprime la demande. Sur macOS, fermer le capot met quand même en veille en
`SYSTEM_ONLY`.

## Tenir plusieurs demandes d'éveil à la fois

Prenez un handle par fonction indépendante, comme un lecteur et un téléchargement :

```kotlin
val playback = EnergyManager.acquireAwake(AwakeMode.SYSTEM_AND_DISPLAY)
EnergyManager.acquireAwake(AwakeMode.SYSTEM_ONLY).use { exportProject() }
playback.close()
```

La demande à l'OS utilise le mode le plus fort demandé par un handle actif, et prend fin quand
tous les handles sont fermés et qu'aucun `keepAwake` ne reste. `close()` est idempotent et
thread-safe.

## Garder l'écran allumé depuis un composable

```kotlin
Box(Modifier.keepScreenOn()) { Player() }
```

L'écran reste allumé tant que le modifier est dans la composition. Les demandes de plusieurs
fenêtres ne se libèrent jamais entre elles et ne touchent pas votre emplacement `keepAwake`.

  systemd-logind ; le repli X11 par économiseur d'écran ne peut pas le servir.
- `Modifier.keepScreenOn()` partage un seul handle `acquireAwake(SYSTEM_AND_DISPLAY)` entre
  fenêtres et popups. Si l'OS refuse, il journalise en `FINE` et n'a pas d'autre effet.

## Référence de l'API

| Méthode | Description |
|---|---|
| `isAvailable(): Boolean` | Indique si le pont natif s'est chargé. |
| `enableEfficiencyMode()` / `disableEfficiencyMode()` | Mode complet du process. |
| `enableLightEfficiencyMode()` / `disableLightEfficiencyMode()` | Mode léger du process. |
| `enableThreadEfficiencyMode()` / `disableThreadEfficiencyMode()` | Le thread appelant seulement. |
| `withEfficiencyMode { }` (suspend) | Exécute le bloc sur un thread dédié en mode par thread. |
| `withLightEfficiencyMode { }` (suspend) | Applique le mode léger au process pendant le bloc. |
| `keepAwake(mode = SYSTEM_AND_DISPLAY)` / `releaseAwake()` | Un emplacement d'éveil partagé ; le dernier mode l'emporte. |
| `acquireAwake(mode = SYSTEM_AND_DISPLAY): AwakeHandle` | Une demande indépendante, libérée par `close()`. |
| `isAwakeActive(): Boolean` | Indique si une demande d'éveil est tenue. |
| `keepScreenAwake()` / `releaseScreenAwake()` / `isScreenAwakeActive()` | Redirections dépréciées vers `keepAwake`, `releaseAwake`, `isAwakeActive`. |

`enable`, `disable`, `keepAwake` et `releaseAwake` renvoient un `EnergyManager.Result` avec
`success`, `errorCode` et `message`. Sur une plateforme non prise en charge, `success` vaut
`false` et `errorCode` vaut `-1`. `AwakeHandle` a `mode`, `isActive` et `close()`.
