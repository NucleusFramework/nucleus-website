The Nucleus Gradle plugin (`id("dev.nucleusframework")`) adds one extension, `nucleus { }`, that configures the run task, packaging, signing, publishing and GraalVM native images. This page lists its properties block by block, in source order; [Configuration](/docs/start/configuration) shows them in a working build script.

All DSL types live in `dev.nucleusframework.desktop.application.dsl`.

## `nucleus { }` [#nucleus]

`dev.nucleusframework.NucleusExtension`:

| Member | Type | Notes |
| --- | --- | --- |
| `application { }` | `JvmApplication` | JVM app: run task, packaging, GraalVM |
| `nativeApplication { }` | `NativeApplication` | Kotlin/Native macOS app |
| `dependencies` | `NucleusPlugin.Dependencies` | Runtime module coordinates |

### `nucleusOptimization { }` [#nucleusoptimization]

`nucleusOptimization = true` turns on five startup knobs at once. Each knob in the block is a `Boolean?`: `null` follows the master switch, `true` or `false` forces that knob regardless of the others.

```kotlin
nucleus.application {
    nucleusOptimization = true
    nucleusOptimization { idleGc = false }
}
```

| Knob | Effect |
| --- | --- |
| `serialGc` | Serial GC when `garbageCollector` is unset. An explicit collector wins |
| `compactHeap` | Adds `-Xms32m` and `-XX:MaxRAMPercentage=25`, unless `jvmArgs` already sets them |
| `singleJar` | Flattens the runtime JARs (or sets `joinOutputJars` when ProGuard is on) so the jpackage image holds one JAR |
| `idleGc` | Requests a GC 3 s after the last window loses focus, or at once when a window is minimized. Also baked into GraalVM images |
| `lastJdk` | Packages and runs with OpenJDK 27, downloaded to `<gradle-user-home>/nucleus/jdk` (BellSoft Liberica JDK 27 on Intel macOS and Windows ARM). `javaHome` wins. The Gradle compile JDK does not change |

The pack leaves `enableAotCache` and ProGuard alone. See [Startup optimization](/docs/performance/startup).

### `nodejs { }` [#nodejs]

`NodeJsSettings` controls the Node.js that runs electron-builder, which every format except `RawAppImage` needs.

| Property | Type | Default | Notes |
| --- | --- | --- | --- |
| `autoDownload` | `Property<Boolean>` | `true` | Download from `nodejs.org` and cache it. `false` uses `node` and `npm` from `PATH` |
| `version` | `Property<String>` | `"22"` | A major line (`"22"`), `"lts"`, or a pinned release (`"22.11.0"`) |
| `installDir` | `DirectoryProperty` | `<gradle-user-home>/nucleus/nodejs` | Download cache |

The plugin looks for Node.js in this order: the `compose.electronBuilder.nodePath` Gradle property, the `NUCLEUS_NODE_HOME` environment variable, this block, then `PATH` (also the fallback when the download fails). A floating version stays pinned once downloaded; delete its directory under `installDir` to pick up a newer release. See [Provision Node.js](/docs/packaging#provision-nodejs).

### `TargetFormat` [#targetformat]

18 formats, in source order:

`RawAppImage`, `Pkg`, `Deb`, `Rpm`, `Dmg`, `Exe`, `Msi`, `Nsis`, `NsisWeb`, `Portable`, `AppX`, `AppImage`, `Pacman`, `Snap`, `Flatpak`, `Zip`, `Tar`, `SevenZ`.

jpackage builds `RawAppImage`, the bare app image. electron-builder builds every other format from it. `AppX` and `Flatpak` always go through the sandboxed pipeline; `Pkg` does only when `macOS { pkg { appStore = true } }`, the default.

<Callout type="warn" title="Changed in 3.0">
`TargetFormat.isStoreFormat` is deprecated at `ERROR` level and no longer compiles. A PKG is a store format only when `pkg.appStore` is `true`, so branch on the DSL value instead. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

### `pkg { }` [#macos-pkg]

`PkgSettings` picks the PKG distribution channel.

| Property | Type | Default | Notes |
| --- | --- | --- | --- |
| `appStore` | `Boolean` | `true` | `true`: Mac App Store build, sandboxed, re-signed with `productsign`, not notarized. `false`: Developer ID build, same pipeline as DMG, installer signed with the Developer ID Installer certificate and notarized by `notarizePkg` |
| `preInstall` | `RegularFileProperty` | unset | Script run as root before the payload is copied. Needs a shebang |
| `postInstall` | `RegularFileProperty` | unset | Script run as root after the payload is copied |

The App Store rejects packages that carry install scripts, so the plugin fails configuration when `preInstall` or `postInstall` is set with `appStore = true`. Each script runs once per install.

```kotlin
macOS {
    pkg {
        appStore = false
        preInstall.set(file("packaging/macos/preinstall"))
        postInstall.set(file("packaging/macos/postinstall"))
    }
}
```

See [Choose a PKG channel](/docs/packaging/macos#choose-a-pkg-channel).

### `appExtensions { }` [#macos-app-extensions]

`MacAppExtensionSettings` embeds prebuilt `.appex` bundles in `Contents/PlugIns/`. Nucleus copies and signs them; it does not build them.

| Member | Notes |
| --- | --- |
| `extension(name) { }` | Declares one `MacAppExtension`. `name` appears in diagnostics only |
| `appex(File)` | The `.appex` bundle to embed |
| `entitlements(File)` | Entitlements for the extension, separate from the app's |
| `provisioningProfile(File)` | Optional, embedded as `Contents/embedded.provisionprofile` inside the extension |

```kotlin
macOS {
    appExtensions {
        extension("NetworkFilter") {
            appex(file("build/appex/NetworkFilter.appex"))
            entitlements(file("packaging/extension/NetworkExtension.entitlements"))
            provisioningProfile(file("packaging/NetworkFilter.provisionprofile"))
        }
    }
}
```

Each extension is signed with its own entitlements, then the app is sealed without `--deep`. The extension exists only inside a signed `.app`: use `runDistributable`, not `run`. See [Embed app extensions](/docs/packaging/macos#embed-app-extensions).

### `notarization { }` [#macos-notarization]

`MacOSNotarizationSettings` accepts one of three credential sets, all `Property<String>`:

- Apple ID: `appleID`, `password`, `teamID`
- `notarytool` keychain profile: `keychainProfile`, optional `keychainPath`
- App Store Connect API key: `apiKey`, `apiKeyId`, `apiIssuer`

`ascProvider` is deprecated at `ERROR` level; use `teamID`.

## `nativeApplication { }` [#native-application]

`NativeApplication` packages a Kotlin/Native app. Only macOS targets are supported.

- `targets(vararg KotlinTarget)`: each must be a `KotlinNativeTarget` of `Family.OSX`.
- `distributions { }`: `NativeApplicationDistributions`, with the [shared metadata](#shared-metadata) and a `macOS { }` block limited to the `AbstractMacOSPlatformSettings` members (no `pkg`, `appExtensions`, `launchAgents` or entitlements).

## Generated app properties [#app-properties]

The plugin writes `nucleus/nucleus-app.properties` into the app resources. The `NucleusApp` runtime object reads it at startup, which is how DSL values reach the runtime libraries. Keys: `app.id`, `app.version`, `app.vendor`, `app.description`, `app.name`, `app.aumid`, `startup.wm.class`, `startup.task.id`, and `optimization.idleGc` when the `idleGc` knob is on.
