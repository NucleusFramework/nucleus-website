## v2.5.13

**Released: 2026-09-04**

### Bug fixes

- **Windows freeze on IME commit and taskbar restart** (#644) — two more instances of the
  #640 lock class: the window-state lock was held across `ImeHandler::process_message`, which
  peeks the queue on `WM_IME_ENDCOMPOSITION` (the Korean IME sends the committed string after
  the end message, so the queue decides whether to defer), and across `set_skip_taskbar` on
  `TaskbarCreated`, where the `CoCreateInstance` + `ITaskbarList` STA call pumps the queue
  while it waits. Both re-entered the window procedure and re-locked a non-reentrant mutex,
  parking the event-loop thread in `WaitOnAddress` for good. The IME commit-pending flag is
  now computed before the lock is taken and passed in, and the skip-taskbar flag is read out
  before the COM call. Wider blast radius than #640: nearly every IME arm took that lock.
  Ported from tauri-apps/tao#1215 and #1264. See
  [Text input](/docs/tao/decorated-window#text-input).
- **Windows freeze on a keyboard-triggered nested message** (#640) — `PeekMessageW` delivers
  pending cross-thread *sent* messages inline, re-entering the window procedure before the
  peek returns. The keyboard callback held the global `KEY_EVENT_BUILDERS` map and the
  key-press/release arms held `LAYOUT_CACHE` across such a peek, so the nested dispatch
  deadlocked the event-loop thread against itself and the window stayed "Not Responding".
  Reported as a freeze when moving a window between Windows 11 virtual desktops. The builder
  is now taken out of the map for the duration and put back only if the slot still exists, and
  the layout-cache guard ends before the peek. Only injected or sent key messages can nest
  here, and they are now dropped instead of hanging the process.

## v2.5.12

**Released: 2026-09-01**

### Bug fixes

- **`alwaysOnTop` dropped on Windows** (#631) — three layers lost `WS_EX_TOPMOST`:
  `DecoratedWindowComposable` created every window with a hardcoded `alwaysOnTop = false` and
  applied the real value from a later `LaunchedEffect`, losing the race against creation-time
  style rewrites (acrylic, skip-taskbar); tao only issues its z-order `SetWindowPos` on a
  `WindowFlags` cache diff, and asynchronously, so an external rewrite that dropped the
  topmost band was never repaired. The initial value is now passed at window creation,
  `setAlwaysOnTop` also applies the z-order synchronously, and the band is re-asserted after
  the known clobber sites — every resize, and the backdrop apply, teardown, and
  survivor-restore paths. See
  [Platform behavior](/docs/tao/overlay-windows#platform-behavior).
- **Input starving with two windows open on Windows** (#632) — any snapshot write in the
  process wakes every scene's `Recomposer` through the global apply observer, and the Windows
  host rendered and presented those frames unconditionally. Each `eglSwapBuffers` at interval
  1 parks the shared event-loop thread until the next VBlank, so every visible window
  re-presented at the animating window's rate and the VBlank waits serialized (a dashboard
  lagging while a small always-on-top window was visible). The scene bundle now tracks a
  visual-dirty flag fed by its `invalidateLayout` / `invalidateDraw` callbacks and the host
  skips the present for a frame with no visual change. Presents that must swap regardless are
  kept: a size or scale apply, the OS modal resize/move loop, a resolved clear-colour change,
  and the first swap after `show()`. See
  [How it works](/docs/tao/decorated-window#how-it-works).

## v2.5.11

**Released: 2026-08-31**

### New features

- **`menuCategory` and `shortcutName` on the NSIS targets** (#630) — follow-up to #629. The
  NSIS targets exposed most installer settings but not these two, so a start-menu group could
  not be declared at all and the shortcut always landed in the start menu root — a blocker for
  projects moving their MSI packaging to the recommended NSIS format while keeping the folder
  they had under jpackage. Both are emitted for `nsis` and `nsis-web`, default to `null`
  (nothing emitted, so existing installers are unchanged), and `windows.menuGroup` acts as the
  default `menuCategory` exactly as it does for MSI. See
  [Customize the NSIS installer](/docs/packaging/windows#customize-the-nsis-installer).

## v2.5.10

**Released: 2026-08-31**

### Bug fixes

- **MSI installer options** (#629) — the MSI target only forwarded `upgradeCode` and
  `perMachine` to electron-builder, so every other Windows installer setting fell back to
  an electron-builder default: `windows.menuGroup` was ignored and the shortcut landed in
  the start menu root, `oneClick` defaulted to `true` so the installer ran with no UI, and
  `runAfterFinish` launched the app as soon as the install finished. `MsiSettings` now
  emits `oneClick`, `runAfterFinish`, `createDesktopShortcut`, `createStartMenuShortcut`,
  `menuCategory`, and `shortcutName`. Defaults match electron-builder unless a project
  opts in; `windows.menuGroup` is the default `menuCategory`. `windows.menu` /
  `windows.shortcut` stay unmapped (jpackage `false` vs electron-builder `true`). See
  [Build an MSI for enterprise deployment](/docs/packaging/windows#build-an-msi-for-enterprise-deployment).

## v2.5.9

**Released: 2026-08-31**

### Bug fixes

- **Fatal dialog stack trace** (#627) — the 2.5.8 native dialog stuffed the throwable into
  the message line. On Linux that doubled the title ("Fatal Error" twice on WMs that draw
  dialog titlebars) and the unbounded secondary label sized the dialog to the whole screen.
  The payload is now a short message plus `Throwable.stackTraceToString()`: all three
  platforms render the trace in a bounded scrollable monospace view with a Copy button
  (`NSAlert` via an out-of-process `osascript` child on macOS, an in-memory `DLGTEMPLATE`
  on a fresh thread on Windows, `GtkMessageDialog` on Linux). Compact fallbacks
  (`CFUserNotification` / `MessageBoxW`) keep the `toString()` summary, capped at 2000
  chars so a `VerifyError` bytecode dump cannot silently hide the box. See
  [Handle uncaught exceptions](/docs/tao/decorated-window#handle-uncaught-exceptions).

## v2.5.8

**Released: 2026-08-31**

### New features

- **Native fatal-error dialog** (#622 / #623) — an exception that escaped a Tao event
  dispatch used to be cleared at the JNI boundary, leaving a frozen, silent, unclosable
  window. The default path now logs the stack at `SEVERE`, shows a blocking native dialog
  (`CFUserNotification` on macOS, `MessageBoxW` on a dedicated thread on Windows,
  `GtkMessageDialog` on Linux), exits the Tao loop, and rethrows so `nucleusApplication` /
  `taoApplication` end with exit code 1. The dialog is shown after the loop has exited — a
  modal pump inside a tao callback deadlocks the main thread. Skip it with
  `-Dnucleus.tao.fatalErrorDialog=false` for unattended runs. See
  [Handle uncaught exceptions](/docs/tao/decorated-window#handle-uncaught-exceptions).
- **`WindowExceptionHandlerFactory`** (#621 / #625) — Tao mirror of Compose Desktop's AWT
  factory. Provide `LocalWindowExceptionHandlerFactory` to catch failures during layout,
  draw, input, IME, and accessibility; a handler that returns normally drops the frame and
  keeps the window alive. Composition failures still kill the recomposer (Compose's own
  design); swallowing one logs at `SEVERE` instead of leaving a window that never updates.
  The default factory rethrows into the fatal dialog. `@ExperimentalComposeUiApi`. See
  [Handle uncaught exceptions](/docs/tao/decorated-window#handle-uncaught-exceptions).

## v2.5.7

**Released: 2026-08-30**

### Bug fixes

- **Popup render re-entry on a scrollbar drag** (#620) — dragging a scrollbar inside a `TrayApp`
  popup scrolls synchronously inside the pointer event, and the `LaunchedEffect`s of the lazy
  items subcomposed by that scroll scheduled a frame the standalone pump rendered inline. Measure
  and layout re-entered while the first pass was still on the stack, throwing
  `performMeasureAndLayout called during measure layout` and leaving the drag with a non-zero
  pending scroll. Every scene entry point of the standalone hosts — pointer, scroll, key dispatch,
  and `setContent` — now runs under the pump's re-entrancy guard, so a frame scheduled mid-pass is
  posted to the Tao main queue instead. See [Notes](/docs/os/tray-app#notes).

## v2.5.6

**Released: 2026-08-30**

### Bug fixes

- **Linux IME preedit** (#558 / #613) — the Linux backend pinned `gtk::IMContextSimple`, GTK's
  built-in fallback, which never reaches the system input method: CJK input was not degraded but
  impossible, and typing `aiueo` then confirming left a stray `a`. The backend now uses
  `gtk::IMMulticontext` — ibus or fcitx5 through the GTK immodule on X11, the text-input-v3 client
  on Wayland — and routes its signals into the same `ImePreedit` / `ImeCommit` events as macOS and
  Windows. Keys the input method consumed no longer reach Compose, including the orphan key
  releases Wayland delivers for a filtered press, and the candidate window follows the caret. See
  [Text input](/docs/tao/decorated-window#text-input).
- **Linux candidate window covering the caret** (#613) — GTK places its windows around a cursor
  *area* in logical pixels relative to the toplevel `GdkWindow`, not a point in physical pixels
  relative to the client area, so the candidate list landed on the composition it described. The
  caret rect is scaled and translated by the content widget's allocation, matching the correction
  the Wayland subsurface already applies. See
  [Text input](/docs/tao/decorated-window#text-input).
- **Linux modifier state drift** (#613) — `ModifiersChanged` was emitted only when the key itself
  was a modifier, so Compose tracked Ctrl, Shift, Alt, and Super from press and release
  bookkeeping. Input methods on X11 re-inject the events they forward, and a dropped Control
  release left Compose believing Ctrl was held for the rest of the session: a plain Return read as
  Ctrl+Return. The state is now derived from the GDK modifier mask carried by every event, so it
  self-heals on the next keystroke.
- **macOS press-and-hold accents** (#611 / #612 / #617) — Nucleus forced `ApplePressAndHoldEnabled`
  in four preference domains and guessed from a state machine when the accent picker was active.
  A held letter then did nothing at all on keyboards where the picker cannot engage, and ordinary
  fast typing armed the picker flag and routed the next commit into the replace path, deleting the
  character just committed ("Xcode" landing as "Xcde"). Nucleus no longer reads or writes the user
  default — the OS decides whether a held letter repeats or opens the picker — and the pick is
  applied from the `replacementRange` AppKit sends with `insertText:`, select-then-insert. See
  [Text input](/docs/tao/decorated-window#text-input).
- **Sub-pixel pointer jitter eating clicks** (#615 / #619) — Tao reports cursor positions in
  1/1024 px and macOS emits a `CursorMoved` before every `mouseDown` and `mouseUp`, so a click
  drifting a fraction of a pixel produced a real move delta, started a parent drag gesture, and
  cancelled the tap: selections needed two clicks. Moves under 1 dp from the last dispatched
  position are now suppressed, and `viewConfiguration.touchSlop` is density-scaled to 18.dp
  instead of 18 raw pixels, which had halved every drag and scroll threshold on 2x displays. See
  [How it works](/docs/tao/multi-touch#how-it-works).
- **Linux tray popup scroll** (#610) — standalone, overlay, and owner-based popups now feed wheel
  events through the same AWT-shaped dispatch as `TaoWindow`, with the Windows lines-per-notch
  value from `LocalScrollConfig`. Standalone popup frames paint inline when the caller is already
  on the main thread, so a wheel flood cannot starve `MainEventsCleared`. See
  [Notes](/docs/os/tray-app#notes).
- **Auto-launch at half size on GNOME** (#614 / #616) — `graphical-session.target` is reached
  before `gsd-xsettings` writes `Xft.dpi` into the X resource database, so a HiDPI app started at
  login froze `sun.java2d.uiScale` at 1.0 while a manual launch was always correct. The generated
  systemd user unit is ordered after `gnome-session-x11-services-ready.target`. systemd ignores
  ordering on units that are not loaded, so this is a no-op on other desktops. See
  [Notes](/docs/lifecycle/auto-launch#notes).

## v2.5.5

**Released: 2026-08-28**

### Bug fixes

- **macOS tray popup and Show Desktop** (#609) — the standalone `NSPanel` had the default
  collection behavior, so "Click wallpaper to reveal desktop" on Sonoma and later Exposé-slid the
  popup away while Compose was already fading it. The panel is now stationary, joins all spaces,
  is fullscreen-auxiliary, and is ignored by window cycling, so `TrayApp` dismisses it itself. See
  [Notes](/docs/os/tray-app#notes).
- **macOS tray popup dismissed by its own icon** (#609) — the outside-click monitor counted a
  `mouseDown` on the `NSStatusItem` and on its native context menu as a click outside the panel,
  so a right-click hid the popup before the menu appeared. Those windows are skipped for
  standalone panels; the left-click toggle stays with the tray callback. See
  [Notes](/docs/os/tray-app#notes).

## v2.5.4

**Released: 2026-08-27**

### Bug fixes

- **Linux inbound drop on tray popups** (#605 / #607) — a `TrayApp` popup on Linux is an
  override-redirect X11 window, so GTK `gtk_drag_dest_set` cannot attach. Inbound XDND 5 is
  implemented on the panel event thread and dispatched through `TaoSceneDnD`, matching
  `DecoratedWindow`. See [How it works](/docs/tao/drag-and-drop#how-it-works).

  `scrollingDelta`. `TaoWindow` already reshapes those to AWT `preciseWheelRotation` (negate Y,
  physical /10 for precise deltas). Tray and overlay popups now use the same mapping, so wheel
  sign and trackpad magnitude match the main window. See [Notes](/docs/os/tray-app#notes).

- **Inbound drop on Windows and macOS tray popups** (#604) — `TrayApp` popups are ownerless

## v2.5.0

**Released: 2026-08-26**

### New modules

- **Spell check** (`nucleus.spellcheck`) — checks spelling through the engine each OS already
  ships: Hunspell on Linux (loaded with `dlopen`, no compile-time dependency), `NSSpellChecker`
  on macOS, and the Windows Spell Checking API. Ships a `SpellcheckContextMenu` wrapper that adds
  suggestions and "Add to dictionary" to a Compose text field's context menu, plus an engine API
  (`SpellChecker`, `SpellcheckSession`) usable without Compose. `nucleus-application` exposes it
  as an `api` dependency, so no extra Gradle line is needed. Where no engine is available every
  operation is a no-op rather than an error. See
  [Spell check](/docs/os/spell-check#check-a-text-field).
    - Per-field and process-wide language override via `locale` / `SpellChecker.locale`. See
      [Choose the check language](/docs/os/spell-check#choose-the-check-language).
    - `SpellcheckMenuPlacement` puts suggestions above or below Cut/Copy/Paste. See
      [Place the menu items](/docs/os/spell-check#place-the-menu-items).
    - The "Add to dictionary" label is localized for 45+ locales; user words persist to
      `~/.config/nucleus/spellcheck/<tag>.dic`.

### New features

- **Native context menus** (#542, #544, #545, #547) — `nativeContextMenu = true` on
  `DecoratedWindow` / `HostedWindow` replaces the Compose-drawn context menu with the platform's:
  a real `NSMenu` on macOS, and a Compose flyout styled as Fluent on Windows, Adwaita on GTK
  desktops, and Breeze on Qt desktops. Covers `ContextMenuArea`, text-field Cut/Copy/Paste, and
  spellcheck items. Tao backend only; accepted and ignored on AWT. See
  [Context menus](/docs/window/context-menu#turn-on-the-native-menu).
    - `NucleusContextMenuItem`, `NucleusContextMenuDivider`, and `NucleusContextMenuSubmenu` build
      items with icons and lazy submenus. See
      [Add your own items](/docs/window/context-menu#add-your-own-items).
    - Stock icons carry their platform shortcut label (`⌘C` / `Ctrl+C`), overridable per item.
      Drawn on the Windows and Linux flyouts. See
      [Show keyboard shortcuts](/docs/window/context-menu#show-keyboard-shortcuts).
    - New `LinuxUiToolkit` in `core-runtime` reports whether the session is Gtk or Qt, which is
      also how the Linux menu style is chosen. See
      [Detect the Linux toolkit](/docs/window/context-menu#detect-the-linux-toolkit).
    - `menu-macos` gained the popup primitives behind it: `NativePopupMenuItem`,
      `popUpNativeMenu`, `isNativePopupMenuAvailable`.
- **Overlay windows** (#564, #568) — new window flags for watermarks, desktop widgets, and
  heads-up overlays: `clickThrough` (pointer events pass through), `alwaysOnBottom` (below normal
  windows, mutually exclusive with `alwaysOnTop`), and `visibleOnAllWorkspaces`. All three are
  reactive, with imperative `TaoWindow` setters alongside. See
  [Overlay windows](/docs/tao/overlay-windows#build-a-click-through-watermark).
    - `transparent` is now exposed on the backend-agnostic `DecoratedWindow` and the Material and
      Jewel window wrappers, not just the Tao composable. A fully transparent window drops the
      contour that traced the rectangular window instead of the content, and Compose scenes are
      told the window is transparent so dialog scrims blend against alpha (#559, #561).
    - `forceX11` gives one window an XWayland surface without moving the whole process off
      Wayland, and `TaoWindow.isNativeWaylandSurface` reports what it actually got. Flags that
      cannot work on a native Wayland surface log once per window with the reason. See
      [Take an X11 surface on Wayland](/docs/tao/overlay-windows#take-an-x11-surface-on-wayland).
- **Compose over native views** (#587) — the `NativeView` `content` slot now draws in the
  window's own Compose scene on all three platforms, so Compose siblings declared after the view
  and in-scene `Popup`s paint over it, and overlay content claims its own pointer events. Linux
  supports the `content` slot at all for the first time (Wayland only).
  `Modifier.consumeOverlayPointerEvents()` is deprecated and no longer needed. See
  [Overlay Compose content](/docs/tao/native-views#overlay-compose-content).
- **Linux clipboard through GTK** (#582, #583) — the Tao clipboard on Linux goes through GDK
  instead of AWT, so copy and paste work in a Wayland-native window and in a session with no
  XWayland. Images (as PNG) and file lists (`text/uri-list` plus the GNOME copied-files target)
  are carried in both directions alongside plain text. No API change: use Compose's
  `LocalClipboard`. See [Copy and paste](/docs/tao/wayland#copy-and-paste).
- **`EnergyManager.acquireAwake`** — returns an `AwakeHandle` that holds one awake request until
  it is closed, so independent features can each keep the machine awake without releasing each
  other. `keepAwake` keeps its single last-writer-wins slot. This also backs Compose's
  `Modifier.keepScreenOn`, which the Tao backend now implements. See
  [Hold several awake requests at once](/docs/lifecycle/energy-manager#hold-several-awake-requests-at-once).
- **Custom scheduler command** (#540) — `SchedulerConfig.executablePath` and
  `executableArguments` point the OS scheduler at a custom launcher instead of the current
  executable. Set them before the first `enqueue`; values are baked into the generated
  plist, unit, or task. See [SchedulerConfig](/docs/lifecycle/scheduler#schedulerconfig).
- **Compose 1.12** (#354, #550, #551, #555) — `decorated-window-tao` moves to Compose
  Multiplatform 1.12, with frames driven through `SingleComposeSceneRenderingScope` and the new
  `RectManager` delayed dispatch kept off the AWT event thread.
- **`jdk.unsupported` in the default runtime modules** — `sun.misc.Unsafe` is required by JNA,
  Jewel, and many common libraries, so the module is included by default rather than discovered
  through a runtime failure. See the
  [`nativeDistributions { }` reference](/docs/start/configuration#nativedistributions---reference).

### Breaking changes

- **`GenericProvider` requires `https`** — a non-`https` update origin now throws
  `IllegalArgumentException` at construction. The manifest, checksums, and artifact all come from
  that one origin, so plain `http` lets an on-path attacker rewrite the three together and the
  SHA-512 protects nothing. `http` is still accepted for loopback hosts so integration tests can
  serve fixtures without TLS. See [Providers](/docs/packaging/auto-update#providers).

### Bug fixes

- **Self-update scripts written to a private directory** — the detached update script and its log
  went to a fixed path in the shared temp directory (`/tmp/nucleus-update.sh` on Linux), which
  another local user can pre-create as a symlink or a file they own, turning the update into local
  code execution as the app's user. Each run now gets a fresh owner-only (`0700`) directory.
- **Windows update script escaping** — manifest-derived paths are escaped before they reach
  PowerShell.
- **Linux root update helper** — closed a time-of-check/time-of-use window and a downgrade path
  in the privileged helper.
- **Linux update helper leaked a gpg-agent** — the signature check no longer leaves a gpg-agent
  running inside the app's systemd scope.
- **MPRIS invalid D-Bus name** (#548) — an app id that is not a valid D-Bus name no longer hangs
  media-control startup on Linux.
- **Context menu dismissal and first right-click** — the flyout closes when the owning window
  loses focus, and the macOS menu opens on the first right-click in an app that is not yet
  active.
- **Tao fixes** — the dialog close button animates its hover like `DecoratedWindow`; a native
  session that swallows a mouse-up no longer leaves a stuck button; Adwaita separators follow
  libadwaita's `currentColor` rule.

## v2.1.7

**Released: 2026-07-26**

### Breaking changes

- **GraalVM Community Edition is now the default toolchain** (#403) — the auto-provisioned toolchain was Oracle GraalVM, governed by the GraalVM Free Terms and Conditions. The GFTC only allows redistributing the Program provided you do not charge your licensees any fees associated with such distribution or use, and the plugin copies GraalVM runtime libraries next to the packaged executable — so that clause silently reached every app built with Nucleus. GraalVM CE (GPLv2 + Classpath Exception) carries no such restriction and is now the default via `GraalvmDistribution.COMMUNITY`. Oracle GraalVM stays available behind an explicit opt-in that logs a licensing warning. `-O3`, `--pgo` and `-H:AdvancedObfuscation` degrade to a warning under a community toolchain, and `runWithPgoInstrument` is not registered at all. The distribution is embedded in the install directory and the CI cache key so an existing Oracle download is never reused, and a `GRAALVM_HOME` whose distribution disagrees with the DSL is ignored.

### Improvements

- **Lazy toolchain provisioning** (#403) — every toolchain provider now resolves in `doFirst`, so an IDE sync or `gradlew tasks` no longer downloads a JDK.

### Bug fixes

- **Survive GitHub API rate limits when resolving Community Edition** (#403) — a pinned version (`"25.0.2"`) now constructs the download URL directly instead of listing releases, making the documented pin-a-version workaround work offline; the native-image build steps pass `GITHUB_TOKEN` so the releases API call is authenticated. Floating versions (`"25"`, `"25i1"`) still need the API.
- **Decode Mach-O `cpu_type` in the file's own byte order** (#402) — `MH_CIGAM_64` is the byte-swapped magic that every little-endian macOS dylib starts with on disk, so `cpu_type` was read swapped and every thin dylib reported `arch=UNKNOWN`. Cross-checked against `lipo` on 57 real dylibs: 44 decoded wrong before, all 57 are correct now. Also recognizes `FAT_MAGIC_64` alongside `FAT_MAGIC`, and hoists the path-plus-header merge into `NativeLibArchDetector.detectEntry` so the strip transform shares it.
- **Extract the target-arch native lib, not the first match** (#401) — native libs whose JAR path carries an arch but no OS token were extracted for the wrong architecture: `detectInfo` discarded the path-detected arch whenever the OS was `UNKNOWN`, and the 64-byte header buffer was too small to reach the PE machine field. An ARM64 DLL could therefore win the flattening race on an x64 target and fail to load. `detectInfo` now merges path and header information field by field and reads 4096 header bytes. Fixes #399.

## v2.1.6

**Released: 2026-07-23**

### New features

- **Advanced obfuscation for native images** (#389) — `graalvm { advancedObfuscation = true }` passes `-H:AdvancedObfuscation=` (Oracle GraalVM only, gated on the resolved toolchain and warning otherwise) so the symbol names baked into the binary — stack traces, heap dumps, `Class#getName`, strings — are obfuscated. Reflection and JNI names from the reachability metadata are preserved automatically, so it is JNI-safe by construction. `-H:+UnlockExperimentalVMOptions` is passed alongside it, and `--enable-sbom=export` keeps the SBOM as a build artifact instead of embedding it and re-leaking the dependency list obfuscation hides.
- **Obfuscate-safe ProGuard rules** (#389) — when `proguard { obfuscate = true }`, a bundled `nucleus-obfuscation-safety-rules.pro` is injected automatically to preserve framework names (`androidx.**`, `kotlinx.**`) while still allowing shrinking and optimization, so the Compose and Kotlin runtimes survive renaming and only the app's own packages get obfuscated. Prevents `ClassNotFoundException: androidx.compose.runtime.Composer`. Not injected when obfuscation is off.
- **Desktop-appropriate default max heap for native images** (#390) — native-image's Serial GC defaults the max heap to 80% of physical RAM, far above a desktop app's norm. Nucleus now bakes `-R:MaximumHeapSizePercent=25` for parity with HotSpot's `MaxRAMPercentage`, configurable via `graalvm { maxHeapSizePercent = N }` or an absolute `graalvm { maxHeapSize = "2g" }` (which takes precedence). Both are defaults only, still overridable at runtime with `-Xmx`.
- **`--enable-native-access=ALL-UNNAMED` baked into native images** (#390) — native modules call `System.loadLibrary` from the unnamed module, which since JDK 24 (JEP 472) emits a restricted-method warning and will be blocked in a future release. The JVM run path already passed the flag; the native binary now starts clean too.
- **Pause the render loop while the window is minimized** (#384) — each platform scene host gates its frame body on `window.isMinimized` before the frame-clock tick, so Compose animations park instead of recording and presenting into a hidden surface. This matters most on Windows, where ANGLE's flip-model swapchain never reports occlusion and there is no vsync back-pressure while minimized; restore re-kicks a redraw explicitly.
- **Jewel 0.39 and IntelliJ icons 262** (#395) — bumps Jewel to `0.39.1-262.9437.29`, adds the `intellij-icons-api`/`impl` dependencies that Jewel 0.39's `IntUiTheme` needs, and registers the build-time initialization and reflection entries required to avoid a `Method.invoke` segfault under SVM.

### Bug fixes

- **Scope JNI local refs on permanently-attached upcall threads** (#387) — object-creating upcalls on permanently attached threads never had their local frame popped, leaking local refs for the life of the process. The touch path was the worst: `dispatch_touch` allocated three `long[]` per event, so a sustained touch drag grew the JNI local reference table until it overflowed and aborted the JVM. Each such upcall body is now wrapped in `env.with_local_frame(...)`, covering the Linux touch and drop paths, macOS deep links, and the macOS/Windows accessibility action trampolines.
- **Clear pending JNI exceptions after accessibility and deep-link upcalls** (#385) — the accessibility and deep-link native-to-JVM callbacks invoked `NativeTaoBridge.dispatch*` without `exception_check`/`exception_clear`, unlike every other dispatch path. A throwing Kotlin handler left the exception pending on the long-lived callback thread (AT-SPI/zbus, UIA, AppKit), making the next JNI call on that thread undefined behavior and, under `panic = "abort"`, a process abort with an unrelated-looking crash site. The guard is now applied to all 18 upcall sites.
- **Migrate `-H:IncludeResources` to reachability-metadata globs** (#389) — the deprecated option warned at build time; the resource inclusion patterns moved into the module's `reachability-metadata.json` with identical semantics. The blanket font and icon globs are deliberately kept: they cover resources bundled inside library JARs, such as Jewel's SVG icons, which per-root `autoIncludeResources` does not reach.

### Improvements

- **Shared scene drag-and-drop extracted into `TaoSceneDnD`** (#386) — deduplicates the three platform scene hosts into one shared file, preserving the Linux-specific behavior where `has_files` reflects the presence of a `text/uri-list` target.
- **Jewel-specific native-image metadata moved into `decorated-window-jewel`** (#395) — the Jewel build-time initialization and reflection entries ship only with Jewel consumers; `graalvm-runtime` keeps only the generic slf4j build-time init.

## Migration guide: 1.2.x → 1.3.x

### Decorated window: monolithic module split

The `decorated-window` module has been split into three modules:

| Before (1.2.x) | After (1.3.x) |
|---|---|
| `nucleus.decorated-window` | `nucleus.decorated-window-core` (shared) |
| | `nucleus.decorated-window-jbr` (JBR implementation) |
| | `nucleus.decorated-window-jni` (JNI implementation, new) |

**Dependency update** — replace:

```kotlin
implementation("dev.nucleusframework:nucleus.decorated-window:<version>")
```

With one of:

```kotlin
// JBR-based (same behavior as before)
implementation("dev.nucleusframework:nucleus.decorated-window-jbr:<version>")

// JNI-based (no JBR dependency, works with GraalVM)
implementation("dev.nucleusframework:nucleus.decorated-window-jni:<version>")
```

**Breaking changes in `TitleBarColors`** — the following fields have been **removed**:

- `titlePaneButtonHoveredBackground`
- `titlePaneButtonPressedBackground`
- `titlePaneCloseButtonHoveredBackground`
- `titlePaneCloseButtonPressedBackground`

These platform-specific button state colors are now handled internally by each module's native implementation. If you were constructing `TitleBarColors` explicitly with these fields, remove them.

**No other code changes required** — all composable APIs (`DecoratedWindow`, `DecoratedDialog`, `TitleBar`, `DialogTitleBar`), scopes, and state types are identical. No import changes needed — the package remains `dev.nucleusframework.window`.

See [Decorated Window](/docs/window) for full details on choosing between JBR and JNI.

## v1.0.0

**Released: 2026-02-17**

Initial release — fork of the JetBrains Compose Desktop Gradle plugin, repackaged as **Nucleus** with extended packaging, distribution, and runtime features.

### Packaging and distribution

- **Electron-builder backend** — DMG, PKG, NSIS, NSIS Web, AppImage, DEB, RPM, Snap, and AppX formats. Replaces jpackage for installer generation.
- **macOS code signing and notarization** — Developer ID and App Store signing, automatic notarization via `notarytool`.
- **macOS App Sandbox** — Sandboxed PKG builds with JNI library extraction, entitlements management, and provisioning profiles.
- **Windows code signing** — SignTool integration with SHA-256 hashing.
- **AppX packaging** — Windows Store packaging with tile assets and identity configuration.
- **DMG customization** — Background images, icon positioning, window size, badge icons, and format selection.
- **Layered icons** — macOS 26+ `.icon` directory support for dynamic tilt/depth effects.
- **Splash screen** — Splash image support in JVM launcher.
- **Universal macOS binaries** — CI workflow for `lipo`-based fat binaries (Apple Silicon + Intel).
- **Type-safe DSL** — Enums for target formats, publish modes, and compression settings replace raw strings.
- **Linux packaging options** — `startupWMClass`, `debDepends`, `rpmRequires`, `debCompression`, `rpmCompression`, after-install scripts, and architecture suffixes.
- **File associations** — macOS `CFBundleURLTypes` injection and Linux/Windows file association support via electron-builder.

### Runtime modules

- **`core-runtime`** — Executable type detection, platform identification, `SingleInstanceManager`, `DeepLinkHandler`.
- **`aot-runtime`** — AOT cache mode detection for JDK 25+ (Project Leyden). AOT cache generation task with safety timeout.
- **`updater-runtime`** — Auto-update engine with GitHub and S3 providers. SHA-512 verification, progress tracking, `installAndRestart()`. Platform-specific install strategies: detached shell script on macOS, background PowerShell on Windows, AppImage replacement on Linux.

### Build and CI

- **Composite actions** — `setup-nucleus`, `update-yml`, and release publishing actions.
- **Cross-platform release workflow** — macOS (arm64 + x64 + universal), Windows (x64 + arm64), Linux (x64 + arm64).
- **Configuration cache support** — Full Gradle configuration cache compatibility.
- **Plugin version from Git tag** — No manual version management in `gradle.properties`.
