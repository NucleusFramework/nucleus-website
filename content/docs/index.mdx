Nucleus is the desktop layer for Compose Multiplatform apps written in Kotlin. Compose draws the UI.
Nucleus opens the native windows, talks to the operating system, and builds signed installers, all
from one Gradle DSL. Your app runs as a GraalVM native image or on the JVM.

To build your first app, follow the [quickstart](/docs/start/quickstart).

<Callout title="Migrating an existing app? Let an AI agent do it">
Paste one prompt into your coding agent and it migrates your app phase by phase. See
[Migrate with an AI agent](/docs/migrate/ai-agent).
</Callout>

## Features

- **Native windows without AWT**, with Wayland support, trackpad gestures, pen input,
  [native views](/docs/native-content/native-views), and [GPU textures](/docs/native-content/texture-view).
- **[Tool windows](/docs/tool-windows)**: docking palettes and Chrome-like tabs you can tear off and merge.
- **Two runtimes, one DSL**: a GraalVM native image, or the JVM with an AOT cache (JDK 25+).
- **More than 30 runtime modules**: notifications, tray, dock menus, dark mode, global hotkeys, spell check, and more.
- **18 packaging formats**, with code signing, notarization, and [differential auto-update](/docs/packaging/auto-update#differential-downloads).
- **Native design systems**: macOS 26, Fluent, Yaru, Jewel, and Material. See [Toolkits](/docs/toolkits).
- **One language across platforms**: share Kotlin code and Compose UI with your Android, iOS, and web apps.
  Moving from Compose Desktop means replacing `compose.desktop.application` with `nucleus.application`.
  See [Nucleus and vanilla Compose Multiplatform](/docs/compare/cmp-default).

## What's new in 3.0

Nucleus 3.0 breaks source and binary compatibility with 2.x. Read the
[migration guide](/docs/migrate/from-2.x) before you upgrade.

- **One window backend.** The AWT, JBR, and JNI backends and the `backend =` argument are gone.
- **No Compose Desktop windows.** Open windows with `DecoratedWindow` or `HostedWindow` instead of
  `Window`, `Dialog`, and `Tray`.
- **Callbacks on the UI thread**, and macOS Cmd+Q goes through each window's `onCloseRequest`.
- **Window state API v2** without AWT, in `dev.nucleusframework.window.tao.v2`.
- **Satellites, docking, and tabs**, as an experimental [tool window](/docs/tool-windows) API.
- **Packaging** downloads its own Node.js and adds `nucleusOptimization` and a Developer ID PKG.

Full list: [Changelog](/docs/changelog).
