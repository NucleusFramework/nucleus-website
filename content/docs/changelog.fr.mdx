Cette page liste les changements de chaque version de Nucleus, la plus récente en premier.
Chaque entrée recense les nouveaux modules, les fonctionnalités, les corrections de bugs et
les changements incompatibles de la version.

## v2.5.0

**Sortie : 2026-08-26**

### Nouveaux modules

- **Correction orthographique** (`nucleus.spellcheck`) — vérifie l'orthographe via le moteur que
  chaque OS embarque déjà : Hunspell sous Linux (chargé par `dlopen`, sans dépendance de
  compilation), `NSSpellChecker` sous macOS et l'API Windows Spell Checking. Le module fournit un
  wrapper `SpellcheckContextMenu` qui ajoute les suggestions et « Ajouter au dictionnaire » au menu
  contextuel d'un champ de texte Compose, ainsi qu'une API moteur (`SpellChecker`,
  `SpellcheckSession`) utilisable sans Compose. `nucleus-application` l'expose en dépendance `api` :
  aucune ligne Gradle supplémentaire n'est nécessaire. Sans moteur disponible, chaque opération
  devient inopérante au lieu d'échouer. Voir
  [Correction orthographique](/docs/os/spell-check#vérifier-un-champ-de-texte).
    - Langue redéfinissable par champ et pour tout le processus via `locale` /
      `SpellChecker.locale`. Voir
      [Choisir la langue de vérification](/docs/os/spell-check#choisir-la-langue-de-vérification).
    - `SpellcheckMenuPlacement` place les suggestions au-dessus ou en dessous de
      Couper/Copier/Coller. Voir
      [Placer les entrées du menu](/docs/os/spell-check#placer-les-entrées-du-menu).
    - Le libellé « Ajouter au dictionnaire » est localisé pour plus de 45 locales ; les mots
      ajoutés sont conservés dans `~/.config/nucleus/spellcheck/<tag>.dic`.

### Nouvelles fonctionnalités

- **Menus contextuels natifs** (#542, #544, #545, #547) — `nativeContextMenu = true` sur
  `DecoratedWindow` / `HostedWindow` remplace le menu contextuel dessiné par Compose par celui de
  la plateforme : un vrai `NSMenu` sous macOS, et un flyout Compose stylé Fluent sous Windows,
  Adwaita sur les bureaux GTK et Breeze sur les bureaux Qt. Couvre `ContextMenuArea`, le
  Couper/Copier/Coller des champs de texte et les entrées d'orthographe. Backend Tao uniquement ;
  accepté et ignoré sous AWT. Voir
  [Menus contextuels](/docs/window/context-menu#activer-le-menu-natif).
    - `NucleusContextMenuItem`, `NucleusContextMenuDivider` et `NucleusContextMenuSubmenu`
      construisent des entrées avec icônes et sous-menus paresseux. Voir
      [Ajouter vos propres entrées](/docs/window/context-menu#ajouter-vos-propres-entrées).
    - Les icônes standard portent le libellé de raccourci de la plateforme (`⌘C` / `Ctrl+C`),
      redéfinissable par entrée. Dessiné par les flyouts Windows et Linux. Voir
      [Afficher les raccourcis clavier](/docs/window/context-menu#afficher-les-raccourcis-clavier).
    - Le nouveau `LinuxUiToolkit` de `core-runtime` indique si la session est Gtk ou Qt, ce qui
      détermine aussi le style du menu Linux. Voir
      [Détecter le toolkit Linux](/docs/window/context-menu#détecter-le-toolkit-linux).
    - `menu-macos` gagne les primitives sous-jacentes : `NativePopupMenuItem`, `popUpNativeMenu`,
      `isNativePopupMenuAvailable`.
- **Fenêtres overlay** (#564, #568) — nouveaux drapeaux de fenêtre pour watermarks, widgets de
  bureau et overlays informatifs : `clickThrough` (les événements pointeur traversent),
  `alwaysOnBottom` (sous les fenêtres normales, exclusif avec `alwaysOnTop`) et
  `visibleOnAllWorkspaces`. Les trois sont réactifs, avec des setters impératifs sur `TaoWindow`.
  Voir [Fenêtres overlay](/docs/tao/overlay-windows#construire-un-watermark-traversant).
    - `transparent` est désormais exposé sur le `DecoratedWindow` agnostique du backend et sur les
      wrappers de fenêtre Material et Jewel, et plus seulement sur le composable Tao. Une fenêtre
      entièrement transparente perd le contour qui épousait la fenêtre rectangulaire au lieu du
      contenu, et les scènes Compose sont informées de la transparence pour que les voiles de
      dialogue se fondent sur l'alpha (#559, #561).
    - `forceX11` donne à une seule fenêtre une surface XWayland sans sortir tout le processus de
      Wayland, et `TaoWindow.isNativeWaylandSurface` indique ce qu'elle a réellement obtenu. Les
      drapeaux inopérants sur une surface Wayland native sont signalés une fois par fenêtre, avec
      la raison. Voir
      [Prendre une surface X11 sous Wayland](/docs/tao/overlay-windows#prendre-une-surface-x11-sous-wayland).
- **Compose au-dessus des vues natives** (#587) — l'emplacement `content` de `NativeView` dessine
  maintenant dans la scène Compose de la fenêtre sur les trois plateformes : les composables
  déclarés après la vue et les `Popup` de la scène peignent donc par-dessus, et le contenu
  d'overlay revendique lui-même ses événements pointeur. Linux prend en charge l'emplacement
  `content` pour la première fois (Wayland uniquement).
  `Modifier.consumeOverlayPointerEvents()` est déprécié et devenu inutile. Voir
  [Superposer du contenu Compose](/docs/tao/native-views#superposer-du-contenu-compose).
- **Presse-papiers Linux via GTK** (#582, #583) — le presse-papiers Tao sous Linux passe par GDK
  et non par AWT : copier-coller fonctionne donc dans une fenêtre Wayland native et dans une
  session sans XWayland. Les images (en PNG) et les listes de fichiers (`text/uri-list` plus la
  cible « copied-files » de GNOME) circulent dans les deux sens, en plus du texte brut. Aucun
  changement d'API : utilisez `LocalClipboard` de Compose. Voir
  [Copier-coller](/docs/tao/wayland#copier-coller).
- **`EnergyManager.acquireAwake`** — renvoie un `AwakeHandle` qui tient une demande d'éveil
  jusqu'à sa fermeture : des fonctionnalités indépendantes peuvent donc garder la machine
  éveillée sans se relâcher mutuellement. `keepAwake` conserve son slot unique où le dernier
  écrivain gagne. C'est aussi ce qui alimente `Modifier.keepScreenOn` de Compose, que le backend
  Tao implémente désormais. Voir
  [Tenir plusieurs demandes d'éveil à la fois](/docs/lifecycle/energy-manager#tenir-plusieurs-demandes-déveil-à-la-fois).
- **Commande de scheduler personnalisée** (#540) — `SchedulerConfig.executablePath` et
  `executableArguments` dirigent le scheduler de l'OS vers un launcher maison au lieu de
  l'exécutable courant. Renseignez-les avant le premier `enqueue` ; les valeurs sont figées dans
  le plist, l'unit ou la tâche générés. Voir
  [SchedulerConfig](/docs/lifecycle/scheduler#schedulerconfig).
- **Compose 1.12** (#354, #550, #551, #555) — `decorated-window-tao` passe à Compose Multiplatform
  1.12, avec des frames pilotées par `SingleComposeSceneRenderingScope` et le nouveau dispatch
  différé de `RectManager` maintenu hors du thread d'événements AWT.
- **`jdk.unsupported` dans les modules runtime par défaut** — `sun.misc.Unsafe` est requis par JNA,
  Jewel et beaucoup de bibliothèques courantes : le module est donc inclus par défaut plutôt que
  découvert via une erreur à l'exécution. Voir la
  [référence `nativeDistributions { }`](/docs/start/configuration#référence-nativedistributions--).

### Changements incompatibles

- **`GenericProvider` exige `https`** — une origine de mise à jour non-`https` lève désormais une
  `IllegalArgumentException` à la construction. Le manifeste, les sommes de contrôle et l'artefact
  viennent tous de cette même origine : en `http` simple, un attaquant en position d'interception
  réécrit les trois ensemble et le SHA-512 ne protège rien. `http` reste accepté pour les hôtes
  loopback, afin que les tests d'intégration servent des fixtures sans TLS. Voir
  [Providers](/docs/packaging/auto-update#providers).

### Corrections de bugs

- **Scripts de mise à jour écrits dans un répertoire privé** — le script de mise à jour détaché et
  son journal allaient à un chemin fixe du répertoire temporaire partagé
  (`/tmp/nucleus-update.sh` sous Linux), qu'un autre utilisateur local peut pré-créer comme lien
  symbolique ou comme fichier lui appartenant, transformant la mise à jour en exécution de code
  local sous l'identité de l'application. Chaque exécution obtient maintenant un répertoire neuf
  accessible au seul propriétaire (`0700`).
- **Échappement du script de mise à jour Windows** — les chemins issus du manifeste sont échappés
  avant d'atteindre PowerShell.
- **Helper de mise à jour root sous Linux** — fermeture d'une fenêtre time-of-check/time-of-use et
  d'un chemin de downgrade dans le helper privilégié.
- **Le helper de mise à jour Linux laissait fuir un gpg-agent** — la vérification de signature ne
  laisse plus de gpg-agent tourner dans le scope systemd de l'application.
- **Nom D-Bus MPRIS invalide** (#548) — un identifiant d'application qui n'est pas un nom D-Bus
  valide ne bloque plus le démarrage de media-control sous Linux.
- **Fermeture du menu contextuel et premier clic droit** — le flyout se referme quand la fenêtre
  propriétaire perd le focus, et le menu macOS s'ouvre dès le premier clic droit dans une
  application encore inactive.
- **Corrections Tao** — le bouton de fermeture des dialogues anime son survol comme
  `DecoratedWindow` ; une session native qui avale un mouse-up ne laisse plus de bouton bloqué ;
  les séparateurs Adwaita suivent la règle `currentColor` de libadwaita.

## v2.4.5

**Sortie : 2026-08-16**

### Corrections de bugs

- **Taille wrap-content `Dp.Unspecified`** (#535) — `DecoratedWindow` ne transmet plus
  NaN à la surface native lorsqu'un axe de `WindowState` / `DialogState` vaut
  `Dp.Unspecified`. Les axes wrap-content sont mesurés après la première composition
  puis appliqués, comme dans Compose Desktop. Voir
  [Paramètres de DecoratedWindow](/docs/tao/decorated-window#paramètres-de-decoratedwindow).
- **Molette souris discrète sous Linux** (#533) — GDK ne remplit `delta_x` / `delta_y`
  que pour les événements lisses (trackpad). Un cran de molette arrivait avec un delta
  nul, donc Compose ne défilait pas. La direction est maintenant mappée sur un delta
  unitaire.
- **Fade au survol des boutons de caption Win11** (#537) — les boutons de caption
  plateforme utilisent la durée de fade système. Voir
  [Contrôles de fenêtre](/docs/tao/window-scaffold#contrôles-de-fenêtre).

## v2.4.0

**Sortie : 2026-08-11**

### Faits marquants

- **`TaoGpuRenderContext` — GPU in-process sur le device de la scène.** Moteurs de carte,
  viewports 3D et charting peuvent allouer leurs cibles de rendu sur le `DirectContext` Skia
  et le device natif de la fenêtre (Metal / ANGLE GLES / EGL natif) sans second GPU, sans
  handle partageable et sans copie inter-device par frame. `TextureView` reste le contrat pour
  les producteurs externes. Voir [Contexte de rendu GPU](/docs/tao/gpu-render-context).
- **`AwakeMode` — garder le système éveillé sans forcer l'écran.**
  `EnergyManager.keepAwake(AwakeMode.SYSTEM_ONLY)` laisse l'écran de veille et la mise en
  veille de l'écran se comporter normalement pendant un job long. `keepScreenAwake()` reste un
  forwarder déprécié. Voir
  [Garder le système éveillé](/docs/lifecycle/energy-manager#garder-le-système-éveillé).
- **Gel de l'ABI publique.** Les modules runtime publiés tournent sous `explicitApi()` Kotlin
  avec des baselines kotlinx binary-compatibility-validator (`api/*.api`) ; `apiCheck` fait
  partie de `check` / `preMerge`. Exception : `decorated-window-jewel` tant que BCV ne lit pas
  les class files JVM 25.

### Nouvelles fonctionnalités

- **`windows.msi { perMachine }`** (#480) — DSL de scope d'install aligné sur
  `nsis { perMachine }`. `windows.perUserInstall` est déprécié (sens inversé) mais reste actif
  tant que `msi.perMachine` n'est pas défini. MSI reste per-machine par défaut. Voir
  [Construire un MSI](/docs/packaging/windows#construire-un-msi-pour-le-déploiement-en-entreprise).

### Améliorations

- **Logging JUL unifié et API tray renommée** (#491) — les modules runtime loguent via
  `java.util.logging` ; `composeNativeTrayLoggingLevel` → `nucleusLoggingLevel` /
  `NucleusLoggingLevel` (alias dépréciés conservés).
- **Construction plus sûre de l'updater** (#493) — provider validé à la construction, config
  figée, téléchargements stagés en privé au lieu d'un chemin temp partagé prévisible. Voir
  [Auto-update](/docs/packaging/auto-update).
- **Drag sortant Windows** (#482) — `DoDragDrop` différé hors du dispatch pointeur Compose pour
  peindre les frames de drag sans réentrance. Voir
  [Drag and drop](/docs/tao/drag-and-drop).

### Corrections de bugs

- **Tremblement du live-resize macOS** (#476) — le contenu ne traîne plus derrière les bounds
  AppKit pendant un resize de coin.
- **Lag du resize interactif Windows** (#479) — VSync désactivé dans la boucle modale de resize
  pour que le contenu suive le bord.
- **GPU frame-paced pendant les boucles modales** (#489, #505) — VSync maintenu pendant
  move/resize Windows et les bursts de resize Linux lorsque la scène héberge des imports
  `TextureView` ou des consommateurs `TaoGpuRenderContext`. Voir
  [Contexte de rendu GPU](/docs/tao/gpu-render-context#frame-pacing).
- **Fuite du thread de rendu Metal macOS** (#495) — pool d'autorelease autour de chaque tâche
  du thread de rendu.
- **`LocalComposeSceneContext` sous `DecoratedWindow`** (#499) — Popup / Dialog / DropdownMenu
  / Tooltip dans le contenu d'une fenêtre décorée ne lèvent plus. Voir
  [DecoratedWindow](/docs/tao/decorated-window).
- **Detach overlay / retain focusable macOS** (#496), **buffer_scale des popups Wayland**
  (#508), **densité de scène depuis l'écran de la fenêtre macOS** (#509), **menu de tiling
  au survol du bouton zoom** (#511), **contraintes de title bar RTL en plein écran** (#512).

- **Hôtes de composition `HostedWindow` / `HostedDialog`** (#473) — bibliothèques et
  navigation ouvrent des fenêtres secondaires sans figer le `Window`/`Dialog` AWT de

## v2.3.0

**Sortie : 2026-08-06**

### Faits marquants

- **`TextureView` — textures GPU externes dans la scène Compose.** Composez des frames de
  décodeur ou de moteur avec z-order, clipping et `graphicsLayer` réels, sans copie CPU.
  Windows utilise des handles D3D11 partagés via ANGLE, macOS Metal/`IOSurface`, Linux
  DMA-BUF/`EGLImage` (YUV planaire I420/YV12 inclus). Les mises à jour de frame passent par
  `TextureViewController.markFrameAvailable` (invalidation draw uniquement). Voir
  [TextureView](/docs/tao/texture-view),
  [sources par plateforme](/docs/tao/texture-view#sources-par-plateforme) et
  [fonctionnement](/docs/tao/texture-view#fonctionnement).

Le chemin d'exécution JVM passait déjà l'option ; le binaire natif démarre maintenant proprement lui aussi.
- **Mise en pause de la boucle de rendu quand la fenêtre est minimisée** (#384) — chaque hôte de scène conditionne le corps de sa frame à `window.isMinimized` avant le tick de l'horloge de frames, si bien que les animations Compose se mettent en pause au lieu d'enregistrer et de présenter sur une surface masquée. C'est surtout critique sous Windows, où le swapchain en flip-model d'ANGLE ne signale jamais d'occlusion et n'exerce donc aucune contre-pression vsync pendant la minimisation ; la restauration relance explicitement un redraw.
- **Jewel 0.39 et icônes IntelliJ 262** (#395) — passe Jewel en `0.39.1-262.9437.29`, ajoute les dépendances `intellij-icons-api`/`impl` requises par l'`IntUiTheme` de Jewel 0.39, et enregistre les initialisations au build et les entrées de réflexion nécessaires pour éviter un segfault de `Method.invoke` sous SVM.

### Corrections de bugs

- **Cadrage des références locales JNI sur les threads attachés en permanence** (#387) — les upcalls créant des objets sur des threads attachés en permanence ne dépilaient jamais leur frame locale, fuyant des références locales pendant toute la vie du processus. Le chemin tactile était le pire : `dispatch_touch` allouait trois `long[]` par événement, si bien qu'un glissement tactile prolongé faisait croître la table de références locales JNI jusqu'au débordement et à l'abandon de la JVM. Le corps de chacun de ces upcalls est désormais encapsulé dans `env.with_local_frame(...)`, couvrant les chemins tactile et de dépôt sous Linux, les liens profonds macOS et les trampolines d'actions d'accessibilité macOS/Windows.
- **Purge des exceptions JNI en attente après les upcalls d'accessibilité et de liens profonds** (#385) — les callbacks natif-vers-JVM d'accessibilité et de liens profonds appelaient `NativeTaoBridge.dispatch*` sans `exception_check`/`exception_clear`, contrairement à tous les autres chemins de dispatch. Un gestionnaire Kotlin levant une exception la laissait en attente sur le thread de callback à longue durée de vie (AT-SPI/zbus, UIA, AppKit), rendant l'appel JNI suivant sur ce thread indéfini et, sous `panic = "abort"`, provoquant un abandon du processus dont le site de crash paraissait sans rapport. La garde est désormais appliquée aux 18 sites d'upcall.
- **Migration de `-H:IncludeResources` vers les globs des métadonnées d'atteignabilité** (#389) — l'option dépréciée émettait un avertissement au build ; les motifs d'inclusion de ressources sont passés dans le `reachability-metadata.json` du module, à sémantique identique. Les globs génériques de polices et d'icônes sont volontairement conservés : ils couvrent les ressources embarquées dans les JAR de bibliothèques, comme les icônes SVG de Jewel, que l'`autoIncludeResources` par racine n'atteint pas.

### Améliorations

- **Extraction du glisser-déposer de scène partagé dans `TaoSceneDnD`** (#386) — déduplique les trois hôtes de scène par plateforme en un seul fichier partagé, en préservant le comportement propre à Linux où `has_files` reflète la présence d'une cible `text/uri-list`.
- **Déplacement des métadonnées d'image native propres à Jewel dans `decorated-window-jewel`** (#395) — les initialisations au build et les entrées de réflexion de Jewel ne sont livrées qu'aux consommateurs de Jewel ; `graalvm-runtime` ne conserve que l'initialisation générique de slf4j.

## Guide de migration : 1.2.x → 1.3.x

### Decorated window : découpage du module monolithique

Le module `decorated-window` a été découpé en trois modules :

| Avant (1.2.x) | Après (1.3.x) |
|---|---|
| `nucleus.decorated-window` | `nucleus.decorated-window-core` (partagé) |
| | `nucleus.decorated-window-jbr` (implémentation JBR) |
| | `nucleus.decorated-window-jni` (implémentation JNI, nouveau) |

**Mise à jour de la dépendance** — remplace :

```kotlin
implementation("dev.nucleusframework:nucleus.decorated-window:<version>")
```

Par l'une de :

```kotlin
// Basé sur JBR (même comportement qu'avant)
implementation("dev.nucleusframework:nucleus.decorated-window-jbr:<version>")

// Basé sur JNI (sans dépendance JBR, fonctionne avec GraalVM)
implementation("dev.nucleusframework:nucleus.decorated-window-jni:<version>")
```

**Changements incompatibles dans `TitleBarColors`** — les champs suivants ont été **supprimés** :

- `titlePaneButtonHoveredBackground`
- `titlePaneButtonPressedBackground`
- `titlePaneCloseButtonHoveredBackground`
- `titlePaneCloseButtonPressedBackground`

Ces couleurs d'état de bouton spécifiques à la plateforme sont désormais gérées en interne par l'implémentation native de chaque module. Si vous construisiez `TitleBarColors` explicitement avec ces champs, retirez-les.

**Aucun autre changement de code requis** — toutes les API composables (`DecoratedWindow`, `DecoratedDialog`, `TitleBar`, `DialogTitleBar`), scopes et types d'état sont identiques. Aucun changement d'import nécessaire — le package reste `dev.nucleusframework.window`.

Voir [Decorated Window](/docs/window) pour tous les détails sur le choix entre JBR et JNI.

Première release — fork du plugin Gradle JetBrains Compose Desktop, réempaqueté sous le nom **Nucleus** avec des fonctionnalités d'empaquetage, de distribution et de runtime étendues.

### Empaquetage et distribution

- **Backend electron-builder** — Formats DMG, PKG, NSIS, NSIS Web, AppImage, DEB, RPM, Snap et AppX. Remplace jpackage pour la génération d'installeurs.
- **Signature de code et notarisation macOS** — Signature Developer ID et App Store, notarisation automatique via `notarytool`.
- **App Sandbox macOS** — Builds PKG sandboxed avec extraction de bibliothèque JNI, gestion des entitlements et profils de provisioning.
- **Signature de code Windows** — Intégration SignTool avec hachage SHA-256.
- **Empaquetage AppX** — Empaquetage Windows Store avec assets de tuile et configuration d'identité.
- **Personnalisation DMG** — Images de fond, positionnement des icônes, taille de fenêtre, icônes de badge et sélection de format.
- **Icônes en couches** — Prise en charge des répertoires `.icon` macOS 26+ pour les effets dynamiques de tilt/profondeur.
- **Écran de démarrage** — Prise en charge d'une image de splash dans le launcher JVM.
- **Binaires macOS universels** — Workflow CI pour les binaires fat basés sur `lipo` (Apple Silicon + Intel).
- **DSL typé** — Des enums pour les formats de target, les modes de publication et les réglages de compression remplacent les chaînes brutes.
- **Options d'empaquetage Linux** — `startupWMClass`, `debDepends`, `rpmRequires`, `debCompression`, `rpmCompression`, scripts après installation et suffixes d'architecture.
- **Associations de fichiers** — Injection `CFBundleURLTypes` macOS et prise en charge des associations de fichiers Linux/Windows via electron-builder.

### Modules runtime

- **`core-runtime`** — Détection du type d'exécutable, identification de plateforme, `SingleInstanceManager`, `DeepLinkHandler`.
- **`aot-runtime`** — Détection du mode de cache AOT pour JDK 25+ (Project Leyden). Tâche de génération de cache AOT avec timeout de sécurité.
- **`updater-runtime`** — Moteur d'auto-update avec providers GitHub et S3. Vérification SHA-512, suivi de progression, `installAndRestart()`. Stratégies d'installation spécifiques à la plateforme : script shell détaché sous macOS, PowerShell en arrière-plan sous Windows, remplacement AppImage sous Linux.

### Build et CI

- **Actions composites** — Actions `setup-nucleus`, `update-yml` et de publication de release.
- **Workflow de release multiplateforme** — macOS (arm64 + x64 + universel), Windows (x64 + arm64), Linux (x64 + arm64).
- **Prise en charge du configuration cache** — Compatibilité complète avec le configuration cache Gradle.
- **Version du plugin depuis le tag Git** — Aucune gestion manuelle de version dans `gradle.properties`.
