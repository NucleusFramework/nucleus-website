Nucleus modules release together under the `dev.nucleusframework` group. `nucleus-application`
brings the entry point, windows and runtime essentials. Add any other module when your app needs
it, on the same version:

```kotlin title="build.gradle.kts"
val nucleusVersion = "<version>"

dependencies {
    implementation(compose.desktop.currentOs)
    implementation("dev.nucleusframework:nucleus.nucleus-application:$nucleusVersion")
    implementation("dev.nucleusframework:nucleus.notification-common:$nucleusVersion")
    implementation("dev.nucleusframework:nucleus.global-hotkey:$nucleusVersion")
}
```

## What nucleus-application brings

Windows, dialogs, popups and native content, window themes and icons, platform detection,
`NucleusApp` metadata, single instance, deep links, the AOT cache, `isSystemInDarkMode()`, and
[spell check](/docs/os/spell-check). The native macOS context menu, `Modifier.keepScreenOn()` and
native image support also come with it.

<Callout type="warn" title="Changed in 3.0">
`nucleus-application` exposes `decorated-window-tao`, so remove your own `decorated-window-tao`
dependency. `decorated-window-awt`, `decorated-window-jbr` and `decorated-window-jni` no longer
exist. See [Migrate from 2.x](/docs/migrate/from-2.x).
</Callout>

## Toolkit modules

`decorated-window-jewel` (Java 25), `decorated-window-material2` and `decorated-window-material3`
style windows and dialogs inside `nucleusApplication`. macOS 26, Fluent and Yaru live in their own
repositories. See [Toolkits](/docs/toolkits).

## OS integration modules

| Capability | Module |
|---|---|
| Notifications, one DSL for every OS | [`notification-common`](/docs/os/notifications) (brings the per-OS modules) |
| Notifications per OS | `notification-macos`, `notification-windows`, `notification-linux` |
| Dock menu (macOS) | `launcher-macos` |
| Jump lists and taskbar buttons (Windows) | `launcher-windows` |
| Unity quicklist (Linux) | `launcher-linux` |
| Native menu bar (macOS) | `menu-macos` |
| Taskbar progress | `taskbar-progress`, [`taskbar-progress-tao`](/docs/os/dock-taskbar/progress) |
| System accent color | `system-color` |
| Global hotkeys | `global-hotkey` |
| Media controls (Now Playing, SMTC, MPRIS) | `media-control` |
| System info (CPU, RAM, GPU, batteries) | `system-info` |
| SF Symbols catalogue | [`sf-symbols`](/docs/os/icons/sf-symbols) |
| FreeDesktop icon names | `freedesktop-icons` |

## Lifecycle modules

| Capability | Module |
|---|---|
| Auto-launch at login | `autolaunch` |
| Scheduled tasks (cron, periodic, boot) | `scheduler` |
| Scheduler tests on a virtual clock | [`scheduler-testing`](/docs/lifecycle/background/scheduler-testing) |
| File-system watcher | [`fs-watcher`](/docs/lifecycle/fs-watcher) |
| Login items, launch agents and daemons (macOS) | `service-management-macos` |
| Efficiency mode and screen wake locks | `energy-manager` |
| Auto-update | [`updater-runtime`](/docs/packaging/auto-update) |

## Performance and networking modules

| Capability | Module |
|---|---|
| Trust manager backed by the OS certificate store | `native-ssl` |
| `java.net.http.HttpClient` with native trust | [`native-http`](/docs/performance/native-http) |
| OkHttp with native trust | `native-http-okhttp` |
| Ktor with native trust | `native-http-ktor` |
| Linux HiDPI scale detection | `linux-hidpi` |

The three `native-http` modules bring `native-ssl` with them.

<Accordion title="Under the hood">

- On the compile classpath, `nucleus-application` brings `decorated-window-tao`,
  `decorated-window-core`, `core-runtime`, `aot-runtime`, `darkmode-detector` and `spellcheck`.
- At run time only, it adds `graalvm-runtime` (with `linux-hidpi`), `menu-macos` (with
  `sf-symbols`), `energy-manager` and `angle-natives`. Declare one of them to import its API.
- The notification, launcher and media-control modules deliver their callbacks through
  `NucleusUiThread`. See [Threading](/docs/concepts/threading).
- Modules read your app's identity from `NucleusApp.appId`, `NucleusApp.version` and the other
  properties the Gradle plugin writes at build time.

</Accordion>
