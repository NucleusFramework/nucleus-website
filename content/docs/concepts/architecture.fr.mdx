Une application Nucleus est une application Compose Multiplatform. Nucleus ajoute en dessous des
fenêtres natives et l'intégration au système, et le plugin Gradle empaquette le tout.
`DecoratedWindow` et les helpers comme `isSystemInDarkMode()` sont des fonctions `@Composable`
ordinaires.

## Les couches

| Couche | Contenu |
|---|---|
| Votre application | UI Compose et logique métier, partageables avec Android et iOS via `commonMain`. |
| Runtime Nucleus | Modules d'intégration système, de cycle de vie, de performance et de mise à jour, et `nucleusApplication`. Voir [Modules](/docs/concepts/modules). |
| Couche de fenêtrage | Fenêtres natives, entrées et boucle d'événements. `nucleus-application` l'apporte. |
| Compose Multiplatform | Le toolkit d'UI. |
| Runtime | Une JVM (JDK 17 ou plus, tout éditeur ; JDK 25 avec `decorated-window-jewel`) ou une image native GraalVM. Voir [Runtimes](/docs/performance). |

`nucleusApplication` fait tourner la boucle d'événements sur le thread appelant et rend la main à
la fermeture de la dernière fenêtre. Les entrées, la composition et le dessin partagent un seul
thread ; voir [Threading](/docs/concepts/threading).

<Callout type="warn" title="Modifié en 3.0">
Les backends AWT (`decorated-window-awt`, `-jbr`, `-jni`), `NucleusBackend` et l'argument
`backend =` ont disparu. Les `Window`, `Dialog` et `Tray` AWT de Compose Desktop ne sont pas pris
en charge. Voir [Migrer depuis 2.x](/docs/migrate/from-2.x).
</Callout>

## Où AWT subsiste

- Compose démarre le thread d'événements AWT, qui maintient la JVM en vie. `nucleusApplication`
  appelle donc `exitProcess` après la fermeture de la dernière fenêtre. Passez
  `exitProcessOnExit = false` pour rendre la main et continuer.
- Votre propre code AWT tourne sur le thread d'événements AWT, distinct de celui qu'utilise
  Compose.
- Un hôte Swing ou Compose Desktop qui embarque des bibliothèques Nucleus sans
  `nucleusApplication` fonctionne toujours. Lisez `WindowBackend.Current` pour distinguer les cas :

```kotlin
if (WindowBackend.Current == WindowBackend.Tao) {
    // Lancé via nucleusApplication
}
```

## Bibliothèques natives

Nucleus charge ses bibliothèques JNI pour vous. Avec `./gradlew run`, un lancement depuis l'IDE ou
un fat JAR, il les extrait dans un cache par utilisateur ; déplacez-le avec
`-Dnucleus.native.cacheDir=<dir>`. Voir
[Chargeur de bibliothèques natives](/docs/performance/native-library-loader).

<Callout type="warn" title="Modifié en 3.0">
Les applications empaquetées ne portent plus les bibliothèques natives Nucleus dans leurs JAR. Le
code qui les lisait comme ressources du classpath doit passer par `NativeLibraryLoader`.
</Callout>

<Accordion title="En coulisses">

- La couche de fenêtrage est `decorated-window-tao`, qui enveloppe Tao, une bibliothèque de
  fenêtrage en Rust.
- La plupart des modules du runtime compilent en bytecode Java 11 : les bibliothèques qui les
  embarquent fonctionnent sur des toolchains plus anciennes.
- Skia dessine via Metal sous macOS, ANGLE sur Direct3D 11 sous Windows et EGL sous Linux.
- Une application JVM empaquetée charge les bibliothèques natives depuis le répertoire de
  l'application (`-Dnucleus.native.libraryPath`), une image native depuis le dossier de
  l'exécutable.
- Dans un hôte AWT, `WindowBackend.Current` vaut `WindowBackend.Awt` et les callbacks natifs
  tournent sur le thread d'événements AWT.
